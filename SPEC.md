# OpenEMT: Specification and Handoff Document

EMT (electromagnetic transient) simulation with one pure solver core behind three
frontends: a drag-and-drop schematic editor running entirely in the browser, a CLI,
and an MCP server. Trapezoidal nodal solver with a positive-sequence power flow.
Developed with Claude (claude.ai) from July 2026. This document is the handoff spec
for continued development with local models (Claude Code + qwen or similar).

**Positioning**: not "PSCAD in a browser." This is the concept-validation layer that
runs *before* anyone opens PSCAD — averaged/simplified models, small networks
(< ~100 nodes), zero install. Target fidelity class: EMTP with averaged converter
models (same class as PNNL DML pfc_avm / DC_bi_avm blocks).

---

## 1. Architecture

```
index.html          standalone bundle (inline everything; works offline, double-click to run)
src/solver.js       numerics: union-find nodes, LU factorization, time loop, events
src/blocks.js       block definitions: params, terminals, companion-model stamps
src/ui.js           SVG canvas: render, drag, wire, select, property panel, plots
```

`index.html` is generated by concatenating the three src files into one page.
Keep src/ as the editing surface; regenerate index.html for distribution.
(A 10-line build script or manual paste both work at this size.)

### Data model

```js
S = {
  blocks: [ {id, type, x, y, params:{...}} ],
  wires:  [ {a:[blockId, termIdx], b:[blockId, termIdx]} ],
  sel, wireFrom, nextId
}
```

Electrical nodes are NOT stored. They are derived at run time by union-find over
wire connections: every terminal starts as its own set; each wire unions two
terminals; each resulting set = one node. Ground blocks pin their set to the
reference (node index -1, eliminated from the matrix). BUS blocks additionally
self-union all of their own taps together (buildNodes, solver.js) — a bus is
a many-terminal junction, not a circuit element: after the self-union it is
topologically indistinguishable from "everything wired directly to one
point," so AC/DC classification, node numbering, and element construction all
handle it with zero special-casing. Tap count floor is 1 (not 2): a 1-tap bus
is a legal, purely cosmetic named anchor for a node, and multiple wires may
share the single tap. Terminal geometry is per-instance for bus
(tap count/spacing depend on its `taps`/`len` params) — see `getTerms()` in
blocks.js, which every terminal-position/topology call site now goes through
instead of reading `DEFS[type].terms` directly.

### Solver (src/solver.js)

EMTP method: fixed-step trapezoidal integration, nodal analysis.

1. Union-find → node numbering (ground sets excluded).
2. Each element contributes a conductance stamp to the n×n G matrix and
   (if stateful) a history current source to the RHS vector each step.
3. G is LU-factorized ONCE (partial pivoting). Each time step is a
   forward/back substitution only — O(n²), not O(n³).
4. Breaker events change G → refactorize at the event instant only.
5. Currently: dt = 50 µs default (user-adjustable, "Time step" field), T = 120 ms
   default (user-adjustable, "Duration" field), decimated output — "Plot step"
   field sets the exact output sample spacing directly; left blank/0, it falls
   back to the original auto behavior (~1400 plot points regardless of T).

### Critical invariants (do not break)

- G stamps: element with conductance g between nodes i,j adds +g to G[i][i]
  and G[j][j], −g to G[i][j] and G[j][i]. Ground terminal (index −1) skips its row/col.
- Singular G ⇒ floating node. Report to user; never silently continue. The
  report NAMES the circuit: `buildLU` returns the failing column, which maps
  back to a node through `topo.off`/`cnt` and then to every block on it, and
  the message calls out the two causes generic advice does not cover — a delta
  winding with no grounded path on its own side, and a node whose only
  elements are `G = 0` current-source interfaces (which are wired to ground
  yet cannot fix a node voltage).
- **A diverging run is an error, not a result.** Node voltages are checked
  every 16th step against `1e4 ×` the largest source/EMF/regulated voltage in
  the circuit; crossing it aborts with the time. Nothing physical approaches
  that bound, so it fires only on genuine numerical blow-up. Added because a
  case imported from a power-flow file (placeholder machine dynamics) grew to
  1e28 V and still returned a "Solved" status with plottable garbage, which is
  worse than failing because it looks like an answer.
- History sources are updated AFTER the node solve of each step, using the
  just-computed branch voltage.
- All styling must be self-contained (own CSS variables + prefers-color-scheme).
  NEVER reference host-page CSS variables — this was a real bug: blocks rendered
  black outside claude.ai because var(--surface-2) was undefined.

## 2. Companion models (physics — derive here, implement in blocks.js)

Trapezoidal rule on branch v–i relation ⇒ "companion" branch = conductance G in
parallel with a history current source Ih (Norton form).

### Voltage convention (`vconv`, July 2026)
The solver is per-phase internally; all derivations below are in phase
quantities. The user-facing AC source/bus voltage parameters may be entered
in either convention, selected by a circuit-level `vconv` field: `'ph'`
(phase RMS, the legacy default) or `'ll'` (line-to-line RMS). At the
parameter boundary a helper `vPh(v, nph) = (S.vconv === 'll' && nph === 3) ?
v / sqrt(3) : v` recovers the per-phase value, so an LL entry of 480 V is the
same physics as a phase entry of 277 V. In 1-ph the line voltage IS the phase
voltage, so `vconv` has no effect there (no sqrt(3) factor). Affected params:
`src.Vrms`, `gfm.E0`/`Vset`, `syncgen.E0`/`Vref`/`Vset`, `svc.Vref`,
`pfc.Vac`, `zip` `V0` (the ZIP nominal reference), `pq`/`zip` `vmin`,
`hvdc`/`wt4` `vmin`, `vsw.Von`/`Voff`. NOT affected: DC voltages
(`pfc`/`batt`/`dcdc` `Vref`, `hvdc.VdcRef`, `cpl.vmin`), the peak clamp
`mov.Vc`, and currents. Power flow divides `Vset`/`E0`/`Vrms` by
sqrt(3) on input and reports bus `Vmag` in the circuit's convention (LL =
per-phase × sqrt(3) when `vconv='ll'`); `Vpu` is convention-independent. An
absent `vconv` reads as `'ph'`, so every legacy file, fixture, example, and
test stays byte-identical and unchanged. New UI circuits default to `'ll'`
(the Clear button); the API defaults to `'ph'` and opts into LL via
`setVconv`. In the UI, toggling the convention CONVERTS already-entered
convention-aware values by sqrt(3) (PH->LL multiply, LL->PH divide, rounded
to mV) so the physical voltage is preserved rather than reinterpreted; this
is undoable (the undo snapshot carries `vconv`). The API `setVconv` is
flag-only (no value conversion), so agents should set it before adding blocks
(see the `set_vconv` MCP tool description).

### Power convention (July 2026)
Every user-facing power parameter in the library is a **three-phase total**, in
kW / kvar / kVA: `syncgen.Pm0`/`Sbase`, `gfm`/`gfl` `P0`/`Q0`/`Sbase`,
`hvdc.Pset`, `wt4`, `im.PL`, and the `pq`/`zip` `P`/`Q`. There is no per-phase
power parameter anywhere, and no `vconv`-style switch: unlike voltage, where
both conventions are in genuine engineering use, a per-phase power entry has no
constituency and only invites the mistake below. The solver is per-phase
internally, so each block divides its total by the number of phases it actually
occupies (`nphB`: 3 on an ordinary 3-phase node, 1 in 1-ph mode and 1 on a
single-phase lateral, where the block's total IS its one phase).
`solvePowerFlow()` is a three-phase-total solve throughout
(`Ii = conj(Snet/(3·V))`), so it consumes these parameters directly.

This was NOT true before July 2026, and the bug is worth recording because
nothing in the test suite could see it. `pq`/`zip` injected their full `P` into
EVERY phase — per-phase semantics — while `solvePowerFlow()` read the same
number as a three-phase total. The two solvers therefore disagreed by exactly
3x about how big every constant-power load in the tool was. It survived because
every load test measured ONE phase against a per-phase expectation (self-
consistent either way) and every power-flow test used constant-impedance `rlc`
loads (stamped as admittance, immune). The witness that settles it is
`examples/ieee9bus.json`, a benchmark with a published answer: its power flow
returned a slack of −133.11 MW against the published +71.6 MW, because it saw
105 MW of the case's 315 MW of load. It is now +72.44 MW. Two consequences that
outlived the fix: any circuit saved before July 2026 has `pq`/`zip` values that
now mean three times what they did (`examples/ieee9bus.json` and
`tests/fixtures/pq_piline.json` were rescaled in place to preserve their
physics; PSS/E-imported cases were already three-phase totals and were correct),
and every PF-initialized case with a constant-power load was previously started
from an operating point the network does not hold, which is a far better
explanation for a run that "converged then blew up" than any weak-bus story.
Guarded in smoke_test.js by solving one circuit both ways and comparing the bus
voltage (0.6% now, 20% on the pre-fix code).

### Resistor
G = 1/R. No history. i = v·G. The standalone `load` (R-only) block was
removed in July 2026; a bare resistor is now `rlc` (or `rlcp`) with L and C
absent (`-1`), which reduces exactly to this companion (the redundant L/C
history terms stay identically zero, since i = v·G is maintained exactly).
This is the limiting case the Series and Parallel RLC derivations below
refer to as "a resistor" companion.

### Voltage source behind Rs (Thevenin → Norton)
Norton injection: I = v_s(t)/Rs into node n1, out of n2. G = 1/Rs stamped between
n1, n2. v_s(t) = Vrms·√2·sin(2πft + φ_phase). Element current: i = (v_s − v_branch)/Rs.

### Series RL branch (line)
v = R·i + L·di/dt. Trapezoidal:
  (v_n + v_{n−1})/2 = R·(i_n + i_{n−1})/2 + L·(i_n − i_{n−1})/dt
⇒ i_n = [v_n + v_{n−1} − i_{n−1}·(R − 2L/dt)] / (R + 2L/dt)

Companion: Req = R + 2L/dt, G = 1/Req,
history Ih = [v_{n−1} − i_{n−1}·(R − 2L/dt)]·G injected n2→n1.
State per branch: previous v and i. Update after solve:
  i ← v·G + Ih ;  v ← v_branch.

### Capacitor
i = C·dv/dt. Trapezoidal:
  i_n = (2C/dt)·v_n − [(2C/dt)·v_{n−1} + i_{n−1}]
Companion: G = 2C/dt, Ih = −[(2C/dt)·v_{n−1} + i_{n−1}] (note sign: source
INTO the branch). Same stamp/update pattern as RL. Implemented in blocks.js
('cap', param C in µF); validated in smoke_test.js against the analytical
series-RC divider (0.00% steady-state error).

### Series RLC branch (rlc, July 2026)
Unlike the RL branch above, a series R-L-C branch is 2nd order: it needs the
shared branch current i AND an independent capacitor-voltage state vC (the RL
branch's single v/i state pair isn't enough, since vC doesn't collapse to a
function of total branch voltage v).

v = R·i + L·di/dt + vC ,  dvC/dt = i/C

Trapezoidal on the L leg and the C leg, summed with R's algebraic leg
(v = v_R + v_L + vC), gives:
  Req = R + 2L/dt + dt/(2C),  G = 1/Req
  k   = R − 2L/dt + dt/(2C)
  Ih  = [v_{n−1} − i_{n−1}·k − 2·vC_{n−1}] · G        (normal trapezoidal step)
  vC update (after solve): vC_n = vC_{n−1} + (dt/2C)·(i_n + i_{n−1})

BE half-step (CDA, same damping trick used after a switching event as the RL
and capacitor companions above — see solver.js's `be` flag):
  Ih_be = [i_{n−1}·(2L/dt) − vC_{n−1}] · G

Both formulas were verified algebraically against the two existing companions
above, which are their limiting cases: with C absent (vC held at 0, see below)
Ih and Ih_be reduce exactly to the RL branch's Ih and BE formulas; with R and L
absent, they reduce exactly to the capacitor's Ih and BE formulas (G also
correctly becomes 2C/dt in that limit). Validated in smoke_test.js both by
these three limiting-case comparisons and by a full 3-element case checked
against the closed-form underdamped series-RLC step response.

**`-1` = component absent, uniformly for R, L, and C.** Each parameter, if
`< 0`, drops out of the branch entirely: R aliases to 0 (already an
unambiguous "no resistor" value on its own — a plain wire — so `-1` is just
accepted as a synonym); L's `2L/dt` term is dropped (effective L=0, which is
already physically "no inductor," a wire — no ambiguity to resolve); C's
`dt/(2C)` term is dropped to 0 as if C→∞, i.e. a wire in its place — this is
NOT the same as setting C=0, which would blow the term up to infinity (an
open circuit, the opposite of "absent"), so C absent has no safe 0-sentinel
and must use -1. vC state is only tracked/updated while C is present; it is
held at 0 otherwise, which is what makes the C-absent limiting-case reduction
above exact. If all three are absent, Req would be 0 (G = ∞); Req is floored
to a small epsilon in that case (mirrors `brk`'s `goff` floor for its open
state) rather than letting the stamp blow up — an all-absent `rlc` block is a
numerically-forced short, not a meaningful configuration.

Implemented in blocks.js ('rlc', params R in Ω, L in mH, C in µF) as a simple
per-phase element (same `stampPhase`/`inject`/`update` shape as `line`/`cap`,
not a spanning element — it's still one reciprocal 2-terminal (G, Ih) pair).

### Parallel RLC branch (rlcp, July 2026, DONE)
Companion shape for R, L, and C sitting side by side between the same two
terminals (sharing one branch voltage), rather than `rlc`'s series chain
(sharing one branch current). Unlike the series case, the three components
don't interact algebraically — no shared current forces a coupled system —
so the companion is simply the sum of three independent, already-known
companions (a resistor, `line`'s inductor-only limit, and `cap`'s own
formula) evaluated in parallel:

```
G  = GR + GL + GC                     (three independent admittances, summed)
Ih = Ih_L + Ih_C                      (R is memoryless, contributes 0 to Ih)

GR = 1/R                              (0 if R absent)
GL = dt/(2L)                          (0 if L absent)   — standalone trapezoidal
GC = 2C/dt                            (0 if C absent)   — identical to cap's G

Ih_L = iL_{n-1} + GL·v_{n-1}          (0 if L absent)   — standalone trapezoidal
Ih_C = -(GC·v_{n-1} + iC_{n-1})       (0 if C absent)   — identical to cap's Ih

iL, iC updated after solve (branch voltage vb just computed):
  iL_n = vb·GL + Ih_L
  iC_n = vb·GC + Ih_C
  cur  = vb·G + Ih                    (total branch current, for probes/plots)
```

Two independent branch-current states are needed (iL, iC) — the inverse of
`rlc`'s state shape (one shared current + an independent capacitor-voltage
state): here there's one shared voltage (`v`, already what the node solve
gives every element — no extra state needed for it) but two independent
current histories, since iL and iC are not equal to each other or to the
total branch current.

BE/CDA half-step (same damping trick, reusing G and only swapping Ih): drop
the v_{n-1} term from each sub-branch's history, exactly the way cap's own
`ihf(be)` already does (`-v·G` instead of `-(v·G+i)`). Verified by reducing
`rlc`'s already-derived BE formula to its pure-L limit, which collapses to
exactly `Ih_be_L = iL_{n-1}` (no v term) — the mirror image of cap's own BE
drop:
```
Ih_be_L = iL_{n-1}                    (0 if L absent)
Ih_be_C = -GC·v_{n-1}                 (0 if C absent)
Ih_be   = Ih_be_L + Ih_be_C
```

Power flow (steady-state phasor): admittances sum directly, no impedance
inversion needed (unlike `rlc`'s Z → cInv(Z) step):
```
Y = { re: GR, im: w·Ceff − 1/(w·Leff) }     (each term 0 if that component absent)
stamp(pf(b,0), pf(b,1), Y)                   // direct — no cInv()
```

**Sentinel convention is the INVERSE of `rlc`'s — the one real trap.** In
series `rlc`, `-1` and `0` were interchangeable for R and L (both mean "no
component," a harmless wire); only C needed `-1` specifically, since C=0 in
series is a dangerous open circuit. In parallel this flips: R=0 and L=0 are
real, physically valid values — a 0 Ω resistor or 0 H inductor in parallel
is a hard short. Implemented as FLOORED conductances (R below 1e-6 Ω and L
below 1e-9 H clamp there, mirroring `rlc`'s all-absent Req floor), in the
transient companion and the power-flow stamp alike: a literal `1/0 =
Infinity` stamp only "works" for a shunt to ground — between two live nodes
the Inf/Inf ratios NaN the LU and the run silently outputs NaN (found and
fixed in the July 2026 solver review; the first-step NaN guard in
`simulate()` now catches any remaining case of that class). So `-1` is
required, not optional, for R and L to mean "not present" (open, G
contribution 0) — `0` means something different (a short) for both. C is
the one safe either way: `C=0` or `C=-1` both naturally give `GC=0` —
standardize on `-1` for consistency with R/L and with `rlc`'s own hint
style, but note C=0 also happens to work (mirrors how `rlc`'s hint notes R
accepting 0 as a safe alias, opposite component).

**No Req-style floor guard is needed** (a real simplification vs. `rlc`):
all three absent gives G=0, the correct, physically meaningful value (open
branch) — not a divide-by-zero, since nothing here is ever inverted. It does
NOT force a short the way all-absent `rlc` does. If this is the only
connection between the block's two terminals, G=0 means a genuinely
floating node — the solver's existing invariant already reports that
(§1: "Singular G ⇒ floating node. Report to user; never silently
continue"), so no new guard code is needed, just an accurate hint sentence.

"Parallel" describes the internal topology of R, L, C relative to each other
(they share a terminal voltage, not a branch current) — it does not mean
the block can only be used as a shunt to ground; like `rlc`, it's still a
plain 2-terminal branch, wireable anywhere a 2-terminal element goes.

Implemented (blocks.js `DEFS.rlcp` + `makeElements` case, solver.js
`buildYbus` stamp, ui.js registration, smoke_test.js limiting-case and
resonance checks, DECISIONS.md entry).

### GFM inverter AVM (droop-controlled grid-forming converter)
Averaged model: controlled EMF e_p(t) = √2·E·sin(θ + φ_p) behind an RL filter
(Rf, Lf), one converter spanning all three phases (single controller state).
The filter branch is the standard series-RL companion on x ≡ e − v_terminal:
  i_n = G·x_n + Ih,  G = 1/(Rf + 2Lf/dt),  Ih = (x_{n−1} − k2·i_{n−1})·G,
  BE half-step (CDA): Ih = G·(2Lf/dt)·i_{n−1}.
RHS injection per phase: I[n1] += G·e_p + Ih, I[n2] −= (same); G stamps as a
per-phase diagonal (reuses the coupled-element machinery with Geq = G·I₃).

Controls (integrated forward-Euler alongside the solve, step h = dt, or dt/2
during CDA half-steps; update AFTER the node solve using the just-computed
branch quantities, then advance θ):
  p_inst = Σ_p v_p·i_p                     (terminal power, W)
  q_inst = [(v_b−v_c)i_a + (v_c−v_a)i_b + (v_a−v_b)i_c]/√3   (>0 inductive)
  Ṗf = (p_inst − Pf)/Tf ;  Q̇f = (q_inst − Qf)/Tf             (LPF, Tf ~ 20 ms)
  ω = 2π·[f0 − mp·(Pf/1000 − P0)]          (P–f droop, mp in Hz/kW)
  E = E0 − mq·(Qf/1000 − Q0)               (Q–V droop, mq in V/kvar)
  θ̇ = ω
The oscillator is self-clocked (θ is a state; injections never read wall-clock
time), which is what lets two GFMs in parallel share load through droop.
Steady state with a resistive load R: q ≈ 0 ⇒ E = E0 + mq·Q0; the operating
point solves the fixed point f = f0 − mp·P(f)/1000 + mp·P0,
P = 3·(E/|Zf(ω)+R|)²·R — used as the analytical validation.
Runs 3-phase, in 1-ph mode, or on a single-phase lateral (July 2026): the
droop/GFL controller was given a one-cycle single-phase P/Q measurement
projected onto the inverter's own reference (§2). The AC current limiter
(`Iacmax`) is the one exclusion single-phase, refused with a clear error,
because one-cycle-stale P/Q cannot hold current through a fault.
Future (needs a new derivation session): PFC rectifier and battery DC/DC AVMs
— controlled Norton sources on a DC bus with PI voltage/current loops.

#### GFM DC port + grid-following mode (July 2026 derivation)
Motivation: the AC-only droop source above behaves like an infinite-energy
supply — its output droops with measured P/Q, but nothing constrains it to
actually HAVE that power available from a real DC source (battery/PV/DC
bus), unlike a real inverter. Two additions, both reusing the branch/state
above unchanged:

**DC port (term 2, optional):** lossless AVM — the DC side supplies exactly
the power the AC branch already measures itself delivering (`Pf`), as a
current-limited Norton injection, one-step lag (same pattern as pfc/batt):
```
icmd = clamp(Pf / (vdc || ε), −Idcmax, Idcmax)     // ε avoids /0 at vdc≈0
inject: I[dc] −= icmd
```
Sign: Pf>0 (delivering to AC) ⇒ icmd>0 ⇒ current leaves the DC node
(battery discharges); Pf<0 (absorbing from AC) ⇒ icmd<0 ⇒ current enters it
(battery charges) — the same bidirectional convention the battery/PFC
already use. No new DC voltage/power signal is needed: DC power equals AC
power by construction (read it off the existing AC-side P/Q signals), and DC
voltage is read the normal way (probe/bus on whatever it's wired to). Only
DC **current** is new and worth its own signal (`idc`, aux channel below).
**Every terminal gets a union-find node whether or not it's wired** (§1) —
so simply adding a 3rd terminal to `DEFS.gfm.terms` would make term 2 a
genuinely floating, un-grounded, un-stamped node (singular matrix) on EVERY
circuit that has a gfm block and never mentions terminal index 2, i.e. every
circuit saved before this feature existed. `buildNodes` (solver.js) auto-
grounds a gfm's term 2 when no wire references it, restoring the "unwired
DC port ⇒ true no-op" property for old and new circuits alike.

**Grid-following mode (`mode` param, 0 = droop [default, unchanged] /
1 = GFL):** shares the identical branch/state (`Pf`,`Qf`,`E`,`th`) — only the
control-law tail differs. Droop is open-loop proportional, drooping AWAY
from nominal; GFL is closed-loop PI, driving TOWARD the P0/Q0 setpoint
instead (reuses `mp`/`mq` as the proportional gains, same Hz/kW, V/kvar
units, plus new integral gains `kiP` [Hz/(kW·s)], `kiQ` [V/(kvar·s)]):
```
errP = P0·1000 − Pf;  integP += kiP·h·errP/1000       // errP in W, kiP in Hz/(kW·s)
ω = 2π·(f0 + mp·errP/1000 + integP)
errQ = Q0·1000 − Qf;  integQ += kiQ·h·errQ/1000
E = E0 + mq·errQ/1000 + integQ
```
No explicit PLL — this assumes the network is already close to f0 (true when
tied to a stiff `src` or another GFM; degenerate-but-stable on an island
alone, since there's nothing to actually follow). No anti-windup/current-
limit on the trims, same accepted-limitation class as droop's unbounded E/ω.

**A real, found-by-testing constraint: this decoupled P→frequency/Q→voltage
control (both modes, but GFL's tight PI setpoint-tracking makes it far more
visible) assumes a predominantly INDUCTIVE tie — the same X≫R assumption all
textbook droop control relies on.** Tie the DC-port-enabled GFL block
directly to a stiff source with only its own Rf+Lf (default 1 mH) plus the
source's Rs in between (X/R ≈ 0.6 at 60 Hz with the defaults — resistance-
dominated) and Q tracking is either extremely slow (many hundreds of ms with
gentle gains) or poorly damped/oscillatory (with aggressive gains) — P still
converges cleanly (its frequency/phase-integral loop is essentially
unconditionally stable here), but Q gets dragged along by the P/Q coupling
inherent to a low-X/R interconnection. With a taller Lf (e.g. 3 mH, giving
X/R ≈ 3) both P and Q settle cleanly within a few hundred ms even with
markedly more aggressive gains. Defaults (`kiP=0.05`, `kiQ=2`) are chosen
conservative/stable across the default Lf so mode=1 doesn't misbehave out of
the box; a well-filtered inverter (larger Lf) tracks its setpoint faster and
tighter — this is the honest tradeoff of reusing the droop branch's EMF/phase
dynamics for setpoint tracking instead of a real inverter's fast inner
current-control loop (out of scope — "lightweight" was the chosen tier).
`smoke_test.js`'s GFL check uses Lf=3 mH / stronger gains specifically to
validate the control law converges correctly when reasonably configured,
matching how a real engineer would size an inverter's output filter.

#### AC current limiter (`Iacmax`, July 2026 derivation)
Motivation: unlimited, the GFM's only fault-current constraint is its coupling
impedance Zf = Rf + jωLf, so a terminal fault draws E/|Zf| (roughly 700 A rms
with the defaults), where a real inverter caps near 1.1 to 1.2 times rating.
The interconnection study measured 1.7x rating plus a brief post-clearing
power reversal; neither is physical (flagged in IDEAS.md as the biggest
honest gap).

Method: indirect limiting by EMF-magnitude backoff (the classical
voltage-reduction / virtual-impedance family, published academic work since
the mid-2000s; deliberately NOT any specific modern single-loop scheme, per
the CLAUDE.md IP rule). Direct current-reference saturation does not fit this
AVM: the branch is a linear EMF-behind-Zf companion inside the nodal solve,
so the current is an outcome, not a reference. Scaling the EMF keeps the
branch linear (no LU change) and mimics what a real limited inverter looks
like from the network: a source whose terminal voltage collapses just enough
to hold current at the limit.

State: a scale factor µ ∈ [0.02, 1] multiplying the EMF magnitude
(e_p = √2·(µE)·sin(θ + φ_p)) plus two filtered phasor sums. The sinusoidal
forced-response branch current is the phasor difference I = (µÊ − V̂)/Zf,
where V̂ is the measured branch terminal voltage. For balanced 3-phase sets
the instantaneous sums

A = Σ_p (e_p/µ)² = 3E²,  B = Σ_p (e_p/µ)·v_p = 3·E·V·cos δ,  C = Σ_p v_p² = 3V²

are exact (ripple-free); B and C are low-pass filtered (T_lim = 5 ms)
against fault transients and carry a 2f ripple under unbalance. The
largest µ that holds |I| at Iacmax solves the quadratic
```
µ²·A − 2µ·B + C = W²,   W² = 3·(Iacmax·|Zf|)²   (|Zf| at f0)
tgt = min(1, (B + √(B² − A·(C − W²)))/A)         (upper root)
tgt = B/A when no real root exists               (projection fallback)
µ  += h·(tgt − µ)/T_dn    if tgt < 1   (actively limited, T_dn = 10 ms)
µ  += h·(1 − µ)/T_up      if tgt = 1   (release ramp, T_up = 100 ms)
µ = clamp(µ, 0.02, 1); snap to exactly 1 within 1e−4 (the exponential
release never reaches 1 in floating point)
```
No real root means the network drives the current above the limit for
EVERY µ (e.g. a recovered grid voltage against a fault-drifted angle); the
projection B/A is the µ of minimum phasor mismatch, which makes the
inverter track the grid voltage until the angle recloses — grid-voltage
ride-through.

Why an affine solve and not the simpler proportional fixed point
µ* = µ·Iacmax/If (with If the measured current): current is proportional
to µ only for an ISLANDED inverter feeding a passive network. Grid-tied —
the motivating use case — the current follows the (µÊ − V̂_grid)
difference, so once µ has backed off during a fault, LOWERING µ RAISES the
post-clearing current: the proportional law has the wrong feedback sign in
that regime, drives µ to the floor, and latches there permanently
(measured before the fix: 214 A rms held against a 40 A limit, inverter
absorbing 11 kW, still latched 1.8 s after the fault cleared). The affine
solve is exact in sinusoidal steady state in both regimes because V̂ is
measured, not assumed.

Stability: tgt does not depend on µ directly (only through the network's
V(µ)), so the loop is first-order — it cannot overshoot or limit-cycle.
Grid-tied, V is nearly stiff and convergence is ~T_dn. Islanded, V ∝ µ
shrinks the per-step correction by the local voltage-divider ratio
c = |V|/(µE), giving an effective time constant T_dn/(1 − c): ~11 ms into
a bolted fault (c ≈ 0.1), slower for a lightly overloaded stiff island
(c → 1). Accepted trade: convergence degrades gracefully where the old law
was exact, and the failure mode (slow approach) replaces a destructive one
(latch-up). Earlier rejected variants, all built on the proportional fixed
point (second-order through the measurement lag): an integrating attack
(µ −= h·err/T_dn) limit-cycles 2 to 73 A around a 40 A target; the same
law with taus halved (2/4 ms) limit-cycles at large signal; an open-loop
algebraic µ = Iacmax/(If/µ estimate) is polluted by the fault's natural
response and latches at the floor. Bolted fault: µ settles at
Iacmax·|Zf|/E (≈0.06 with defaults at Iacmax = 40 A), above the 0.02
floor. The held current runs ~1 to 3% above Iacmax (natural-response
residue and filter bias). The first ~1.5 cycles of a fault still pass the
unlimited transient (a ~10 ms outer loop, not sub-cycle hardware current
control); see §7.

Anti-windup (GFL mode): while actively limited the P/Q PI trims have no
authority (any E increase is cancelled by the µ backoff), so both
integrators freeze on the one-step-lagged actively-limited flag (tgt < 1).
During the T_up release the trims DO have authority (µ follows its own
schedule and output still scales with E), so they run — and the flag, not
a µ ≥ 1 test, is what unfreezes them: an exact-equality test on the
asymptotic release stalls ~1e−13 below 1 in floating point and would
freeze the trims for the rest of the run. Droop mode needs none: its E is
algebraic.

`Iacmax` is A rms per phase; 0, absent (pre-feature files), or negative
disables the limiter entirely (µ pinned at 1), so every saved circuit
behaves exactly as before. The limiter acts on the AC branch only; the DC
port keeps its own separate Idcmax clamp. syncgen deliberately gets NO
limiter: a synchronous machine really does deliver multiples of rated
current into a fault; that is physics, not a modeling gap.

Validation (smoke test): island droop GFM (defaults, Iacmax = 40 A) into
R = 12 Ω, prefault I ≈ E0/|Zf + R| ≈ 22.9 A rms (below limit, limiter must
not disturb the droop fixed point); 3-phase 0.05 Ω fault at the load bus
drives the unlimited current to E/|Z| ≈ 683 A rms, limited run must hold
≈ Iacmax within 10%, and after the fault clears the load voltage must
recover to the prefault fixed point (µ released). A second run with
Iacmax = 0 must reproduce the unlimited current (backward compatibility).
Grid-tied (both modes, src 277 V behind 0.5 Ω, same fault): held ≈ Iacmax
within 10% during the fault; droop at zero setpoint must return to ~0 A
exchange with µ = 1 exactly (the proportional law latched at ~214 A here);
GFL must re-settle on P0 = 5 kW within 5% with µ = 1 (integrators
re-engaged after the anti-windup freeze).

### Synchronous generator, classical model (`syncgen`, July 2026 derivation)
Motivation: every generation source up to this point is inverter-based —
`src` is an idealized fixed-frequency EMF, `gfm` is a converter whose
frequency/voltage are ALGEBRAIC functions of filtered measured P/Q (droop)
or a PI setpoint (GFL), with no memory of its own motion. A real
synchronous generator's rotor is a spinning mass with inertia, so frequency
is a genuine DYNAMIC STATE governed by a second-order swing equation —
inertial response, electromechanical oscillations after a disturbance,
multi-machine load sharing via governor droop, none of which an algebraic
droop line can produce. Classical model only (round rotor, constant-
magnitude transient EMF, no subtransient/saturation/exciter dynamics) — same
"lightweight AVM" tier as every other converter in this file.

**Electrical branch — identical structure to GFM's `makeConverters`, only
the θ update law differs.** Same per-phase series-RL companion on
`x ≡ e − v_terminal`, using the machine's own armature resistance `Ra` and
transient reactance `Xd'` expressed as an inductance `Ld` (mH, same
convention as gfm's `Lf`):
```
G = 1/(Ra + 2·Ld/dt),  k2 = Ra − 2·Ld/dt,  kL = 2·Ld/dt
e(ph) = E·√2·sin(θ + shift[ph])              // IDENTICAL to gfm's e(ph)
inject: I[a1] += G·e + Ih,  I[a2] −= (same)  // reversed-wiring generator convention, same as src/gfm
```
Two AC terminals only (`terms: [[0,my],[w,my]]`) — no DC port; a rotating
machine has no natural DC side, unlike an inverter.

**Swing equation — the new physics.** The rotor stores kinetic energy
`KE = H·Sbase` at rated speed (H in seconds — standard definition: "seconds
of rated power needed to spin the rotor up from rest"; Sbase = machine
rating, kVA). Energy balance, small-deviation approximation (always valid
here since Δf/f0 stays tiny in any run this tool can simulate):
```
d(KE)/dt ≈ (2H·Sbase/ω0)·dω/dt = Pm − Pe − Pdamp
```
Convert ω→f (ω=2πf); express damping directly as a power term
`Pdamp = D·Δf` (D in **kW/Hz** — more intuitive than textbook per-unit D,
consistent with this file's avoid-per-unit style everywhere else) and
mechanical power via a governor droop `Pm = Pm0 − Kgov·Δf` (Kgov in
**kW/Hz**, 0 = no governor/fixed Pm — mirrors gfm's `mp`/`mq` being direct-
unit gains rather than percentages):
```
Δf = f − f0
Pe = (v_a·i_a + v_b·i_b + v_c·i_c) / 1000    // instantaneous 3-ph power, kW — UNFILTERED (see below)
Pm = Pm0 − Kgov·Δf
ḟ  = f0·(Pm − Pe − D·Δf) / (2·H·Sbase)
θ̇  = 2π·f                                    // same "θ is a self-clocked state" pattern as gfm
```
`Pe` feeds the swing equation unfiltered (instantaneous, like real torque) —
filtering it would add unphysical lag to the one term that should respond
immediately. Update order mirrors gfm's `Pf`→`w`→`θ` sequencing exactly:
advance the ODE state (`f`) first using its OLD value in the RHS, THEN
integrate `θ` from the freshly-updated `f` (semi-implicit Euler — better
damping behavior than fully-explicit, same reasoning gfm's own sequencing
already relies on).

**AVR.** Reuses gfm's Q-droop verbatim, same Tf-filtered `Qf`, same formula:
`E = E0 − mq·(Qf/1000 − Q0)`.

**Exciter and governor dynamics (July 2026, opt-in).** Two first-order
control lags, both DEFAULT OFF (Te = 0, Tg = 0) so every pre-existing
circuit behaves bit-for-bit as before:
```
Governor (Tg > 0): Pm is a STATE, not the algebraic droop line:
  Pm_cmd = Pm0 − Kgov·Δf;  dPm/dt = (Pm_cmd − Pm)/Tg
  clamp Pm to [0, Pmax] (Pmax = 0 means no ceiling); init Pm = Pm0 (or PF)
Exciter (Te > 0): proportional AVR with lag REPLACES the Q-droop E law:
  Vt²f += h·(Σph v_t² / 3 − Vt²f)/Tf     (terminal Vrms², same Tf filter)
  E_cmd = E0 + Ka·(Vref_avr − √Vt²f)     (Vref_avr = Vref param, 0 → E0)
  dE/dt = (E_cmd − E)/Te, clamp to [0, Emax] (0 = no ceiling)
```
This is the classical simplified IEEE-class pair (TGOV1-like turbine lag,
ST1-like static exciter: gain + lag + ceiling, no stabilizer). Steady
state of the AVR is the proportional fixed point
Vt = g·(E0 + Ka·Vref)/(1 + g·Ka) for a machine feeding an impedance
divider gain g, which the smoke test checks analytically. With the AVR on,
mq/Q0 are unused (one E law at a time); with a governor lag the steady
frequency is UNCHANGED (the lag moves only the transient), also checked.
Known limitations (§7): no PSS, no exciter saturation, no reheat/deadband
on the governor, proportional-only AVR (deliberate: an integrator would
fight the PF-init flat start).

**Numerical safety, checked not assumed.** Linearizing the swing equation
about an operating point gives a standard damped oscillator with natural
frequency `ωn = √(π·f0·Ks/(H·Sbase))`, where `Ks = ∂Pe/∂δ` (kW/rad, the
synchronizing-power coefficient) and damping ratio
`ζ = f0·D/(4·H·Sbase·ωn)`. With the defaults below and a couple mH of total
tie reactance, `ωn` works out to roughly 1–2 Hz — a real, textbook-typical
electromechanical oscillation frequency. At a 50 µs solver step that's
10,000+ steps per oscillation cycle: an enormous stability margin, 2–3
orders of magnitude slower than the fast LC/PI feedback loops that actually
caused instability elsewhere in this tool's development (a PQ load + shunt
capacitor; a GFM reactive-power injector). Verified empirically (headless,
not just derived): a single machine tied through Ra+Ld+a line to a stiff
`src` (infinite bus) locks to EXACTLY f0 at steady state (checked to
<0.00001 Hz via the internal state) with `Pe_ss = Pm0` to machine precision
— energy balance and frequency lock both hold as theory predicts. A step-
response sweep over `D ∈ {5,15,25,40,60}` via log-decrement peak analysis on
the same circuit gave `ζ ∈ {0.028, 0.090, 0.153, 0.247, 0.373}` — exactly
matching the hand-derived `ζ` formula above, confirming `D=25` (the shipped
default) lands at `ζ≈0.153`: several visibly decaying swings settling within
~2.5 s, not zero damping forever and not so damped it looks static. A
two-machine test (different Kgov/H/Sbase, common load, no infinite bus)
confirmed both machines synchronize to the exact same frequency and that
each machine's own `(Pm0−Pe)/(Kgov+D)` implies the identical Δf — i.e. `D`
acts as an EXTRA effective droop term in aggregate multi-machine load
sharing, not just `Kgov` alone (falls straight out of the swing equation at
steady state: `Pe_i = Pm0_i − (Kgov_i+D_i)·Δf`).

**Defaults**: `Pm0=0, Q0=0` (idle/inert on drop, matching gfm's `P0=0`/`Q0=0`
default), `H=4` s (typical steam-turbine range 3–5 s), `Sbase=50` kVA
(in-scale with this tool's kW-level examples), `Ra=0.05` Ω, `Ld=2` mH,
`f0=60`, `E0=277`, `mq=0.5` V/kvar (same as gfm), `Tf=20` ms (same as gfm),
`Kgov=15` kW/Hz (≈5% droop at these ratings — a realistic default so two
machines dropped as-is already load-share sensibly), `D=25` kW/Hz (`ζ≈0.15`
per the sweep above).

**Sign convention.** Reversed-wiring generator, same physical stamp
direction as `src`/`gfm` — `syncgen: 1` in `FLOW_REVERSED` (ui.js), so both
the power-flow arrows and the plotted P sign follow the ONE universal
app-wide convention (positive = absorbing) established in §3. `Pm0`/`Kgov`
stay in the generator-intuitive convention (positive = dispatching this much
out), exactly like gfm's `P0` — the param and the plotted signal are allowed
to differ in sign convention, same precedent as gfm.

**Aux signal.** Frequency (`f`, Hz) is exposed via the same `AUX`/`auxInfo`
mechanism gfm uses for `Idc` (§3) — plot it from the Signals picker to watch
inertial response directly, the actual point of this block. The `AUX`
mechanism only supports one scalar channel per block kind (`curMeta.aux`/
`auxUnit` are singular, not arrays); rotor angle δ isn't separately exposed
in this pass — generalizing `AUX` to multiple named channels per kind is a
real, larger refactor (4+ call sites across solver.js/ui.js) deferred as a
natural follow-up, not attempted here for one extra signal.

**Known limitations** (classical model only, same honesty as every other
converter's documented tier): no subtransient reactances (Xd''/Xq/Xq'), no
saturation curve, no field/exciter dynamics beyond the Q-droop AVR, no
anti-windup on the governor or AVR (same accepted-limitation class as gfm's
droop). 3-ph mode only (same reason as gfm — the AVR needs the phase set to
measure Q).

### Induction motor, classical single-cage third-order model (`im`, July 2026 derivation)
Motivation: every load so far is static (R, PQ polynomial-in-nothing, CPL).
Motors are the dominant dynamic load on real systems: they draw inrush at
starting, reaccelerate after voltage dips, and can stall; none of that is
representable by a static load. Classical third-order model (Brereton, Lewis
& Young 1957; standard stability-study tier): rotor transient EMF phasor +
slip as dynamic states, stator transients neglected (same
"lightweight AVM" tier as gfm/syncgen, which also neglect stator dc offset
in their EMF branches).

**Electrical interface: Norton current source (QSS phasor coupling), NOT an
EMF-behind-impedance branch.** Two syncgen-style attempts failed, and the
failure mode is structural, worth recording. Attempt 1 (raw EMF branch on
Rs + L′ with instantaneous phasor extraction from the branch currents): the
trapezoidal stator branch produces real point-on-wave dc offsets at
energization (τ = L′/Rs); a stationary dc vector seen from the rotating
frame spins backwards at ωs, contaminates the extracted current phasor,
feeds Pe and the rotor ODE, and the loop self-excites. Attempt 2 (one-cycle
moving average on the extracted current): fixes energization, but during a
start the E′ TRANSIENT itself spins at −s·ωs in the frame; its EMF content
appears to the stator branch at (1−s)·ωs, where the branch admittance
approaches 1/Rs (no reactance near dc), giving the spinning mode a
round-trip gain ~dX/Rs ≫ 1 at mid slips where the averaging window has
little attenuation. No linear filter kills the whole slip range: the plant
itself (instantaneous branch driven by a fast-spinning EMF) violates the
third-order model's slowly-varying-phasor premise. So the interface is
inverted: extract the TERMINAL VOLTAGE phasor, compute the stator current
phasor ALGEBRAICALLY, and inject clean balanced sinusoids as a G = 0 Norton
current source (same interface family as pq/cpl/pfc; passive sign
convention, so no FLOW_REVERSED entry and plotted P is positive-absorbing
directly):
```
L′  = Lls + Lm·Llr/(Lm + Llr)     (transient inductance, H)
Lt  = Lls + Lm                    (total/synchronous inductance, H)
T0′ = (Llr + Lm)/Rr               (rotor open-circuit time constant, s)
dX  = ωs·(Lt − L′),  X′ = ωs·L′   (Ω), ωs = 2π·f0
Î   = (V̂f − E′)/(Rs + jX′)        (motor convention, phasor algebra)
inject per phase: i(ph) = √2·(I_re·sin(θs+shift) + I_im·cos(θs+shift)),
I[a1] −= i, I[a2] += i            (one-step lag, pfc/gfm-dc-port pattern)
```

**States.** Rotor transient EMF phasor (Ed, Eq) in a synchronously rotating
frame (RMS volts, sin reference: a signal √2·(U_re·sin θs + U_im·cos θs)
has phasor U_re + j·U_im), per-unit rotor speed ν = ωr/ωs (slip s = 1 − ν),
and the frame clock θs which advances at exactly ωs (θs is the FRAME, not a
rotor angle: rotor position enters only through the −j·s·ωs·E′ rotation).

**Voltage-phasor extraction.** For balanced sets the identities
Σph sin²(θs+shift) = 3/2 and Σph sin·cos = 0 hold at every instant, so
V_re = (√2/3)·Σph v_ph·sin(θs+shift_ph) (and cos for V_im) is
instantaneously exact (same trick as gfm's limiter phasor sums), then a
ONE-CYCLE moving average (integer cycles, the standing RMS-window rule)
nulls dc offsets, harmonics of ωs, and negative-sequence leakage exactly,
with unity gain on the envelope: steady state is untouched and
switching/fault transients enter the model smoothly over one cycle.

**Rotor flux dynamics** (standard third-order form, motor convention):
```
dE′/dt = −j·s·ωs·E′ − (E′ − j·dX·I)/T0′
```
componentwise: dEd/dt = s·ωs·Eq − (Ed + dX·I_im)/T0′,
dEq/dt = −s·ωs·Ed − (Eq − dX·I_re)/T0′.
At steady state this reproduces the textbook equivalent circuit exactly
(that is how the model is derived), which is what the smoke test exploits.

**Integration: decay explicit, rotation EXACT (splitting).** Explicit Euler
on the rotation term alone has gain |1 + j·s·ωs·h| > 1 per step; at s = 1
(starting) the amplification (≈(s·ωs·h)²/2 per step) can outrun the 1/T0′
damping when T0′ is large, i.e. exactly for realistically-sized machines.
So each step first applies the decay/forcing explicitly, then rotates the
phasor by the exact angle:
```
Ed* = Ed + h·(−(Ed + dX·I_im)/T0′)     Eq* = Eq + h·(−(Eq − dX·I_re)/T0′)
φ = s·ωs·h:  Ed ← Ed*·cosφ + Eq*·sinφ,  Eq ← Eq*·cosφ − Ed*·sinφ
```
Rotation preserves |E′| exactly, so the scheme is unconditionally stable in
the rotation and first-order accurate overall (h/T0′ and mechanical rates
are tiny at 50 µs; same accuracy class as gfm/syncgen's controller states).

**Mechanical.** Airgap power Pe = 3·(Ed·I_re + Eq·I_im) W (RMS phasors;
its only smoothing is the one-cycle window already inside V̂f). Load torque
TL = TL0·ν^k with TL0 ≡ PL0/ωs_mech (PL0 = load power at synchronous speed,
`PL` kW; k = `kexp`, 0 = constant torque, 2 = fan/pump). Swing in power
units (same avoid-per-unit style as syncgen):
```
dν/dt = (Pe − PL0·ν^k) / (2·H·Sbase)      [W / (s·W)]
```
advanced semi-implicitly like syncgen (ν from the OLD Pe, then θs += ωs·h).

**Sign/display conventions.** Passive current-source convention
(I[a1] −= i, exactly like pq/cpl), so plotted P is positive-absorbing (a
running motor reads positive kW) with NO FLOW_REVERSED entry. Aux signal:
slip `s` via the AUX mechanism (same single-scalar-per-kind limitation as
syncgen's f).

**Defaults** (in scale with the tool's kW examples, ~0.03–3 pu on a 15 kVA
base at 277 V): Rs=0.45 Ω, Lls=4 mH, Lm=120 mH, Rr=0.6 Ω, Llr=4 mH
(T0′ ≈ 0.21 s, X′ ≈ 3 Ω, X ≈ 47 Ω), H=0.5 s, Sbase=15 kVA, PL=10 kW,
kexp=2, s0=0.03 (near the ~10 kW equilibrium, so a dropped motor settles
instead of performing a full start; set s0=1 for a genuine DOL start study),
f0=60.

**Validated** (smoke_test.js): steady-state slip and stator current against
the steady-state equivalent circuit solved INDEPENDENTLY in the test
(Thevenin torque balance Pe(s) = PL0·(1−s)^k by bisection, stator current
from the full input impedance Zin(s)) — 0.08% slip error, 0.21% current
error at defaults; plus a DOL start check (s0=1: slip must fall
monotonically AND stay inside the physical band [−0.05, 1.001] over the
whole run, a guard written specifically because both failed interface
attempts above produced runaway overspeed that a weaker
"slip decreased" assertion certified as passing).

**Known limitations** (§7): no stator transients (the ~6–7x inrush
MAGNITUDE is captured via |V̂−E′|/|Rs+jX′|, the point-on-wave dc-offset
asymmetry is not), single cage (starting-torque underestimate for
deep-bar/double-cage machines), no saturation, frame fixed at f0 (assumes
the network stays near nominal frequency, same assumption class as gfm's
GFL mode), absent from solvePowerFlow() (a motor-fed case initializes from
its own s0 instead; PF results ignore motor draw). As a G = 0 current
source it contributes no admittance to the matrix (same class as pq/cpl),
and on a very weak tie (source impedance approaching |Rs + jX′| ≈ 3 Ω at
defaults) the envelope loop voltage→phasor→current→voltage can oscillate —
physically consistent with a large motor on a soft feeder, but not a
validated regime.

### DC-side converter AVMs (PFC rectifier, battery DC/DC, CPL)
DC-bus abstraction (rack/microgrid DC studies): converters are controlled
NORTON CURRENT SOURCES on the bus — no conductance stamp (G = 0); the bus
needs a capacitor block for the matrix to be non-singular (physical too: every
DC bus has one). A DC bus is a single-phase network, so 1-ph mode is the
natural way to run a pure DC study. These blocks are NOT rejected in 3-ph
mode, though (corrected July 2026: the older wording here claimed they were,
and no such guard exists or ever existed): a DC node simply carries 1 unknown
regardless of `nph`, which is exactly what lets a DC island coexist with a
3-phase AC network in one circuit. That hybrid case is the whole point of
`central_ups.json`. What IS enforced is the real safety property: an AC node
and a DC node may never be the SAME node. Wiring one directly to the other is
refused up front by the AC/DC classification fixpoint (§1), naming the
PFC/GFM DC port as the only legal join. Verified by test, both directions. The PFC's AC side is abstracted
(assumed stiff grid at unity pf); its DC port is what's modeled.

PFC rectifier, hybrid mode (3-ph): terminal 0 = AC input node (3-φ bundle),
terminal 1 = DC+ output, DC return = ground (implicit). DC side: PI/limit as
below. AC side: unity-pf balanced current sink carrying the DC power
(lossless AVM):  P = v_dc·i_cmd,  V̂² = (2/3)·Σ v_p²  (peak amplitude, exact
for balanced),  i_p = [2P/(3V̂²)]·v_p  drawn from the AC node (one-step lag on
v; no G stamp so the matrix stays constant). Undervoltage shutdown when
V̂ < 0.5·√2·Vac (auto-restarts on recovery); tgrid (ms) still forces grid loss.
In 1-ph mode the AC terminal is ignored (abstracted stiff grid; wire it to
ground) — same behavior as before hybrid support.

PFC DC loop / battery DC/DC (identical structure, different setpoints):
  PI voltage loop with output current limit, integrated forward-Euler at h
  (dt, or dt/2 in CDA half-steps), measurement = own terminal voltage from
  the previous solve (one-step lag, negligible at 50 µs):
    err = Vref − v;  integ += ki·h·err;  raw = kp·err + integ
    icmd = clamp(raw, lo, hi);  integ += icmd − raw   (anti-windup back-calc)
  Injection: I[n1] += icmd, I[n2] −= icmd.
  PFC clamp: lo = (rev=1 ? −Imax : 0), hi = Imax. With rev=1 the PFC is a
  bidirectional AC/DC link: negative icmd absorbs from the DC bus, and the
  SAME hybrid AC equation above exports it — P = v_dc·i_cmd < 0 makes
  kdraw < 0, so the unity-pf sink becomes a unity-pf in-phase injection
  (real power INTO the AC grid). No new AC math; UV shutdown still gates
  everything to 0 upstream of the clamp. Export scenario: set the PFC's Vref
  BELOW whatever holds the DC bus (battery/other source); its PI winds
  negative and pins at −Imax. Default rev=0 = the old one-way rectifier.
  PFC extra: tgrid (ms) — grid lost at tgrid ⇒ icmd = 0, integrator reset.
  Battery clamp is SOC-gated (bidirectional charge/discharge, July 2026):
    hi = (soc > 0 ? Imax : 0)      — empty battery can't source
    lo = (soc < 100 ? −Ichg : 0)   — full battery can't absorb
    d(soc)/dt = −icmd/(36·Ah)  %/s  (Ah·3600 A·s per 100 %), forward-Euler
    at the same CDA-aware h, clamped to [0, 100].
  One PI, both directions: bus above Vref (e.g. PFC holding 380 > batt 360)
  drives raw negative ⇒ CC charge at Ichg until SOC = 100, where the floor
  rises to 0 and charging stops WITHOUT chatter (err stays negative, icmd
  pins at 0). Bus sagging to Vref ⇒ the old discharge PI, until SOC = 0 and
  the bus collapses (realistic). soc0 = 100 (default) reproduces the old
  discharge-only idle exactly — a full battery cannot charge, so the idle
  current stays 0 and the classic backup scheme below is unchanged. Note the
  default Ah (0.02) is deliberately TINY: EMT runs are milliseconds, and a
  realistic rack battery (~100 Ah) would show a perfectly flat SOC; 0.02 Ah
  makes charge/discharge visible on a 100 ms plot. SOC is recorded per step
  and exposed as a plottable signal (aux channel, §3).
  Backup scheme: battery Vref set BELOW PFC Vref ⇒ battery output clamps to 0
  while the PFC holds the bus; on grid loss the bus sags to the battery
  setpoint and its PI takes over. No droop needed for 2-source DC PoC.

CPL (constant power load, e.g. server rack):
  i_target = P/v for v > vmin (UVLO cutoff below vmin, load sheds), first-order
  LPF (1 ms) on the drawn current to tame the negative-resistance step.
  Injection: I[n1] −= i, I[n2] += i.
  Stability (small-signal, bus cap C, regulating converter kp, ki):
    C·s² + (kp − P/V²)·s·C-normalized... char. poly: C s² + (kp − P/V²) s + ki
  ⇒ stable iff kp > P/V² (CPL negative incremental conductance) and ki > 0.
  Defaults kp = 2 A/V, ki = 2000 A/(V·s), C = 1000 µF, P = 10 kW, V = 380 V:
  kp = 2 ≫ P/V² = 0.07 ✓, poles ≈ −965 ± j1035 rad/s (settles in ~4 ms).
  UVLO default 300 V: keeps restart current P/vmin below typical Imax so the
  bus can climb through the UVLO point during current-limited precharge.

### Dedicated DC/DC converter (`dcdc`, July 2026 derivation)
Motivation: the battery block conflates the cell (SOC, capacity) with its own
built-in voltage-regulating converter. Real BESS installations separate
these — a dedicated buck-boost sits between the battery at its own native
voltage and a bus at a different level, and is what actually controls
charge/discharge (CC while charging/discharging hard, CV when regulating the
bus) — the classic industry pattern. Architecture picked by elimination
between the two existing candidates:
- batt/cpl (`makeElements`, built once per DC-classified block, single
  shared branch current between two terminals) doesn't fit — dcdc's two
  ports carry INDEPENDENT currents (input ≠ output, it converts voltage).
- pfc (`makeSpanning`, two independent Norton injections tied only by power
  balance, own `_vb`) is the right shape — **dcdc reuses this architecture
  exactly, DC↔DC instead of AC↔DC.** This matters mechanically: the generic
  per-phase loop auto-stamps `_vb = v(n1)−v(n2)` for ordinary branches
  (`phEls[p].forEach(e => {...; e._vb = vb;})`, solver.js) — meaningful for a
  single shared-current branch, but NOT for dcdc, where the cross-port
  voltage difference isn't a physically meaningful "branch voltage" (the two
  ports are independently regulated at different levels). Building it via
  `makeElements` would silently let that generic assignment overwrite
  whatever `_vb` the block itself sets. Spanning elements sit outside that
  loop and set their own `_vb` — the same reason pfc/gfm do it that way.

Two DC ports, both G=0 Norton (no stamp — the regulated side needs a
capacitor, same requirement as pfc/batt). Term 0 = IN, term 1 = OUT (the
regulated side — matches pfc's "DC output is regulated" and battery's "Vref
is what it holds" convention).
```
CV mode (mode=0, default): PI regulates OUT to Vref (identical structure to
  pfc/batt, no UV-shutdown/grid concept — dcdc has no AC side):
    err = Vref − vOut;  integ += ki·h·err;  raw = kp·err + integ
    icmdOut = clamp(raw, −Imax, Imax);  integ += icmdOut − raw   (anti-windup)
CC mode (mode=1): dispatch a fixed current directly — no PI, it isn't
  regulating a state, just setting an output:
    icmdOut = clamp(I0, −Imax, Imax)
Both modes then (lossless AVM, power balance — same principle as GFM's DC
port and PFC's AC-side draw):
    pOut = icmdOut · vOut
    target_icmdIn = clamp(pOut / (vIn ∥ ε), −Imax, Imax)
    icmdIn += min(1, h/1ms)·(target_icmdIn − icmdIn)      // 1 ms LPF
Injection: I[out] += icmdOut,  I[in] −= icmdIn.  _vb = vOut (P/Q plot signal
— Q doesn't apply, dc:true, same as pfc/gfm's DC ports). No sign-flip needed
in ui.js's P-sign list — `I[out]+=icmdOut` already reads "positive =
delivering" with no flip, exactly like pfc's DC port precedent.
```
**The 1 ms LPF on `icmdIn` is not optional — found by testing.** Without it,
this locks into a spurious LOW-VOLTAGE, both-sides-current-limited
equilibrium during the startup transient: OUT's PI reaches Vref in a
handful of 50 µs steps while IN's cap is still near 0 V, so the raw
`pOut/vIn` demand instantly clips at Imax and — because dcdc's derived draw
looks exactly like a constant-power load (P roughly fixed by OUT's own
regulation, independent of vIn) — it can stay pinned there rather than
easing off as vIn recovers, even though the intended (unclipped) operating
point is well within Imax. This is the identical negative-incremental-
conductance shape CPL already has, so the fix is CPL's own established fix:
the same 1 ms LPF, verified by direct testing to converge cleanly to the
analytical operating point where the un-filtered version got stuck.

Sign check: icmdOut>0 (delivering to OUT) ⇒ icmdIn>0 ⇒ current leaves IN
(battery discharges through it). icmdOut<0 (CV mode absorbing, or CC mode
with I0<0) ⇒ icmdIn<0 ⇒ current enters IN (battery charges) — same
bidirectional convention already established for battery/PFC/GFM.
**Composability note**: wiring dcdc directly to a battery block puts TWO
active controllers on the shared node (dcdc's derived draw + the battery's
own Vref-PI) — this is safe/non-conflicting specifically because the
battery's role is passive supply-to-setpoint (matching the existing
"backup" pattern where a regulating source just supplies whatever a load
draws), not a competing voltage-setter fighting dcdc for control of the
same node.
**A real gotcha found while building the example**: feeding a `pfc` bus
with dcdc's constant-current OUTPUT (CC mode) will runaway-ramp the bus
voltage without bound if the PFC is left at its unidirectional default
(rev=0) — PFC's clamp floors at 0 (can't absorb), so once the bus rises even
slightly above its Vref (from dcdc's unconditional injection having nowhere
else to go), PFC goes fully passive (icmd=0) and nothing opposes further
rise. Set the PFC's `rev=1` (already-established reversible-export feature)
whenever pairing it with a dcdc/GFM DC port that might push power the other
way — same requirement PFC-as-a-passive-recipient always has, just newly
exercised by a second active DC-side device.

### PV array with embedded MPPT (`pv`, July 2026 derivation)
Motivation: real PV installations are (almost) always paired with an MPPT-
controlled converter — the panel's I-V curve has a single power-maximizing
operating point that shifts with irradiance, and the converter's job is to
hunt for and hold it while stepping the panel's own voltage to whatever the
DC bus needs. Built as ONE combined block (panel + converter + MPPT), not
three separate ones, per the request that motivated it — with a real
Perturb & Observe search rather than an idealized instant-snap-to-MPP,
since P&O's characteristic hunting/oscillation around the peak is real,
correct behavior, not noise to eliminate.

**I-V curve** — single-exponential "engineering equation" fit (a standard
lightweight closed-form model, parametrized directly by the datasheet
numbers every panel ships with: Voc, Isc, Vmpp, Impp at STC):
```
C2 = (Vmpp/Voc − 1) / ln(1 − Impp/Isc)      // shape constants, G-independent
C1 = (1 − Impp/Isc) · exp(−Vmpp/(C2·Voc))
I(V) = Isc_G · [1 − C1·(exp(V/(C2·Voc)) − 1)],  clamped to [0, Isc_G]
```
Irradiance (`G`, W/m², default 1000 = full sun) scales the current axis
linearly — `Isc_G = Isc·G/1000` — while Voc/Vmpp are held fixed (a documented
simplification: real Voc/Vmpp shift slightly with irradiance/temperature;
this AVM neglects that and has no temperature parameter at all). Verified
by direct computation (not just derivation): this closed form is NOT an
exact MPP fit — `dP/dV=0` doesn't land precisely at the nominal Vmpp — but
the discrepancy is small (checked numerically: nominal Vmpp=36V, true
numerical peak at 36.6V, 0.18% higher power — well within the P&O hunting
band anyway, so it doesn't matter in practice).

**MPPT (Perturb & Observe)**, running on its own slower clock (`Tmppt` ms,
default 1 — 20 solver steps at 50 µs, not every step, matching how a real
MPPT controller updates far slower than the EMT timestep):
```
every Tmppt ms:
  P_now = vop · I(vop)
  if P_now < P_prev: dv = −dv          // power dropped -> reverse direction
  vop = clamp(vop + dv, 0, Voc)
  P_prev = P_now
```
`vop` (the internal, MPPT-controlled operating voltage) is completely
decoupled from the actual bus voltage — that decoupling IS what the
embedded converter is for; it's a genuine internal state variable, not the
node voltage `pv` happens to be wired to. Fixed step size (`dV`, default
0.5 V) means the steady-state behavior is a small, persistent oscillation
around Vmpp — verified: with the defaults, `vop` hunts between 36.0-37.0 V
once settled, matching the expected ±1 step-size band around the peak. This
is genuine P&O behavior, not an artifact to fix.

**Output injection** — lossless AVM, generation-only (floor of 0 — a panel
can't absorb power):
```
every solver step:
  I_now = I(vop)                         // vop only CHANGES every Tmppt,
  P_pv = vop · I_now                     // but re-evaluated every step so
                                          // the injected current tracks the
                                          // (possibly moving) bus voltage
  target = clamp(P_pv / (vbus ∥ ε), 0, Imax)
  icmd += min(1, h/1ms)·(target − icmd)  // same 1 ms LPF fix as CPL/dcdc —
                                          // identical negative-incremental-
                                          // conductance shape (P roughly
                                          // fixed, injected current is
                                          // P/v) as CPL/dcdc's derived
                                          // ports, so it needs the same
                                          // established fix.
inject: I[n2] += icmd, I[n1] −= icmd   (n1=return/term0, n2=DC+/term1 — the
ordinary PASSIVE terminal arrangement, same as batt, NOT pfc/dcdc's single-
terminal-to-ground convention — so pv needs the same P-sign flip batt gets
in ui.js, always reading positive since it's generation-only).
```
**Architecture** — reuses the SIMPLER of the two patterns established while
building `dcdc`: pv has exactly ONE current between exactly two terminals
(architecturally identical to batt/cpl), so it's built inside the existing
`makeElements` (not a new spanning factory) — `_vb` is auto-computed
generically by the per-phase loop (`e._vb = v(n1)-v(n2)`, solver.js), which
is correct here since n1/n2 ARE pv's only two terminals (unlike dcdc's
cross-port difference, which needed its own spanning-element `_vb`). Zero
curInfo/vbInfo dispatch changes needed. `Vop` rides the same generalized
aux-channel mechanism as battery SOC / gfm Idc (one `AUX` table entry).

### CDA (critical damping adjustment) at switching events
Pure trapezoidal leaves an undamped z = −1 (Nyquist) oscillation after a
switching discontinuity (observed: sustained 2-point ringing after fault
clearing into a capacitor). Standard EMTP fix: replace the step following any
switch event with TWO backward-Euler half-steps (h = dt/2). Key property: BE
at h = dt/2 yields the SAME companion conductances as trapezoidal at dt
(series RL: G = 1/(R + L/h) = 1/(R + 2L/dt); cap: G = C/h = 2C/dt), so the
existing LU is reused — only the history formulas change for that one step:
  series RL / xfmr:  Ih_BE = G·(2L/dt)·i_{n−1}          (no v term)
  capacitor:         Ih_BE = −G·v_{n−1}                  (no i term)
  coupled line:      Ih_BE = Geq·(2L/dt matrix)·i_{n−1}
Post-solve update is unchanged (i = G·v + Ih; v ← v_branch) in both modes.

### Breaker
Conductance switch: G_on = 1e4 S, G_off = 1e-8 S (never exactly 0, so G stays
nominally non-singular; caveat: an island whose only path to ground is 1e-8 S
is numerically near-singular — the solver detects this and reports it).
Params: tclose (ms), topen (ms, −1 = disabled), init (0 open / 1 closed).
State change ⇒ refactorize LU (per phase — each phase owns its factorization).
Closing happens at tclose in all phases. Opening is current-zero: at topen the
breaker ARMS; each pole actually opens at the first sign change of its own
branch current after arming (pcur·cur ≤ 0 test between consecutive steps), so
poles clear at different instants.
The FAULT block reuses this machinery verbatim: a one-terminal switch to
ground with gon = 1/Rf, tc = ton, to = toff (elements carry gon/goff/tc/to
so the solver event loop is switch-type agnostic). FAULT keeps the original
single-transition (one-shot auto-clear) model described below; it does not
get the multi-op schedule.

**Multi-operation reclosing (July 2026).** `brk` params add nOps (1-5, the
number of close/open pairs). Op 1 is tclose/topen as above (so nOps=1 is
byte-for-byte the original single-transition behavior; every existing
example is unaffected). Ops 2..nOps are numbered tclose2/topen2 ..
tclose5/topen5, built at circuit-build time into a per-element `sched` array
of {tc, to} pairs (blocks.js). Instead of latching on the pole's own
current-zero opening, the solver event loop (solver.js) checks whether a
next scheduled op exists and, if so, advances to it: pulls the next op's
tc/to into the element's live tc/to and resets armed/opened to false, so the
close check can fire again on a later step. This is the exact reset shape
`vsw.update()` already used to force a controller-driven reclose on a `brk`
element (2026-07-16); the schedule just drives the same reset from a time
table instead of a controller command. A schedule entry whose `to` is −1
means "stay closed from here on" (same semantic as the single-op case);
each pole still advances/clears independently, since `sched`/`opIdx` are
per-phase-element state like everything else the switching loop tracks.
Caveat: nOps > 1 and an external `relay`/`vsw` `brkId` link to the same
breaker both drive the same element's tc/to/opened state and will conflict
if combined — use one control path or the other, not both.

### Overcurrent relay, IEEE C37.112 (`relay`, July 2026 derivation)
Motivation: breakers so far open only at a user-scheduled `topen`; real
protection DECIDES to open from measurements. The relay is the decision
element: a series sensing block that trips a separate `brk` block by ID
(the project's standing ID-lookup convention), letting one breaker serve
both scheduled and protective studies unchanged.

**Element.** Spanning series element, one per relay block, looping
ph = 0..nph−1 (pline pattern; a relay on a DC node degenerates to one
phase). Stamps a FIXED closed-breaker conductance G_on = 1e4 S per phase —
the relay itself never opens, so the LU is never refactorized on its
account; only the target breaker switches. Branch current per phase is
i = vb·G_on (the ~0.1 mV/A drop is the sensing shunt).

**Measurement.** Per-phase one-cycle sliding RMS (integer-cycle window, the
standing rule; N = round(1/(f·dt)) samples, running sum of squares).
Multiple of pickup: M = Irms/Ipu, evaluated per phase; the worst phase
drives the trip integral.

**Inverse-time element (51), C37.112 dynamic integral.** The standard's
analytic curve gives the trip time at constant M:
```
t(M) = TD·( A/(M^p − 1) + B )   seconds
  moderately inverse (MI): A=0.0515, B=0.1140, p=0.02, tr=4.85
  very inverse (VI):       A=19.61,  B=0.491,  p=2,    tr=21.6
  extremely inverse (EI):  A=28.2,   B=0.1217, p=2,    tr=29.1
```
For time-varying current the standard's dynamic (induction-disk travel)
form integrates: trip when ∫ dt/t(M(t)) ≥ 1, accumulated only while
M > 1 (guarded at M > 1.001 against the pole). Below pickup the disk flies
back: d(integral)/dt = −(1 − M²)/(TD·tr) (the standard's reset
characteristic), floored at 0. Curve constants are per C37.112-1996.

**Instantaneous element (50).** `Iinst` (A rms, 0 = disabled): any phase
RMS above it trips immediately (subject only to the one-cycle RMS window
itself — no intentional delay).

**Trip action.** On trip (latched), the relay ARMS its target breaker by
setting the breaker elements' `to` to the present instant in every phase;
the solver's existing switch-event machinery then opens each pole at its
own next current zero, exactly as a scheduled `topen` would (elements carry
gon/goff/tc/to so the event loop stays switch-type agnostic — the same
reuse the fault block exploits). A new one-line link step in `simulate()`
hands spanning elements the per-phase element lists
(`sEls.forEach(e.link)`), which is how the relay finds its breaker's
elements; `simulate()` validates up front that `brkId` names an existing
`brk` block. Aux signal: the trip integral (0..1, latches at 1), so the
plot shows the relay "winding up" toward its trip.

**Validated** (smoke_test.js): timed-trip instant against the closed-form
t(M) at a known steady M (plus the bounded one-cycle RMS warmup and
current-zero slop), the instantaneous element, and a below-pickup no-trip
hold.

**Known limitations** (§7): no directional element, no reclose, one target
breaker per relay, RMS (not peak/cosine) measurement only, and on a DC
node the trip arms a breaker that never finds a current zero (same DC
breaker physics as everywhere else).

### SVC/STATCOM shunt compensator (`svc`, July 2026 derivation)
Motivation: dynamic reactive support is the standard fix for weak-bus
voltage problems; the two classical devices differ only in their limit
behavior (SVC = thyristor-switched susceptance, Q ∝ V² at the ceiling;
STATCOM = converter current source, Q ∝ V at the ceiling).

**Model.** One-terminal 3-ph shunt (fault-block attach, ground return).
The pq derivation's quarter-period trick gives a REAL susceptance with no
1/V² division at all: an inductor draws i = B_L·v(t−T/4), so a shunt
compensator injecting capacitive current is
```
i_drawn(ph) = −(Iq/Vrms)·v_ph(t−T/4)     (Iq in A rms, + = capacitive)
```
State: Iq, integral voltage control with the classical droop slope:
```
dIq/dt = Ki·(Vref − Vrms − Xs·Iq)        (steady: Vref − V = Xs·Iq)
mode 0 (SVC):     clamp Iq ∈ [Bmin·Vrms, Bmax·Vrms]   (B limit, Q~V²)
mode 1 (STATCOM): clamp Iq ∈ [−Imax, +Imax]           (I limit, Q~V)
```
Vrms from a one-cycle moving average of Σph v²/3 (integer-cycle rule).
Pure integrator + hard clamp needs no anti-windup back-calculation. 3-ph
mode only (it measures the phase set). Aux signal: Iq.

**Validated** (smoke_test.js): on a sagging weak bus the closed loop
lands exactly on its droop line (Vref − V = Xs·Iq checked from measured
signals), lifts the bus above the analytic uncompensated baseline, and at
a deliberately unreachable Vref pins at the mode-specific ceiling
(Iq = Bmax·Vrms for SVC, Iq = Imax for STATCOM).

**Known limitations** (§7): balanced positive-sequence support only, no
harmonic/TCR switching detail, not represented in solvePowerFlow(), and
the quarter-period reference shares pq's off-nominal-frequency caveat.

### Node frequency at probes and buses (July 2026 derivation)
Motivation: machines already reported frequency (`syncgen`'s rotor, `gfl`'s
and `gtrip`'s PLL), but NETWORK frequency had no reading of its own. The only
way to get frequency at a bus was to hang a threshold-free `gtrip` relay there
purely as a sensor, which is how `studies/Spain_Blackout` measured it. A probe
is the natural place for the measurement, and a cascade study wants frequency
at every bus, not only where a machine happens to sit.

**Measurement.** Every probe and every bus on a 3-phase AC node carries the
same SRF-PLL that `gfl`/`gtrip` use, run as a pure sensor with no thresholds
and no trip path. Correlate the three node voltages against the loop's own
rotating frame, box-car one cycle, and drive a PI loop on the quadrature
angle:

```
delta = atan2(<Vim>, <Vre>),   w = w0 + Kp·delta + Ki·∫delta dt,   f = w / 2π
```

with the same gains, integrator clamp and slew limit as `gtrip`.

Two details that matter in practice:

- **The frame turns while the window fills.** Correlating against a stationary
  frame averages a sinusoid to zero over the window, so the first reading
  after the fill would be 0/0. This is the same trap `zrel` fell into.
- **The loop starts aligned.** With frame angle 0 the correlator reads
  (3/2)·Vm·(cos θ, sin θ), so the node's own angle is one `atan2` away and is
  applied on the first step. Left at θ = 0 the PI loop pulls in from an
  arbitrary angle error, which is a genuine 45 to 62 Hz excursion over the
  first cycles: honest, but it dominates the plot's autoscale and buries the
  signal. Aligned, the same run stays inside 59.96 to 60.13 Hz.

**Tracking range.** +/-50% of nominal (25 to 75 Hz on a 50 Hz system),
deliberately wider than `gtrip`'s +/-30%: gtrip is a control loop driving a
trip decision and must not chase garbage, this is an instrument. A clamped PLL
reports a rock-steady 0.5 to 0.7 x nominal that reads exactly like a settled
system, so each node latches a saturation flag surfaced as `probeMeta.fSat`
and `query(id,'f').saturated`. A trace that touched the stop is not a
measurement and must not be quoted.

**3-ph AC only.** A positive-sequence phasor needs three phases, so DC nodes
and single-phase laterals carry NO frequency signal rather than a misleading
flat nominal. `probeMeta.hasF` says which nodes have one; the API's
`query(id, 'f')` returns a single series (a positive-sequence PLL has one
output, not one per phase) and a clear error where there is none. Inferring
frequency from a single phase would be a different method (zero-crossing
period) with different noise behaviour, not the same number.

**Validated** (smoke_test.js): tracks 60.0000, 50.0001 and 59.2000 Hz against
sources at those frequencies; a bus and a probe on the SAME node read
identically; a 1-ph run reports `hasF` false with a null series.

### Distance / line-protection relay (`zrel`, July 2026 derivation)
Motivation: real transmission lines are protected by distance (impedance)
relays that decide whether to trip from the local V and I phasors. The
existing `relay` is an overcurrent element; a distance relay lets a line
study decide its own islanding or fault clearing from apparent impedance,
which is what `studies/Spain_Blackout` needs for a solver-driven France-tie
opening.

**Element.** Series sensing block, two terminals, placed in the protected
line exactly like the overcurrent `relay`. It stamps the same fixed closed-
breaker conductance G_on per phase; the element itself never opens, so the
LU is never refactorized on its account. On trip it arms a separate `brk`
block by ID.

**Measurement.** A local SRF-PLL locked to the positive-sequence terminal
voltage, same family as `gfl`/`gtrip`. Both the terminal-0 voltage and the
element current are correlated against the PLL's own rotating frame in one
pass and averaged by one-cycle boxcars:

```
Vre = Σ_k v_k·sin(θ + δ_k),   Vim = Σ_k v_k·cos(θ + δ_k),   δ = [0, −2π/3, +2π/3]
```

and identically for I. For a balanced set this sums to (3/2)·peak·cos∠, so
the **same** factor √2/3 is applied to both, turning each into an RMS
phasor:

```
Z = V_1 / I_1   (ohms, apparent impedance to the fault)
```

The scaling must be identical on the two paths or the ratio is not in ohms.
Scaling V as an RMS phasor (√2/3) while scaling I as a half-peak phasor
(1/3) leaves a stray factor of √2 in every impedance the relay measures,
which reads as a plausible number and is invisible until a reach is checked
against a hand calculation. The smoke test therefore asserts |Z| against the
analytical network impedance, not just against trip/no-trip.

Two gates precede any zone pickup, both measurement validity rather than
protection philosophy:

- **Frame rotation during fill.** θ free-runs at ω₀ while the one-cycle
  window fills. Correlating against a *stationary* frame averages a 60 Hz
  signal to zero, so the first sample after the fill would be 0/0 — and a
  garbage Z near the origin sits deep inside every mho circle, tripping a
  healthy line on the relay's first look at it.
- **Settling window.** One further full window before the element may act:
  the first complete boxcar still straddles the energization transient and
  the PLL has had no cycle to pull in. `seed()` sets both as already
  satisfied, since a PF-initialized case starts with valid measurements.

`tarm` (arming delay, ms) is the separate, deliberate block on a start-up
ring, with the same meaning and default as `gtrip`'s. `Imin` (positive-
sequence RMS amps, 0 = off) is the optional classical fault-detector
supervision: gate the impedance element on a minimum current so Z = V/I only
acts while enough current flows for the ratio to mean something.

**Characteristic.** Two public-domain options:

*Mho* (default): circle with diameter from the origin to `Zr·e^(jθ)`.
```
center = (Zr/2)·e^(jθ),   radius = Zr/2
trip when |Z − center| < radius
```
*Impedance circle*: plain circle centered at `Zr·e^(jθ)` with radius `Zr`.
```
trip when |Z − Zr·e^(jθ)| < Zr
```

`θ` is the characteristic angle (deg); `Z1`, `Z2`, `Z3` are the reaches of
the three zones.

**Zones and timing.** Three independent definite-time zones. Zone 1 is
normally instantaneous (`T1 = 0`), zones 2/3 are backup delays. Each zone
has its own pickup latch and dwell timer: while Z stays inside the circle
the timer runs; leave the circle and it resets. First zone to time out
latches the trip permanently for the run.

**Out-of-step tripping (double blinder).** Distance zones cannot detect a
system separation, and this is not a tuning problem. A separation swing on an
exporting tie sits in the CAPACITIVE half of the impedance plane: measured on
the Spain_Blackout France ties, X is negative in every sample from the
disturbance to the tie opening, on both ties. A mho circle at the line
characteristic angle (84° there) is tangent to the origin and extends into
X > 0, so the locus and the characteristic occupy effectively disjoint half
planes and the element never picks up over reaches from 60 Ω to 300 Ω.
Enlarging the reach only grows a circle in a region the locus never visits.
The classical scheme therefore discriminates on **time**, not position.

(Corrected 2026-07-29. This paragraph previously said the locus "sits between
0° and −25°", which the measurement does not support: an exporting tie has
R < 0, so a locus near the resistance axis has an argument near ±180°, not
near 0°, and the measured argument spans roughly −178° to 0°. The conclusion
was right and the stated reason was wrong. The operative fact is the SIGN OF
X, not the narrowness of the angle. See DECISIONS.md 2026-07-29.)

Define the blinder coordinate as the component of Z perpendicular to the
characteristic direction `e^(jθ)`:

```
u = R·sin θ − X·cos θ
```

which reduces to the textbook pair of vertical lines on R when θ = 90°. Two
blinders sit at `|u| = RB1` (inner) and `|u| = RB2` (outer), `RB2 > RB1 > 0`.

```
region(u) = 2 if |u| > RB2,  1 if RB1 < |u| <= RB2,  0 otherwise
```

A fault puts the impedance inside the blinders in a single step; two systems
pulling apart take tens of milliseconds to walk the locus across. So the
scheme times the transit: on a 2→1 crossing it records the instant and the
side, and if the locus then reaches region 0 no sooner than `Tsw` after that
crossing, the event is declared a **power swing** rather than a fault.

Trip logic (`oos`): `1` = trip on the way **out** — wait until the locus
leaves the outer blinder on the side opposite the entry, i.e. a completed pole
slip. This is the classical preference: the breaker interrupts with the two
systems swinging back together and sees far less recovery voltage than it
would at the 180° point. `2` = trip on the way **in**, as soon as the swing is
declared. `0` = off, so a case that does not ask for it behaves exactly as a
plain distance relay.

The blinder region starts as "unknown", so a locus that is already inside the
blinders at t = 0 must leave and re-enter before it can be called a swing.

**Trip action.** Same as `relay`/`gtrip`: set the target breaker elements'
`to` to the present instant; the existing switch-event machinery opens each
pole at its own next current zero.

**Validated** (smoke_test.js), on a src / breaker / relay / line (3.5 Ω at
80°) / load network: measured |Z| matches the analytical network impedance
to better than 2% both healthy (20.894 Ω) and with a resistive fault
(8.050 Ω); a fault inside zone 1 trips and the pole clears at the next
current zero; a fault outside the reachable zones holds off; tight reaches
against a healthy load hold through start-up (the 0/0 regression); a
nonexistent `brkId` and a 1-ph run each produce a clear validation error.

**Known limitations** (§7): no out-of-step BLOCKING of the distance zones
(the scheme trips, it does not supervise), no trip-on-Nth-slip counter, no
directional element, no quadrilateral/lens/offset-mho variants, no
sequence-component supervision, no communication-assisted or traveling-wave
schemes. Blinders are straight lines, not the lens/tomato pair some schemes
use. Reaches and blinders are entered in ohms, not per unit. 3-ph AC only;
the positive-sequence extraction needs three phases.

### Bergeron traveling-wave line (`tline`, July 2026 derivation)
Motivation: the lumped `line`/π blocks are fine below a few kHz, but
switching-surge and traveling-wave studies need true distributed
propagation: a wave entering one end must ARRIVE at the other exactly one
travel time later, reflect off mismatches, and double at an open end. That
is the founding EMTP method (Dommel 1969).

**Model.** Lossless distributed LC characterized by surge impedance Z (Ω)
and travel time τ (µs), plus total series resistance R lumped the standard
way (R/4 at each end, R/2 in the middle). Companion (per phase, both ends;
m = far end):
```
Zm = Z + R/4,   h = (Z − R/4)/(Z + R/4)
i_k(t) = v_k(t)/Zm + hist_k
hist_k = −(1+h)/(2Zm)·v_m(t−τ) − (1+h)·h/2·i_m(t−τ)
         −(1−h)/(2Zm)·v_k(t−τ) − (1−h)·h/2·i_k(t−τ)
```
(R = 0 gives h = 1 and the classic lossless form
i_k = v_k/Z − v_m(t−τ)/Z − i_m(t−τ).) The two ends are DECOUPLED in the
matrix: each stamps only a diagonal 1/Zm at its own node (that decoupling
is the whole point of the method — the ends talk only through delayed
history), so it is a spanning element with diagonal-only stamps, looped
per phase like the π line (no cross-phase coupling in this pass; ground
return implicit).

**Delay buffers.** Per phase and per end, circular buffers of v and i;
the τ-delayed read is linearly interpolated (delay need not be an integer
number of steps). `simulate()` validates τ ≥ dt with a clear error. CDA
half-step pairs would store two samples per dt and skew the buffer clock,
so on backward-Euler steps the element stores only on the second half-step
(toggle), and history reads reuse the full-step delayed values (standard
EMTP practice; the error is one half-step of delay once per switching
event).

**Plotted signals.** i[p] = sending-end (terminal 0) current into the
line; _vb = sending-end node voltage, so P = v·i reads sending-end power
INTO the line (pfc's single-node-voltage precedent); no through-power.

**Validated** (smoke_test.js): open-end energization — the receiving end
is exactly zero until τ and then reproduces 2·v1(t−τ) sample-for-sample
until the second reflection window closes (t < 3τ); matched load Z —
v2(t) = v1(t−τ) with no reflection.

**Known limitations** (§7): balanced/per-phase only (no coupled-mode
Bergeron), lossless propagation with lumped R (no frequency-dependent
attenuation — that is `fdline`'s job), AC-side use intended.

### Frequency-dependent line, JMarti class (`fdline`, July 2026 derivation)
Motivation: the Bergeron line's Zc and attenuation are constants, but real
lines (especially with ground return) have frequency-dependent
characteristic impedance and propagation: high-frequency wavefronts
attenuate and disperse while the fundamental passes nearly unscathed.
JMarti (1982) represents both as rational functions and convolves
recursively (Semlyen). v1 ships MINIMUM fitting order with canned typical
parameters — no fitting code (that is where the complexity lives; the
user can override the pole/gain params directly):
```
Zc(s) = Zh + kz/(s + pz)         kz = (Zlf − Zh)·pz   (Zc: Zh at HF, Zlf at dc)
H(s)  = e^(−sτ)·kh/(s + ph)      kh = att·ph          (delay + 1-pole smear, dc gain att)
```

**Recursive convolution.** For a kernel k·e^(−pt) with linearly
interpolated input, the exact recursion is
y_n = a·y_(n−1) + b·x_n + c·x_(n−1) with a = e^(−p·dt),
b = (k/p)·(1 − (1−a)/(p·dt)), c = (k/p)·((1−a)/(p·dt) − a).

**Companion (per phase, per end; Marti form).** With forward/backward
waves F_k = v_k + Zc∗i_k, B_k = v_k − Zc∗i_k and B_k = H∗F_m:
```
Zc∗i_k = Zh·i_k + w_k,  w recursion on i_k (coefficients b_z, c_z)
i_k_n = G·(v_k_n − rhs_k),  G = 1/(Zh + b_z)
rhs_k = a_z·w_(n−1) + c_z·i_(n−1) + b_k_n
b_k_n = a_h·b_(n−1) + b_h·F_m(t_n−τ) + c_h·F_m(t_(n−1)−τ)
```
Diagonal-only stamps and τ-delayed F buffers exactly like `tline`
(including the CDA store-toggle and the τ ≥ dt validation); after the
solve, w advances and F_k = v_k + Zh·i_k + w_k is stored. Setting
Zlf = Zh and att = 1 with a fast ph degenerates to the Bergeron line
(asserted).

**Validated** (smoke_test.js): the Bergeron degenerate case reproduces
open-end doubling; with real frequency dependence the 60 Hz transfer
(magnitude and phase) matches an INDEPENDENT complex two-port solve of
the same rational functions to <2%.

**Known limitations** (§7): first-order fitting only (one pole each for
Zc and H — real JMarti fits use 5–15; accuracy beyond the fundamental and
the first wavefront is qualitative), per-phase/balanced only, no fitting
from geometry, and the propagation recursion double-advances on CDA event
steps (same accepted slop as tline's buffer).

### Surge arrester (`mov`, July 2026 derivation)
Motivation: switching and fault-clearing transients produce temporary
overvoltages; the arrester is the classical clamp. Standard EMTP
representation: PIECEWISE-LINEAR resistor with segment switching, not the
exponential i = k·(v/Vref)^α law directly — an α ≈ 30 exponential as a
lagged Norton injection is violently unstable without a matrix stamp, and
a per-step Newton solve is out of scope for this solver's LU-once
architecture (same class of argument as the pq derivation's).

**Model.** One-terminal shunt to ground (fault-block topology), per phase.
Two segments per polarity:
```
|v| ≤ Vc:  i = G_off·v            (leakage, G_off = 1e-8 S)
 v > +Vc:  i = (v − Vc)/Rd         (affine clamp, slope 1/Rd)
 v < −Vc:  i = (v + Vc)/Rd
```
Continuous at the knee (i = 0 at |v| = Vc), so segment changes cause no
numerical shock. The element stamps its CURRENT segment's conductance
(stampPhase reads `e.G` fresh at every rebuild) and injects the affine
offset ±Vc/Rd while conducting. Segment selection is a new GENERIC
`segCheck(t)` hook in the solver's event scan: any per-phase element may
report "my conductance changed", triggering the same LU refactor + CDA
half-steps a breaker uses. The arrester conducts only near voltage peaks,
so expect a handful of refactors per cycle during a clamped overvoltage
(bounded, and only while actually clamping).

**Validated** (smoke_test.js): below the knee (392 V peak vs Vc = 450) the
arrester passes only leakage; above it, the clamped peak matches the
source/arrester divider v = (Vs/Rs + Vc/Rd)/(1/Rs + 1/Rd) and its current
(v − Vc)/Rd analytically.

**Known limitations** (§7): two-segment piecewise-linear (no α exponent,
no frequency-dependent or IEEE-WG dynamic arrester model), no energy
accumulator/failure model.

### Switched-shunt voltage controller (`vsw`, July 2026 derivation)
Motivation: utilities regulate feeder voltage with mechanically switched
capacitor/reactor banks; the controller is the missing piece (the bank
itself is just `cap`/`rlc` behind a `brk`). `vsw` is a one-terminal
SENSOR (no stamp, no injection, the probe of the control family) that
closes/opens a breaker by block ID, the same link() machinery the relay
introduced.

**Measurement.** Per-phase node voltage at its terminal; Vrms from a
one-cycle moving average of Σph v²/nph (integer-cycle rule), so switching
transients don't chatter the thresholds.

**Control.** mode 0 (support, capacitor bank): close when Vrms < Von,
open when Vrms > Voff (Von < Voff, the dead band holds the bank in).
mode 1 (limit, reactor bank): mirrored (close high, open low). Either
condition must hold CONTINUOUSLY for Td ms before acting (utility-style
time delay, also the anti-chatter guard).

**Action and the reclose caveat.** Close: clears the target breaker's
`opened`/`armed` latches and sets `tc` = now (the event loop closes it
this step); open: sets `to` = now (arms; each pole opens at its own
current zero). Clearing `opened` deliberately allows RECLOSE, which the
standalone breaker forbids (its latch documents real breakers not
auto-reclosing); a switched shunt's whole purpose is repeated operation,
so the controller-driven path is exempt. Aux signal: commanded bank state
(0/1). `brkId` validated up front like the relay's.

**Validated** (smoke_test.js): a sagging feeder (analytical phasor
prediction for both the sagged and the supported voltage) closes the bank
one delay after the RMS window settles and holds it, landing at the
predicted compensated voltage; a healthy feeder never closes.

### Latching generation-trip relay (`gtrip`, July 2026 derivation, §5 item 34)
Motivation: `vsw` is a shunt controller that RECLOSES by design, and `relay`
decides on current only. Neither can make a generator trip and STAY tripped on
a voltage or frequency excursion, which is the mechanism that lets a cascade
self-drive (plant A trips, the network moves, plant B's own measurement crosses
its threshold, B trips) instead of being scripted onto a timeline. `gtrip` is
the third member of the control family: the same one-terminal sensor shape as
`vsw`, the same `brkId` link as `relay`, definite-time 59/27/81O/81U elements,
and a latch that is never cleared for the rest of the run.

**Element.** One-terminal SENSOR: no `stamp`, no `inject`, no history in the
network, so it can never perturb the solution it measures (the `vsw` shape, and
the reason it needs no LU refactorization of its own). Lateral-aware through
`topo.phList(b)`: `[0,1,2]` on an ordinary 3-phase node, `[0]` on DC or in 1-ph
mode, `[k]` on a phase-k lateral. Node voltages read as `v_p = V[gIdx(b,0,p)]`
with the solver's `n < 0 -> 0` ground convention.

**Voltage measurement.** `vsw`'s measurement verbatim: a one-cycle boxcar of
Σ_p v_p²/nEff (integer-cycle rule, N = round(1/(f0·dt)) samples, running sum),
then Vrms = sqrt(sum/N). For a balanced 3-phase set this is exactly the
per-phase rms with no ripple at all, and it is the only form that also works on
a lateral or in 1-ph mode. Thresholds are per-phase quantities, so they go
through `vPh(p.Vov, nphB)` with the same `nphB` rule `vsw` uses (a lateral is a
phase-to-neutral connection and takes no LL/√3 divide). No decision is made
until the window is full (`bcnt >= N`), the `vsw` start-up-ramp guard.

**Frequency measurement (3-phase AC only).** The 81 elements need a bus
frequency, which nothing in the library measures at a node today (`syncgen`
reports rotor speed, `gfl` reports its own PLL, both internal to a source). Reuse
the `gfl` SRF-PLL, simplified by the fact that this is a ONE-terminal sensor:
`gfl` locks to the BRANCH voltage `vbr = v(t0) − v(t1)`, which sits π off the bus
angle under the standard term0-grounded wiring; `gtrip` correlates the node
voltage directly, so there is no sign flip and no π offset anywhere. Do not
carry `gfl`'s `vbr`/π reasoning across.

Per step, project the node voltages onto the relay's own rotating frame θ and
average over the same one-cycle boxcar (φ = (0, −2π/3, +2π/3), the standing
`SHIFT`):
```
Vrf = (√2/3)·Σ_p v_p·sin(θ+φ_p) ,   Vif = (√2/3)·Σ_p v_p·cos(θ+φ_p)
```
For a balanced set v_p = √2·V·sin(θg+φ_p) this gives V̂ = V·e^{j(θg−θ)} with
|V̂| = V (per-phase rms), i.e. the same scaling as Vrms above, which is why the
one Vrms quantity can supervise both families and no second magnitude state is
needed. The boxcar-averaged V̄rf, V̄if give the loop error
```
δ = atan2(V̄if, V̄rf)          (rad; normalised, so the gains are
                               voltage-independent from 4 kV to 400 kV)
```
and the PI loop is `gfl`'s, with one deliberate change:
```
∫δ += δ·h        only while |δ| < π/2 AND Vrms ≥ Vblk_eff   (pull-in-range
                 anti-windup; freeze on a collapsed bus)
∫δ  clamped so that |Ki·∫δ| ≤ 0.3·ω0                        (state clamp)
ω_vco  = ω0 + Kp·δ + Ki·∫δ ,   θ += ω_vco·h                 (tracking path)
ω_meas = ω0 + Ki·∫δ                                          (measurement path)
f = ω_meas/(2π)
```
`h = dt/2` on a backward-Euler CDA half-step, as everywhere.

Two frequencies, and this is the derivation's substantive choice. `gfl` needs
`ω_vco` because it must place an injected sinusoid; a definite-time 81 element
must not see it. The proportional term Kp·δ is the PHASE-correction path: any
angle step (a fault, a breaker pole clearing, or simply the one-cycle boxcar
lagging a transient by up to a cycle) puts a large spurious δ into it and
`ω_vco` spikes, which is correct for re-aligning θ and completely wrong as a
grid-frequency reading. The INTEGRATOR STATE is the frequency estimate: in lock
δ → 0 and the integrator alone supplies the whole off-nominal offset, so
ω_meas = ω_vco = ω_grid in steady state, while ω_meas stays smooth through the
transient. This is why the integrator is clamped as a STATE here rather than
clamping only the summed correction as `gfl` does: in `gfl` the sum is the
output, here the state is. Two free consequences: ∫δ = 0 at t = 0 makes
f = f0 EXACTLY at start, so a cold start cannot false-pick an 81 element before
the loop has converged; and the PLL's own second-order response is the only
filter in the path, so no extra low-pass is added (do not add one, it would put
an unmodelled third pole in a measurement that already has a delay-based
element sitting on it).

At the defaults Kp = 30 s⁻¹, Ki = 900 s⁻² (the gains already validated for
`gfl`) the loop is ω_n = √Ki = 30 rad/s (4.8 Hz), ζ = Kp/(2√Ki) = 0.5, i.e. a
2% settling of about 4/(ζω_n) ≈ 0.27 s. That is the floor on any meaningful
Tdf; see the limitations.

**Lock detector.** `locked` = |δ| has stayed below δ_lock = 0.02 rad (about
1.1°) continuously for one cycle. While not locked, f is still reported (so the
aux trace is live during pull-in) but both 81 dwell timers are HELD AT ZERO.
This removes the cold-start question entirely instead of leaving it to the
user's choice of Tdf.

**Undervoltage supervision of the 81 elements (the classical 27-block-81).**
`Vblk` (V rms, 0 = off, typically 0.8 pu): while Vrms < Vblk the PLL integrator
freezes (θ coasts on the last ω_vco, `gfl`'s freeze) and `locked` is forced
false, so the 81 timers hold at zero. Frequency measured on a collapsed bus is
meaningless: the guard exists so that nothing measured there can reach an
element. The 27 element is NOT supervised by Vblk (that would defeat its
purpose); see the limitations for the de-energized-start footgun that follows
from it.

Amended on implementation (July 2026): this derivation originally justified
Vblk by claiming a bolted fault would otherwise read as a frequency excursion
and trip generation. Measurement says otherwise, and the reason is the
integrator readout above. With the PLL settled, a held 3-phase fault moves the
reported frequency by at most about 0.1 Hz (bolted: 59.966 to 60.050 Hz
unsupervised, 59.997 to 60.050 Hz supervised), nowhere near a realistic 81
pickup. The integrator-state readout already rejects the transient that the
VCO output would have shown, so Vblk is defense in depth rather than the only
thing preventing a false trip. What it does do, and what the validation
actually asserts, is HOLD THE 81 DWELL TIMERS for as long as the bus is down:
an element already picked up before the fault stops accumulating at the fault
and never resumes while the bus stays collapsed. That is the property worth
having and the one that is tested.

**Definite-time elements with pickup/dropout hysteresis.** Four independent
elements, each disabled by a zero threshold (the `Iinst` precedent):
```
59  over V :  pick up Vrms ≥ Vov ,  drop out Vrms < Vov·(1 − hysV)
27  under V:  pick up Vrms ≤ Vuv ,  drop out Vrms > Vuv·(1 + hysV)
81O over f :  pick up f    ≥ Fov ,  drop out f    < Fov − hysF
81U under f:  pick up f    ≤ Fuv ,  drop out f    > Fuv + hysF
```
hysV is a FRACTION of pickup (default 2%), hysF is ABSOLUTE in Hz (default
0.05 Hz). They cannot share one number: 2% of 60 Hz is 1.2 Hz, far wider than
the ~1 Hz total range an 81 pickup lives in, so a fractional band would swallow
the element.

Each element owns its OWN dwell timer:
```
picked up and not blocked -> dwell_i += h
dropped out, or blocked   -> dwell_i = 0
trip when any dwell_i ≥ Td_i        (Tdv for 59/27, Tdf for 81O/81U)
```
Four timers, not one shared timer: one element dropping out must not reset
another's accumulation. The reset is deliberately asymmetric, and that
asymmetry IS the hysteresis: the timer keeps running everywhere between the
dropout value and the pickup value, so measurement ripple on a quantity parked
right at the threshold cannot repeatedly reset the timer and prevent a trip
that should occur. Since the trip latches, the hysteresis has no effect
whatsoever on the trip itself, only on the timer, which is the whole reason it
exists in a latched element.

**Latch and trip action.** On trip, latch `tripped = true` (never cleared for
the run) and arm the target breaker exactly as `relay` does:
```
brkEls.forEach(e => { if (e.to < 0 || e.to > t*1000) e.to = t*1000 })
```
The guard keeps an already-scheduled earlier open from being pushed out. Each
pole then clears at its own next current zero through the solver's existing
switch-event machinery. `gtrip` NEVER touches `tc`, `opened` or `armed`: that
is the precise inversion of `vsw`, which clears those latches on purpose to
permit reclose. A latching protective relay requires a manual reset, and the
run has none, so a re-energized bus never un-trips it. Measurement (Vrms boxcar
and PLL) keeps running after the trip, only the decision logic stops (`relay`'s
`if (this.tripped) return;` placed after the measurement update), so the aux
frequency trace stays meaningful through the post-trip swing, which is exactly
what a cascade study wants to see.

**Placement matters.** Put `gtrip` on the NETWORK side of the generator's
breaker to keep watching system frequency after the machine is gone; on the
machine side it de-energizes at the trip and its PLL freezes on Vblk.

**Seeding (§5 item 32).** A sensor holds no history the network can disagree
with, so `gtrip` seeds in the INDEPENDENT loop (outside SEED_REQUIRED and
SEED_SOURCES), and a `gtrip` problem can never veto the all-or-nothing pass.
Measurement state is seeded, control state stays cold, the standing `vsw`/
`relay` split:
- Vrms boxcar: `vsw`'s `seed` verbatim (slot j from `c.inst(c.term(b,0,pl[k]),
  −(N−j)·c.dt)`), window left full.
- PLL: ang = arg of the phase-A node phasor `c.term(b,0,0)`; fill bufR/bufI over
  t = −(N−j)·dt with θ_T = ang + ω·t (`gfl`'s seed, node voltage instead of
  vbr), then θ = ang + ω·c.t0, ∫δ = 0, ω_vco = ω0. The boxcar in the lock frame
  is (+|V|, 0), so δ = 0 on the first step.
- lockCnt = N (the PLL genuinely starts locked; lock is measurement-validity
  state, not control state).
- COLD: all four dwell timers, `tripped`, and `cause` (stays null until a trip).

**Params** (`DEFS.gtrip`, label 'Gen Trip', one terminal):
```
brkId 0        breaker block #
Vov   0        59 pickup (V rms, 0=off)     Vuv 0   27 pickup (V rms, 0=off)
Tdv   100      V delay (ms)                 hysV 2  V dropout band (%)
Fov   0        81O pickup (Hz, 0=off)       Fuv 0   81U pickup (Hz, 0=off)
Tdf   300      f delay (ms)                 hysF 0.05  f dropout band (Hz)
Vblk  0        81 V block (V rms, 0=off)
f0    60       f0 (Hz: RMS window and PLL)
KpPLL 30       PLL kp (1/s)                 KiPLL 900  PLL ki (1/s^2)
```
Tdf's default of 300 ms is set just past the PLL settling time so the default
configuration cannot measure its own loop.

**Wiring into the solver.** `makeGtrips(topo, dt, nph)` pushed from
`makeSpanning` next to `makeVsws`; `link(phEls)` collects the target breaker's
per-phase elements by block ID (`relay`'s three-line version); `cur: 0` so it
rides the existing zero-current aux path. Two up-front validations in
`simulate()`: extend the existing `badRelay` brkId check to cover `gtrip`, and
add a new one rejecting Fov > 0 or Fuv > 0 when the sensor's nEff is not 3
(3-phase AC only, the same posture as `gfm`'s 1-ph current-limiter refusal).
Aux signal: `gtrip: { quantity: 'f', unit: 'f Hz', get: e => e.f }`. A `gtrip`
with every threshold at 0 is therefore also the project's bus-frequency METER,
which nothing else provides at a node. `ui.js`: `meas` palette entry, one-line
summary, `gtrip: ['Vov','Vuv','Vblk']` in the vconv-scaled param list, hint
text, science panel.

**Trip cause (2026-07-29).** The element that asserts the trip (`'59'`,
`'27'`, `'81O'` or `'81U'`) is recorded as `this.cause` at the same instant
`this.tripped` is set, same convention as `zrel`'s `oosTripped`. It is a
final-state fact about the run, not a time series, so it does not ride the
aux channel; `solver.js`'s `curMeta` carries it (filled in once after the
main loop, since `curMeta` itself is built before the loop starts) and
`api/core.js`'s `_listSignals` surfaces it as `cause` on the block's signal
entry, `null` for every other kind and for a `gtrip` that never trips. This
closes a real gap: with more than one element enabled on a relay, nothing in
the run said which one fired, and an offline reconstruction driven only by
bus V/f series got the answer wrong on the one case with independent ground
truth (`studies/Spain_Blackout`) because it cannot see the PLL lock detector
that gates the frequency elements. The relay itself always knows; it now
says so.

**Validation** (smoke_test.js):
1. Frequency accuracy: a 61 Hz source, all thresholds 0, aux f settles to
   61.000 ± 0.01 after the settling time (the `gfl` PLL test shape).
2. 59 definite time: source stepped to 1.15 pu at t1 with Vov = 1.10 pu,
   Tdv = 100 ms; trip inside [t1 + Tdv, t1 + Tdv + one cycle + one current-zero
   half-period], branch current zero thereafter.
3. 81U definite time: an island driven to a known steady off-nominal frequency,
   trip no earlier than the crossing + Tdf.
4. Latch: restore nominal voltage after (2), the breaker stays open to the end
   of the run (the property `vsw` deliberately lacks).
5. Hysteresis: a dip that goes below pickup but stays above dropout still trips
   at the nominal time; a dip past dropout resets the timer and there is no
   trip in the run.
6. Undervoltage supervision: a bolted fault that collapses the bus produces NO
   81 trip with Vblk set, and does trip with Vblk = 0. This is the guard the
   PLL's fault transient makes necessary.
7. Two-plant cascade (item 34's headline). Two `syncgen`s A and B with governor
   droop Kgov and damping D sharing a load P_L. A trips; B then carries P_L and
   its droop settles it at
   ```
   f_ss = f0 − (P_L − Pm0_B)/(Kgov_B + D_B)
   ```
   Set Fuv strictly between f0 and f_ss. The swing is second order, so the
   crossing instant is not closed-form; assert instead (a) B trips, (b) the
   trip is no earlier than t_A + Tdf, and (c) the SAME case with A's trip
   removed never trips B. (c) is the actual claim: the second trip is
   solver-driven, not scripted. An overvoltage variant of the same test (drop
   a load and let line charging raise V at the remaining plant until its 59
   picks up) exercises the other family.
8. Cause reporting: a droop-driven 81U trip reports `cause === '81U'`, a
   bolted-fault undervoltage trip reports `cause === '27'`, and a relay with
   every threshold at 0 (never trips) reports `cause === null`.

**Known limitations** (§7):
- 81 elements are 3-phase AC only, validated up front. On a lateral, in 1-ph
  mode, or on DC only the 59/27 elements exist.
- Two delays (Tdv shared by 59/27, Tdf shared by 81O/81U), not four
  independent ones; a real relay has four.
- Definite time only: no inverse-time frequency curve, no ROCOF/81R element,
  no directional or sequence supervision. 81R is deliberately out of scope for
  item 34.
- The 81 measurement chain is a one-cycle boxcar plus a second-order PLL, so
  its effective response is about 0.3 s at the default gains. A Tdf well below
  that measures the loop, not the grid.
- The PLL locks to the positive-sequence fundamental, so a heavily unbalanced
  fault puts a 2ω component in δ. Vblk supervision is the intended guard.
- The 27 element reads a de-energized bus as a deep undervoltage: on a cold
  start either set Tdv longer than the energization transient or leave 27 off
  and drive the study from 59/81.
- One target breaker per gtrip, and the standing conflict caveat: do not
  combine a `gtrip` link with `brk` nOps > 1 or a `vsw` on the same breaker.
- No reset within a run, by design. On a DC node the trip arms a breaker that
  never finds a current zero (the standing DC breaker caveat).

### Ideal transformer + leakage (grounded two-port)
Model: ideal transformer, ratio a = N1/N2 = V1/V2, with leakage R,L in series
on the primary side. Both windings share the ground reference (grounded-common
two-port — fine for radial PoC circuits; isolated secondaries need MNA).

Derivation. Let vb ≡ v1 − a·v2 be the voltage across the leakage branch
(primary node v1, ideal winding voltage a·v2 behind it). The leakage is a
standard series-RL companion on vb: i1 = G·vb + Ih with G = 1/(R + 2L/dt),
same history recursion as the line. Ideal-transformer current transfer:
current injected INTO node 2 is a·i1 (power check: v1·i1 − a·i1·v2 = i1·vb =
leakage dissipation; the ideal part is lossless).

Nodal form: currents drawn from nodes [I1, I2] = Y·[v1, v2] − [−Ih, a·Ih]·(−1),
   Y = G · [ 1   −a ]
           [ −a  a² ]
Y is symmetric ⇒ same LU machinery works. Generalized stamp: element with
ratio a adds +g at (n1,n1), +a²g at (n2,n2), −a·g at (n1,n2) and (n2,n1).
Every ordinary element is the a = 1 case, so the solver stamp and the
branch-voltage computation (vb = v(n1) − a·v(n2)) generalize with `a || 1`.
History injection each step: I[n1] −= Ih, I[n2] += a·Ih.
Reported current: primary i1 (secondary current = a·i1).

Params: V1, V2 (rated winding voltages), R (Ω), L (mH), primary-referred
leakage.

**Nameplate voltage entry (July 2026).** The winding ratio is not entered
directly: users think in nameplate voltages, so each transformer block takes
rated per-winding voltages and derives `a` internally (`xfmrA` in blocks.js).
For the per-phase/1-ph `xfmr` the terminal voltage IS the winding voltage, so
a = V1/V2. For `xfmr3`/`xfmr3w` the nameplate is line-line, and the winding
(phase) voltage on a wye side is LL/√3 while on a delta side it equals LL:
with k = √3 for a wye side and k = 1 for a delta side,
   a = N1/N2 = (V1/k1)/(V2/k2) = (V1/V2)·(k2/k1).
V1/V2(/V3) are fixed LL nameplate values and are deliberately NOT scaled by
the circuit's vconv toggle (a nameplate is not a per-phase source quantity).
The legacy `a`/`a2`/`a3` params remain a load-time fallback inside `xfmrA` so
older saved files still solve (see DECISIONS.md 2026-07-20).

**Saturable core (July 2026, opt-in `Lm`/`lknee`/`Lsat` params).** Exactly
the future-work plan above, now implemented: a piecewise-linear
magnetizing inductor shunted at the PRIMARY terminal (grounded two-port
convention). Flux is the integral of the terminal voltage
(λ += h·(v + v_prev)/2, trapezoidal), and the two-slope map
```
|λ| ≤ λk:  i_m = λ/Lm
|λ| > λk:  i_m = sign(λ)·λk/Lm + (λ − sign(λ)·λk)/Lsat
```
gives the magnetizing current. Companion per segment: G_m = dt/(2·L_seg)
(identical under CDA's backward-Euler half-steps, so the LU is reused),
history Ih = i_m + G_m·v (trapezoidal) or i_m (BE). Segment crossings go
through the same generic `segCheck` hook as the arrester, now also scanned
for SPANNING elements: with `Lm > 0` the transformer must become a
spanning element (`makeSatXfmrs`, per-phase loop) because the generic
stamper cannot add an independent shunt at one terminal (the same
constraint that made the π line spanning). `Lm = 0` (default) keeps the
original per-phase element untouched. Note the physical consequence of a
lossless magnetizing branch: energization flux offset
λ(t) = λpk·(1 − cos ωt) decays only through the EXTERNAL resistance path
(τ ≈ Lm/R_source), which IS the classical inrush mechanism — the smoke
test runs several τ before checking the steady saturated peak against the
two-slope prediction. `solvePowerFlow()` includes the linear jωLm shunt.

**Validated** (smoke_test.js): linear regime magnetizing RMS = V/(ωLm)
(knee above operating flux); saturated steady peak
i = λk/Lm + (λpk − λk)/Lsat with λpk = √2·V_measured/ω; legacy Lm = 0
invariance via the untouched original xfmr assertions.

### Vector-group transformer (`xfmr3`, July 2026 derivation)
Motivation: `xfmr` is three independent grounded two-ports; real three-phase
transformers have winding CONNECTIONS (Yy, Dy, Yd with a clock-number phase
shift and neutral grounding choices), and the connection is most of the
zero-sequence physics: delta windings circulate zero-sequence current so it
never reaches the line, ungrounded wyes block it entirely. That behavior is
what SLG-fault and ferroresonance-adjacent studies need.

**Structure.** Three single-phase units, each the EXISTING xfmr companion
verbatim (ideal a:1 + primary-referred leakage RL, g = 1/(R + 2L/dt), port
Y2 = g·[[1, −a], [−a, a²]], history pair [Ih, −a·Ih], per-unit state
vb_w/i_w): `a` stays the WINDING ratio a = N1/N2 (line-line ratio then
carries a √3 factor per connection, stated in the UI subtitle and §7).
Winding ports map onto phase nodes by incidence rows:
```
Y winding k:  u_k = v_k − v_n     (v_n = 0 if solidly grounded; else internal)
D winding k:  u_k = v_k − v_(k+σ) (σ = ±1, the pairing direction)
```
With positive sequence v_k = V·e^(−j·2πk/3), a delta winding sees
√3·V·e^(+j·σ·30°), so σ IS the clock number: primary D σ=+1 → Dy11,
σ=−1 → Dy1; secondary D σ=+1 → Yd1, σ=−1 → Yd11. Supported `conn` values:
Yy0, Dy1, Dy11, Yd1, Yd11.

**Assembly + Kron reduction.** Extended unknowns: 6 phase entries (3 per
side) plus one INTERNAL neutral per wye side that is not solidly grounded
(Rn > 0 grounds it through 1/Rn; Rn = −1 leaves it ungrounded, admittance
0 — still well-posed, the three winding conductances hold it). Assemble
Y_ext = Σk Cᵀ·Y2·C (+ neutral grounding diagonals), then eliminate the
neutral rows once at build:
```
Y_red = Y_pp − Y_pn·Y_nn⁻¹·Y_np          (stamped once, symmetric)
inject: J_red = J_p − Y_pn·Y_nn⁻¹·J_n     (J_ext = −Cᵀ·[Ih, −a·Ih] per unit)
update: v_n = Y_nn⁻¹·(J_n − Y_np·v_p), then u = C·[v_p; v_n],
        vb_w = u1 − a·u2, i_w = g·vb_w + Ih   (per unit, CDA be-form as usual)
```
Zero-sequence circulation (delta) and blocking (ungrounded wye) fall out of
the incidence structure; nothing is special-cased. Yy0 with both neutrals
solid reduces EXACTLY to three independent `xfmr` blocks (regression anchor).

**Power flow.** Positive-sequence complex-ratio stamp in `buildYbus()`:
with c = √3·e^(j·σ·30°) for a delta side and 1 for wye, y = 1/(R + jωL):
Y11 += y·|c1|², Y22 += y·a²·|c2|², Y12 += −y·a·c1*·c2, Y21 += −y·a·c1·c2*
(Hermitian off-diagonals: the clock shift survives into the power flow, so
machine init downstream of a Dy sees the 30° shift).

**Linear magnetizing shunt (`Lm`, July 2026).** An opt-in linear
magnetizing branch across the PRIMARY winding (Lm in mH, 0 = off, default
0), carrying the PSS/E MAG2 susceptance the importer used to drop. It is
the linear segment of the `xfmr` saturable shunt verbatim: companion
G_m = dt/(2·Lm) stamped onto the primary port incidence (so delta/wye and
the Kron neutrals place it correctly), a magnetizing history current
I_hM = i_m + G_m·v_m injected at the primary port, and flux λ integrated
from the primary port voltage (i_m = λ/Lm). The shunt is LOSSLESS, so a
cold energization carries the physical inrush DC flux offset that only the
source/leakage resistance slowly decays; the settled AC magnetizing
current is V_winding/(ωLm). In the power flow Y11 += −j/(ωLm) at the
primary. No saturation knee (the RAW carries none); MAG1 core-loss
conductance is dropped. `xfmr3w` carries the same shunt on its primary
(side 0, always wye).

**Plotted signals.** Per-phase PRIMARY WINDING current and leakage-branch
voltage (so P = v·i reads the leakage dissipation, same as `xfmr`); line
current on a delta side is the difference of two winding currents and is
not separately exposed; no through-power (`thru` false, like pfc/dcdc).

**Validated** (smoke_test.js): Dy11 secondary magnitude √3·V1/a and +30°
phase lead measured by phasor correlation; SLG-fault zero-sequence
blocking (source line currents sum to ~0 with a delta primary); ungrounded
wye kills the SLG fault current vs the grounded case; PF |V| ratio through
a Dy11; open-secondary AC magnetizing current = V_LN/(ωLm) for `xfmr3` and
`xfmr3w` (DC inrush offset removed).

**Known limitations** (§7): linear magnetizing only (no saturation knee,
though the lossless Lm does produce the inrush DC offset), no
off-nominal tap, no Dd or zigzag connections, winding-ratio (not line-line)
`a` semantics, and a side with no external ground reference anywhere
(e.g. delta, or ungrounded wye feeding ungrounded loads) has floating
zero-sequence potential — the solver reports the singular matrix and the
user grounds something, same rule as everywhere else.

### VSC-HVDC point-to-point (`hvdc`, July 2026 derivation)
Motivation: embedded HVDC links move scheduled power between two AC
systems that need not be synchronous; at concept level the essential
physics is the DC-link energy balance between two converter buses. Scope
is deliberately generic (screening boundary in the business log): no MMC
internals, classical two-level VSC AVM.

**Model.** One block, two 3-ph AC terminals (each a shunt injection with
implicit ground return, svc convention). The DC link is an INTERNAL state,
not a network node:
```
side A (link regulator): P_A = clamp(kp·(VdcRef − Vdc) + ∫ki·err, ±Prate)
side B (dispatcher):     P_B follows Pset through a first-order lag Tp
link:                    dVdc/dt = (η·P_A − P_B)/(Cdc·Vdc)   (init VdcRef)
```
Positive Pset sends power A→B; negative reverses everything (the PI
naturally pulls P_A negative). Each side is a wt4-style QSS phasor current
injection: Î = (P_inj − jQ)·V̂/(3|V̂|²) with side A's P_inj = −P_A and side
B's P_inj = +P_B, per-side fixed Q dispatch, shared current limit Imax,
UVLO, one-cycle MA extraction, and the 1 ms LPF on the injected phasor
components (the wt4 Nyquist-ringing finding applies verbatim). Aux
signal: Vdc. FLOW_REVERSED so side A's plotted P is positive-absorbing.

**Validated** (smoke_test.js): scheduled transfer arrives at grid B and
is drawn from grid A with the efficiency deficit (energy balance across
the block), the link holds VdcRef, and a negative schedule reverses the
flow.

**Known limitations** (§7): lossless apart from the single lumped η, no
DC-side cable model (the link is one lumped energy store), no
MMC/converter detail, no frequency-support controls, not in
solvePowerFlow().

### Type 4 wind turbine (`wt4`, July 2026 derivation)
Motivation: full-converter (Type 4) wind is the dominant new-build
generation; at the bus it is a current-injecting converter whose available
power follows the wind. Scope is deliberately GENERIC (IP screening note in
the business log): classical cubic power curve + rating cap + current
limit; no vendor LVRT/synthetic-inertia/pitch schemes.

**Model.** The induction motor's proven QSS interface, run as a source:
extract the terminal-voltage phasor (sin/cos correlators + one-cycle
moving average), compute the injection phasor algebraically from the
commanded complex power, inject clean balanced sinusoids (G = 0 Norton):
```
P_cmd = min(Prated, Prated·(vw/vrated)³),  vw steps to vw2 at tgust
Î = (P_cmd − j·Q0)·V̂/(3·|V̂|²)      then |Î| clamped to Imax (converter
                                     current limit, scale both parts)
UVLO: Vrms < vmin ⇒ zero injection (also the natural soft start while
the measurement window first fills)
```
Injection is generator-convention (I[a1] += i), so `wt4` joins
FLOW_REVERSED like src/gfm/syncgen. Aux signal: commanded P (kW). 3-ph
only. Q0 is a fixed reactive dispatch (unity default).

**Validated** (smoke_test.js): delivered P equals the cubic curve below
rating and the cap above it; a gust step moves P between the two
predictions; delivered Q matches Q0.

**Known limitations** (§7): no wind-speed time series (single gust step),
no inertia/pitch/turbine dynamics (P follows wind instantly through the
one-cycle window), no LVRT profile beyond UVLO + current limit, not in
solvePowerFlow().

### Transmission-grade GFL solar inverter (`gfl`, July 2026 derivation)
Motivation: every active source model OpenEMT had was unstable on a weak bus
(the Spain_Blackout study, `studies/Spain_Blackout/DIAGNOSTICS.md`). The `gfm`
GFL mode diverges at transmission scale for two reasons: its small signal-
filter Lf (0.5 to 3 mH) plus transmission line charging C (~1 to 2 uF)
resonates in the kHz range, above the solver Nyquist; and its kW-scale droop
gains flip the inverter voltage on MW/Mvar swings. `wt4` is a current source
with no series L (so no Lf-C resonance) but a free-running clock, so it cannot
follow a network not already at f0. This block is the transmission-grade GFL
current-source primitive: the `wt4` QSS phasor current injection with an
explicit SRF-PLL, per-plant-rated (per-unit) current limit and voltage floor,
and a transformer-leakage output reactance reflected into the current-limiting
algebra (IP screening in the business log: SRF-PLL Chung 2000, classical
phasor injection, voltage-reduction current limiting). 3-ph only.

**Model.** A Norton current source at the grid bus (term 0/1 = AC, generator
convention / FLOW_REVERSED like `wt4`): NO series filter branch is stamped, so
there is no Lf-C resonance at all (this is the cure, not a parameter tweak).
The one-cycle terminal-voltage phasor Vhat = Vrf + j*Vif is the `wt4` sin/cos
correlator + moving average, projected onto the PLL's OWN rotating frame:
```
Vrf = (√2/3)·Σ_p vbr_p·sin(θ+φ_p) ,  Vif = (√2/3)·Σ_p vbr_p·cos(θ+φ_p)
```
where vbr = v(term0) − v(term1) (so under the standard term0-grounded wiring
vbr = −v(bus), and the PLL locks to arg(vbr), π off the bus angle).

**SRF-PLL** (replaces `wt4`'s free-running θ += ω0·dt): the angle of Vhat in
the PLL frame IS the branch-minus-PLL error, so
```
δ = atan2(Vif, Vrf)               (rad; the normalised angle, voltage-independent)
ω = ω0 + KpPLL·δ + KiPLL·∫δ ,   θ̇ = ω
```
Anti-windup: integrate only inside the pull-in range (|δ| < π/2) and clamp the
frequency excursion to ±30% of ω0, so a fault transient (which the one-cycle
boxcar lags by up to a cycle, producing a spurious large δ) cannot wind the
integrator to a runaway frequency. The PLL FREEZES (holds θ and ∫δ) when
|Vhat| < Vfloor, so it re-locks when V returns rather than running away on a
collapsed bus. This is what lets it follow a network at f ≠ f0 (validated: a
61 Hz grid, f0 = 60 plant -> fpll settles to 61.000 Hz).

**Current command** (`wt4` algebra, P/Q scheduled setpoints, kW/kvar -> W/var):
```
Îre = (P·Vrf + Q·Vif)/(3·|V̂|²) ,  Îim = (P·Vif − Q·Vrf)/(3·|V̂|²)
```
**Voltage floor** (the dual of the constant-power-load phantom-voltage trap):
a 1-ms LPF on a floor factor ff ramps the injection to zero when |V̂| <
Vfloor·Vph and back to 1 above it, curing the I = P/V runaway on a depressed
bus without a step that excites Nyquist ringing. **Current limit**: |Î|
clamped to Imax·Irated (scale both components; Imax pu, Irated = Sbase/(3·Vph)),
holding the current at 1.1 to 1.2x rating through a fault. **Converter-voltage
ceiling** (optional, Emax > 0): the internal EMF behind the transformer
leakage E_int = V̂ + Î·jXt must stay within Emax·Vph; if it exceeds, Î is backed
off proportionally. This is where Xt (the transformer leakage, pu on Sbase/
Vrated) actively matters; with Emax = 0 (default) the limit/floor alone govern.
A 1-ms LPF on (Irf, Iif) (the `wt4` Nyquist-ringing cure) precedes injection at
the PLL angle: i_ph = √2·(Irf·sin(θ+φ_p) + Iif·cos(θ+φ_p)). Aux signal: PLL
frequency fpll = ω/(2π) Hz.

**Per-plant rating.** Sbase (kVA, 3-ph), Vrated (V, per the circuit's vconv),
Imax/Vfloor/Emax in per-unit; the current limit is the transformer's rated
current (1.1 to 1.2x), so the same defaults hold from 4 kV to 400 kV. Xt is
sized as a transformer leakage (default 0.1 pu), not a small signal-filter L:
the SPEC's "output reactance sized as a transformer leakage rather than a
small signal-filter L" is honored by reflecting Xt into the algebra rather
than stamping a real series branch, since a series L behind an ideal current
source is physically redundant (the current source dominates the grid current)
and would only re-introduce a passive L-C mode.

**Power-flow participation.** Registered as a PV/PQ/slack gen bus (like `gfm`/
`syncgen`) with P = P0, V = Vset (or Q = Q0), and reactive limits Qmax/Qmin, so
multi-bus cases converge with the distributed reactive support the PF needs
(the Spain_Blackout PF diverged without GFLs providing it). pfInit seeds the
PLL to the bus angle and the commanded current to the dispatched P/Q.

**Passive-history seeding (§5 item 32).** `gfl` IS in buildYbus (as a gen bus),
so the PF solved the network WITH its P injection and the surrounding branches
are seeded for that current (unlike `wt4`, which is absent and must stay cold).
The seed pre-fills the voltage boxcar, sets θ = arg(vbr) + ω·t0 (the PLL lock
point, wiring-agnostic), and seeds (Irf, Iif) from the dispatched P/Q against
the seeded boxcar (the SAME formula `update` uses, so no one-step sign-flip
transient). It seeds in the independent loop (not SEED_REQUIRED/SEED_SOURCES),
so a `gfl` issue never vetoes the all-or-nothing pass.

**Validated** (smoke_test.js): fixed-P/Q setpoint tracking at unity (0.4%), at
leading (P 0.8%, Q 1.8%), and at lagging (P 1.6%, Q 0.9%) PF against the
setpoint; current limit held at exactly 1.2x through a 0.63 pu depressing fault
(ratio 1.00) with full recovery; voltage floor ramps injection to ~0 A under a
held bolted fault (0.05 pu) with no I = P/V runaway; stable on a weak bus
(SCR ~3) tracking its setpoint (0.4%, fpll = 60.000); and the PLL following a
61 Hz grid (fpll = 61.000, the feature `wt4`'s free-running clock lacks).

**Known limitations** (§7): the current limit is an outer ~10 ms loop (the
one-cycle measurement + 1 ms LPF), not sub-cycle hardware current control, so
the first cycles of a fault still pass the unlimited transient; no vendor
LVRT or synthetic-inertia scheme (generic textbook AVM only); 3-ph only; the
PLL locks to the BRANCH-voltage angle (π off the bus angle under the standard
term0-grounded wiring, which the seed handles wiring-agnostically).

### Three-winding transformer (`xfmr3w`, July 2026 derivation)
Motivation: transmission substations are full of three-winding units, and
the delta tertiary's zero-sequence sink is the classic reason they exist;
autotransformer-with-tertiary studies need this shape.

**Per-phase 3-port star.** Windings referred to the primary (a1 = 1,
a2 = N1/N2, a3 = N1/N3), each with its own leakage companion
gw = 1/(Rw + 2Lw/dt). All three referred branches meet at an internal star
node vs which is eliminated ANALYTICALLY (Σ branch currents = 0):
```
G = g1+g2+g3,  vs = (Σw gw·aw·uw + Σw Ihw)/G
port current:  iw = aw·[gw·(aw·uw − vs) + Ihw]
⇒ Y3[w][j] = aw·aj·(δwj·gw − gw·gj/G)          (3×3, per phase)
   history:  hw = aw·(Ihw − gw·ΣIh/G)
```
Winding branch states (vb_w = aw·uw − vs, i′w) keep the standard series-RL
recursion, CDA be-form as usual.

**Connections.** The xfmr3 incidence/Kron machinery generalized to three
sides: extended vector = 9 phase entries + one internal neutral per
non-solidly-grounded wye side (up to 3; Y_nn⁻¹ via the coupled-line inv3
for the 3-neutral case). Same clock convention as xfmr3 (a non-primary D
winding with σ=+1 is the 1 o'clock, σ=−1 the 11). Supported `conn`:
Yy0y0, Yy0d1, Yy0d11, Yd1d1 (primary wye only in this pass).

**Power flow** (July 2026, second pass). The SAME analytic star-point
elimination, written in phasors: with A_k = a_k·c_k (c from the xfmr3
complex-ratio rule, √3·e^(j·σ·30°) for a delta side and 1 for wye; the
primary is always wye so A_1 = 1) and g_k = 1/(R_k + jωL_k) the
primary-referred arm admittances,
```
G = g1+g2+g3,   Y[k][j] = conj(A_k)·A_j·(δ_kj·g_k − g_k·g_j/G)
```
a Hermitian 3×3 stamp in `buildYbus()`, so a delta winding's clock shift
reaches machine init downstream exactly as it does through an `xfmr3`.
Opening one arm (g3 → 0) collapses this EXACTLY to the two-winding xfmr3
stamp above, which is the derivation's regression anchor. A star arm with
NEGATIVE reactance is normal (the T is a mathematical equivalent, not three
physical branches) and the stamp handles it; only an exact 0 + j0 arm is
floored, since 1/0 would put Infinity in the matrix. An unwired winding
keeps its own floating node and settles at the star potential, which is the
correct open-winding answer.

**Validated** (smoke_test.js): Yy0d1 per-winding ratios and shifts
(|V2| = V1/a2 at 0°, |V3| = V1/(a3·√3) at −30°); the delta-tertiary
zero-sequence sink shown the crisp way: with an UNGROUNDED primary a
secondary SLG fault has no zero-sequence path except tertiary delta
circulation, so the fault current with a `d1` tertiary is >50x the
`y0`-ungrounded-tertiary case. The power-flow stamp is checked against the
same T rebuilt from primitives whose PF stamps were already validated (a
series `rlc` for the primary arm out to a virtual star bus, then one
`xfmr3` per remaining arm): every bus agrees to ~1e−10 for a wye and for a
delta tertiary, the latter also carrying the 30° shift.

**Known limitations** (§7): primary-wye connections only, no Dd/zigzag,
winding-ratio `a` semantics (as xfmr3), no saturation on the 3-winding
unit.

### Coupled 3-phase RL branch (line with mutuals)
Vector branch relation: v = R·i + L·di/dt with 3×3 symmetric matrices
R = [[Rs,Rm,Rm],[Rm,Rs,Rm],[Rm,Rm,Rs]], L likewise (Ls, Lm). Trapezoidal:
  (R + 2L/dt)·i_n = v_n + v_{n−1} − (R − 2L/dt)·i_{n−1}
Companion: Geq = (R + 2L/dt)⁻¹ (full 3×3, computed once by adjugate inverse),
K2 = R − 2L/dt, history Ih = Geq·(v_{n−1} − K2·i_{n−1}) (vector),
i_n = Geq·v_n + Ih. State: previous v, i vectors (one coupled element spans
all three phases — NOT three per-phase elements).
Stamp: for phase pair (p,q), Geq[p][q] enters like a scalar conductance between
(node1 in phase p, node1 in phase q) and (node2,p / node2,q): + at (n1p,n1q)
and (n2p,n2q), − at (n1p,n2q) and (n2p,n1q).
Sanity identity used for validation: for balanced currents (Σi = 0) the branch
reduces to the positive-sequence impedance Z1 = (Rs − Rm) + jω(Ls − Lm).

### PI (nominal π) equivalent line (`line` with `C`, July 2026 derivation)
Motivation: `line` was series R+L only; real (medium-length) transmission
lines have charging capacitance, conventionally modeled as the nominal π
equivalent — series R+L in the middle, shunt C/2 to ground at each end. Opt-
in extension of the existing `line` block (new `C` param, µF total, default
0 = today's exact behavior — zero risk to any saved circuit), the same
pattern `Rm`/`Lm` mutual coupling already used.

**Architecture constraint found while deriving this**: `stampPhase()` (the
generic per-phase stamper `line`/`rlc`/`cap`/etc. all share, solver.js)
only supports a single reciprocal 2-terminal conductance
(`G[i][i]+=g; G[j][j]+=g; G[i][j]-=g; G[j][i]-=g;`) — no way to add
INDEPENDENT shunt terms at n1 and n2 separately. Only spanning elements
(their own `stamp(M)`, in `sEls`) can do that, so a PI line must become a
spanning element (`makePiLines`) when `C>0`, mirroring `makeCoupledLines`'s
structure but looped over `ph=0..nph-1` (not hardcoded to 3) so it works in
1-ph mode too, unlike coupled lines — there's no mutual coupling to model
here, just independent per-phase R+L+shunt-C. `C=0` is excluded from this
path entirely, falling through to the original generic-G branch unchanged.
On a DC node the loop collapses to ONE copy (`nEff`, the relay's pattern):
every phase index clamps onto the node's single unknown, so the naive
ph-loop stamped the same line nph times in parallel — R/3, C×3 at nph=3,
silently wrong by 3x (found and fixed in the July 2026 solver review; the
same `nEff` collapse applies to `tline` and `fdline`, whose node types now
also PROPAGATE AC/DC classification like other 2-terminal passives).

Per phase:
```
Series (identical to the plain line, unchanged): Gs = 1/(R+2L/dt),
  k2 = R−2L/dt, kL = 2L/dt
Shunt, each end (half the total C — standard π split, same trapezoidal
  companion `cap` already uses, applied to a single terminal with implicit
  ground return, same convention as pfc/batt/cpl): Gc = 2·(C/2)/dt = C/dt
stamp: M[n1][n1] += Gs+Gc,  M[n2][n2] += Gs+Gc,  M[n1][n2] -= Gs,  M[n2][n1] -= Gs
inject: I[n1] -= IhSeries+IhShunt1,  I[n2] += IhSeries−IhShunt2
```
Verified against an INDEPENDENT complex nodal analysis (a hand-derived 2×2
linear system for series impedance + shunt admittance at each end + load —
NOT the same formula the implementation uses, see `smoke_test.js`): 0.00%
error. Exposes the SERIES current/voltage as its plotted signal (`.i`/`.v`,
`kind:'pline'`), matching exactly what plain `line` already plots — shunt
charging currents aren't separately exposed (§7).

**Coupled + shunt-C together is not supported** — real risk to the already-
solid, well-tested `makeCoupledLines` code for a combination judged less
commonly needed this pass. `simulate()` returns a clear validation error if
a block has both `Rm`/`Lm` and `C` nonzero.

### PQ load (`pq`, July 2026 derivation)
Motivation: a pure-R `rlc` is constant-impedance (R only); `pq` is the standard
power-flow load model — constant real+reactive power regardless of bus
voltage, distinct from a fixed R/L/C sized once (which only draws the
target P/Q AT one particular voltage).

**Architecture constraint found while deriving this**: the solver only
re-factors its matrix on breaker switching events (main loop, solver.js:
`fact = buildLU(...)` once, refactored only when `switched`) — so anything
whose behavior needs to change CONTINUOUSLY during a run must be a G=0
Norton current source, never a conductance stamp (a continuously-varying
admittance would need re-stamping every step — an O(D³) refactor every
50 µs, computationally infeasible). This ruled out an "adaptive L/C
companion" design and confirmed the current-source approach below,
consistent with every other dynamic block this session (batt/pfc/dcdc/pv
are all G=0).

Both P and Q as Norton current injections, avoiding CPL's `P/v(t)`
zero-crossing blowup (only safe for CPL because it's DC — v never crosses
zero) by normalizing against a filtered RMS², not the instantaneous voltage:
```
Vrms² tracking (LPF, same Tf pattern as GFM's Pf/Qf):
  v2f += h·(v(t)² − v2f)/Tf
Real component (in phase with v):
  i_real(t) = (P·1000/v2f) · v(t)
Reactive component needs a CAUSAL 90°-shifted reference. A quarter-PERIOD-
  delayed voltage sample IS that reference (derivation below) — robust
  through the sharp transients this tool specializes in (a switching event
  or fault), unlike a numerical-derivative quadrature generator which would
  spike right when a fault/breaker event matters most:
  i_reactive(t) = (Q·1000/v2f) · v(t−T/4)
i(t) = [Pph·v(t) + Qph·v(t−T/4)] / v2f ,  Pph = P·1000/nphB, Qph = Q·1000/nphB
```
`P`/`Q` are the load's THREE-PHASE TOTAL (see "Power convention" above), so the
companion on each phase carries `1/nphB` of it — `nphB` being 3 on an ordinary
3-phase node and 1 in 1-ph mode or on a lateral, where the total is the one
phase. Until July 2026 the undivided `P·1000` went into every phase, which made
a 3-phase `pq` draw 3x its label and disagree with `solvePowerFlow()`.

Derivation of the T/4 term: for v(t)=Vpk·sin(ωt), v(t−T/4)=−Vpk·cos(ωt); a
pure inductor Q=V²/(ωL) draws i_L(t)=−(Vpk/ωL)·cos(ωt) = v(t−T/4)/(ωL);
solving ωL=Vrms²/Q gives i_L(t) = (Q/Vrms²)·v(t−T/4) exactly — and the same
formula naturally flips to capacitive/leading when Q<0, no separate L/C
branching needed. `v(t−T/4)` comes from a small fixed-size circular buffer
(`N = round(T/(4·dt))`, e.g. 83 samples at 60 Hz/50 µs), sized from the
block's own `f` param (not a global frequency read — simpler, self-
contained, matches `src`'s own `f`). UVLO (`vmin`) sheds the load below a
floor voltage, checked against the tracked RMS (not instantaneous v, which
crosses zero every half-cycle and would falsely trip a naive check).
Injection is the ordinary passive convention (`I[n1]-=i, I[n2]+=i`, positive
= absorbing, same as `rlc`/`cpl` — no new P-sign case in ui.js). Built
inside `makeElements` (single shared current between two terminals, exactly
like `rlc`/`cpl`) — no spanning-element machinery needed, unlike the PI
line, since pq has only one current, not two independently-derived ones.

Verified in the solver (not just the derivation): a stiff-source-fed PQ
load (P=8 kW, Q=3 kvar) settles to within ~1-2% of both setpoints once the
Tf-based tracking has had several time constants to converge (smoke_test.js
runs 400 ms and measures the last 50 ms — the default 120 ms UI duration
isn't quite enough settling time, same reasoning as the GFL mode test);
flipping Q negative correctly delivers leading/capacitive power with no
formula change. The residual few-percent error comes from the first-order
LPF Vrms² tracker not perfectly rejecting the 2×line-frequency ripple
inherent in v(t)² (v²  has a genuine DC term plus a 120 Hz-at-60 Hz-system
component) — a real, documented limitation (§7), not a bug: tested with
several `Tf` values and the error doesn't monotonically shrink with a
slower filter, consistent with this being an inherent characteristic of the
technique rather than an under-filtered transient.

### ZIP composite load (`zip`, July 2026 derivation)
Motivation: real aggregated feeders are neither constant-impedance (a pure-R
`rlc`) nor constant-power (`pq`); the standard composite representation (IEEE
load-modeling task force) is the ZIP polynomial, a weighted mix of constant
impedance (Z), constant current (I), and constant power (P) parts:
```
P(V) = P0·(az·(V/V0)² + ai·(V/V0) + ap)
Q(V) = Q0·(bz·(V/V0)² + bi·(V/V0) + bp)
```
Coefficients are normalized by their own sum at element build (each triple
sums to 1; an all-zero triple falls back to pure Z), so users can enter any
relative weights. `P0`/`Q0` are the THREE-PHASE TOTAL at `V0` and are divided
by `nphB` per phase, exactly as `pq` (see "Power convention" above).

**Implementation: pq's machinery with per-part normalization.** Same
Tf-filtered Vrms² tracker (`v2f`), same quarter-period-delayed voltage
sample as the causal reactive reference (see the pq derivation above for
why), and pq's Norton injection with the passive sign convention for the I
and P parts. The Z part is STAMPED instead (2026-07-27, see below). The
only new physics is the denominator of each part:
```
i(t) = [az·P0·v(t) + bz·Q0·v(t−T/4)]·1000/V0²            constant Z (fixed)
     + [ai·P0·v(t) + bi·Q0·v(t−T/4)]·1000/(V0·√v2f)      constant I (∝ 1/Vrms)
     + [ap·P0·v(t) + bp·Q0·v(t−T/4)]·1000/v2f            constant P (pq formula)
```
Check: in-phase RMS current of each part times Vrms gives exactly
P0·az·(V/V0)², P0·ai·(V/V0), P0·ap. The Z part uses the FIXED nominal
denominator (that is what constant impedance means), so it is benign at any
voltage; only the I and P parts carry pq's 1/Vrms behavior.

**The Z part is stamped, not injected (2026-07-27).** Being benign at any
voltage is a statement about the physics, and until this date the numerics did
not follow. `az·P0/V0²` is a plain conductance G and `bz·Q0/V0²` a plain
susceptance B, both constant and both known at element build. Applying a fixed
admittance as a Norton injection off the PREVIOUS step's voltage is an explicit
feedback loop of gain G/G_node, and it diverges wherever the load's conductance
passes the node's own companion conductance. So G is stamped directly and B
through the standard trapezoidal companion at the block's own `f` (absorbing =
an inductor L = 1/(ωB), injecting = a capacitor C = |B|/ω, same companions
`rlcp` uses), giving the Z part history state it did not previously carry. Both
are SIGNED, so a negative `P0`/`Q0` (an embedded generator entered as a load)
stamps a negative conductance or a capacitive susceptance, which is what the
polynomial says; the matrix requires an entry to be constant, not passive.
UVLO is unaffected and becomes automatic: a stamped admittance is always in the
matrix, which is exactly the "Z part rides through" rule below. The reported
element current is the injected I/P parts PLUS the stamped Z branch, so the
drawn-power validation still measures the whole load.

How it was found (Spain study, DECISIONS.md 2026-07-27): a run blew up after
the same ~4 STEPS at every timestep from 20 µs to 1 ms. A physical instability
has a time constant in seconds and blows up at the same ABSOLUTE time whatever
the timestep; divergence in a fixed number of STEPS is only ever a numerical
feedback path. `az` = 0.1 was enough to trigger it, and a small 2-bus network
does NOT reproduce it (its loop gain is under 1), so the regression fixture in
smoke_test.js deliberately builds a node fed through a large series inductance
and nothing else, where G_z/G_node ≈ 140.

**UVLO** (`vmin`, on the tracked RMS like pq): sheds the constant-I and
constant-P parts only. The Z part persists through the undervoltage: the
physical picture is electronics/drives tripping while resistive load
(heating) stays connected, and numerically it is exactly the part that is
safe at depressed voltage. Distinct from pq, which sheds everything;
documented in §7.

**Power flow**: a `zip` bus enters `solvePowerFlow()` as a PQ injection at
its NOMINAL P0/Q0, exactly like `pq` blocks (the solve lands near V0, where
the polynomial evaluates to ~1; the voltage dependence itself is not
iterated). Approximation documented in §7.

**Validated** (smoke_test.js): drawn P and Q at V = V0 and at V ≈ 0.8·V0
against the polynomial evaluated by hand, both within the pq block's
established few-percent measurement class (same v2f-ripple limitation).

### Aggregation current-scaling coupler (`scale`, July 2026 derivation)
Motivation: a study at hundreds-of-MW scale (e.g. a hyperscale datacenter)
is really N identical parallel copies of a much smaller reference unit
(one 1-2 MW UPS/rectifier/inverter chain, one motor, one PDU). Simulating
N literal copies wastes cycles for no new information (they are, by
construction, undiversified and identical), and hand-resizing every
passive/control gain for a target MW figure is exactly the error class the
batch-2 datacenter study review turned up. PNNL-38817 (Data Center EMT
Model Library) and ERCOT's GRIT AI-datacenter PSCAD manual both solve this
with a "current scaling" element: build ONE reference unit at a
well-conditioned native scale, and multiply its port current by a scalar
N before it reaches the shared network, while the reference unit itself
still senses the real (unscaled) network voltage.

**The coupling is asymmetric by design.** Term 0 (network/facility side)
and term 1 (reference-unit side) sit at (nearly) the same voltage, but they
carry DIFFERENT current: term 0 carries N times term 1's current. Two
nodes tied by an ordinary conductor cannot do this (KCL forces equal
current through a shared branch); it requires two electrically distinct
nodes coupled by a matched dependent-source pair: a unity-gain
voltage-controlled voltage source (term 1 tracks term 0) and a gain-N
current-controlled current source (term 0 receives N× term 1's draw).
This deliberately does NOT conserve power at the coupling point (there is
no real conductor between term 0 and term 1), because it stands in for the
N−1 replicas that are never separately simulated.

**Implementation: a same-step asymmetric admittance stamp** (corrected
2026-07-18; see DECISIONS.md for why the original one-step-lag design below
was replaced):
```
Y = g·[[N, −N], [−1, 1]]     g = 1/Rf

term 0 (network) diagonal += N·g     term 1 (reference-unit) diagonal += g
cross terms: M[term0][term1] −= N·g     M[term1][term0] −= g   (NOT equal,
  unlike every other 2-terminal stamp in this file — this is the algebraic
  expression of the asymmetric coupling above)

stamp(M): the four entries above, solved simultaneously with the rest of
          the network in the same linear system (no history term: purely
          algebraic, so inject() is a no-op)
update(V): i[ph]    = g·(V(term0) − V(term1))   current actually flowing
                                                 into the reference sub-circuit
           iNet[ph] = N · i[ph]                 aggregate current the
                                                 network side sees
           _vb[ph]  = V(term1)
```
Both terminals are AC-only, 3-phase (SPEC §1 node classification), and the
element is a spanning block (own `stamp`/`inject`/`update` against the
global V/I arrays, like `gfm`/`svc`/`xfmr3`) since it needs simultaneous,
independently-addressed access to two otherwise-unrelated nodes, not a
single branch voltage.

A first version stamped this as a one-step-lag Thevenin tap (term 1's
reference voltage = last step's V(term 0), the same pattern pq/cpl/pfc/batt/
svc use) plus a lagged Norton injection of N·i back at term 0. That forms a
discrete feedback loop whose gain scales with N: unconditionally unstable
for the large N (tens of thousands+) this block exists to support. The
same-step stamp above has no delay, so there is no feedback loop to go
unstable — verified stable at N up to 1,000,000 (see DECISIONS.md,
2026-07-17 and 2026-07-18 entries).

Params: N (replica count / scale factor, real-valued, not required to be
an integer since the target MW figure rarely divides evenly by a whole
unit count), Rf (Ω, the term-1 coupling/sensing resistance; plays the same
role as `src`'s Rs, keeping the reference sub-circuit's own local bus
well-conditioned rather than floating).

**Reported signals**: `i`/`_vb` (curInfo/vbInfo) expose the REFERENCE-UNIT
side (term 1) current/voltage, matching every other per-phase `.i[ph]`
element; the network-side AGGREGATE current (N×) is exposed separately via
the AUX channel (`Inet`, phase A only, same convention as `batt`'s SOC and
`gfm`'s Idc) since it has no branch voltage of its own to pair with. Not a
simple series branch (its two terminals carry different currents), so
`tvInfo` is null: no through-power identity, consistent with `pfc`/`svc`/
`hvdc`.

**Validated** (smoke_test.js): a purely resistive circuit (`src` to `scale`
to `rlc`) has a closed-form series-divider solution independent of this
implementation: I_local = Vsrc/(R + Rf + N·Rs), V1 = I_local·R,
I_net = N·I_local. Checked at N = 100 (integer replica count) and N = 2.5
(non-integer), both within 0.21%. That residual is NOT a lag artifact (the
same-step stamp has no lag) — it is the RMS-window measurement error
smoke_test.js's own hand-rolled `rms()` helper produces whenever its
sample window isn't an integer number of cycles; a bare `src`-to-`rlc`
resistor circuit measured the same way shows the identical ~0.21%. The
solver's own internal RMS (used for plots/exports) already uses
integer-cycle windows per the known trap in CLAUDE.md.

### Single-phase lateral tap (`tap`, July 2026 derivation)
Motivation: every AC node before this carried the FULL three-phase set, so
there was no way to express a single-phase lateral hanging off one phase of a
3-phase feeder: the pole-top distribution transformer, the 1-ph residential
service, the single-phase spur that makes a distribution feeder genuinely
unbalanced. Attempting it wired directly either left the other two phases of
the lateral node unstamped (a singular matrix, correctly reported as a
floating node) or, through the old `min(p, cnt-1)` index clamp, silently
shorted all three phases together. The existing unbalance story stopped at
"you need a coupled line, otherwise the phases are independent" (§7).

**There is no new companion model here.** The tap is a topology feature: the
lateral's elements are the SAME trapezoidal companions as always, simply
instantiated once instead of three times. What is new is per-node PHASE
IDENTITY in `buildNodes`.

**Per-node phase identity.** Alongside the existing AC/DC `type[n]`, each node
carries `phs[n]`: `-1` = carries the full 3-phase set (every node that existed
before this feature), `0/1/2` = a single-phase lateral living on phase A/B/C
alone. Node unknown counts and global indexing follow:
```
cnt[n] = (nph === 3 && type[n] === 'ac' && phs[n] < 0) ? 3 : 1
gIdx(b, ti, p):
  cnt[n] === 3                      -> off[n] + p           (unchanged)
  ac node with phs[n] >= 0          -> p === phs[n] ? off[n] : -1
  otherwise (DC, or 1-ph mode)      -> off[n]               (legacy clamp)
```
Returning `-1` on the other two phases is the crux: `-1` already means "not
connected" everywhere in the stamping code, so a lateral element built on the
wrong phase stamps nothing at all, with no special-casing anywhere else.

**Classification is a second fixpoint, structurally identical to the AC/DC
one.** A `tap` seeds BOTH of its sides (term 0 = `-1`, term 1 = its phase);
seeding term 0 explicitly is what stops a lateral's phase index from
propagating BACKWARDS through the feeder and silently collapsing the whole
3-phase network to one phase. The phase then propagates through the passive
set plus the single-phase `xfmr` (its secondary must inherit the lateral, or
the pole-top transformer case energizes only one of three secondary phases -
found by testing, not by inspection). Blocks whose model genuinely spans the
phase set (gfm, syncgen, im, xfmr3, xfmr3w, svc, scale, wt4, hvdc, and a
mutually coupled line) seed `-1`, so wiring one onto a lateral surfaces as a
bridging conflict rather than misbehaving downstream. `tap` is deliberately
absent from the propagation set, which is precisely what makes it the ONE
block allowed to join a 3-phase node to a single-phase one; any other block
bridging the two is an error naming the offender.

**The tap element itself** is an ordinary 2-terminal conductance
`G = 1/Rc`, built only on its own phase by the generic rule above. It is NOT a
union-find merge: merging would give the lateral node all three unknowns back
and lose the phase restriction entirely. `Rc` defaults to 0.1 mOhm - small but
explicitly nonzero, for the same reason `brk` uses a finite `GON`: a literal
0 Ohm branch between two live nodes NaNs the LU (§2, parallel RLC).

**A lateral is phase-to-neutral**, returning through the circuit ground, so
its voltage parameters are PHASE quantities even when the circuit is entered
line-to-line. `vPh()` is therefore called with a block-local phase count
(1 on a lateral) rather than the run's `nph`, so a 277 V lateral load reads
277 V whether the circuit convention is PH or LL. Verified: identical lateral
current in both conventions with the source held at the same physical voltage.

**Validated** (smoke_test.js) against an INDEPENDENT complex-phasor solve of
the same circuit (a lateral off a feeder that also carries a balanced 3-phase
load): lateral current and voltage match to 0.00% on each of A, B, and C; the
two untapped phases stay symmetric to ~1e-15 (machine precision); only the
tapped phase sags, which is the unbalance the feature exists to produce. Plus
a phase-identity check (the lateral voltage correlates >0.99 with its OWN
source phase and <0.7 with the other two), a 2400/240 V pole-top transformer
whose secondary correctly inherits the lateral, and the four error paths.

#### Single-phase PFC AC side (July 2026 derivation)
The 3-phase PFC draws its DC power as an instantaneous conductance emulation:
`v2 = (2/3)·Σ v_p²` is the squared peak amplitude (exact and ripple-free for a
balanced set), and `i_p = kdraw·v_p` with `kdraw = 2P/(3·v2)` gives
`Σ v_p·i_p = P`. Neither half of that survives a single phase: one phase has no
ripple-free `v²` identity, and the conductance emulation itself goes unstable.

**Why the obvious port fails.** `i = kdraw·v(t−dt)` is a resistor emulated by a
ONE-STEP-LAGGED current source, which is stable only while `kdraw` is below the
node's own companion conductance. Two things push a single-phase draw over that
line. A single phase carries THREE TIMES the `kdraw` of a 3-phase draw at equal
power (`P/V²` vs `P/3V²`), and the node conductance that has to dominate it,
`1/(R + 2L/dt)` for a feeding RL branch, SHRINKS as `dt` is refined, so the
model would become less stable the finer the time step. Measured: a 4 kW
lateral behind 0.5 mH ran away to ±53 kV (`kdraw` = 0.0521 S against a node
conductance of 0.0495 S). These are ordinary distribution numbers, not a
pathological corner.

**Fix: phasor injection, exactly as `im` already does** (same failure, same
remedy, see that section's "two attempts failed" note). Extract the terminal
voltage PHASOR over one cycle against a self-clocked frame `θ` advancing at
`2π·f`, solve the current phasor algebraically, and inject a reconstructed
sinusoid that does NOT depend on this step's node voltage, which removes the
algebraic feedback path entirely:
```
θ  += 2π·f·h                                  (self-clocked, CDA-aware h)
V_re = √2·<v·sin θ>,  V_im = √2·<v·cos θ>     (one-cycle moving average)
I = (P/|V|²)·V        i.e. I_re = P·V_re/|V|², I_im = P·V_im/|V|²
inject: i(t) = √2·(I_re·sin θ + I_im·cos θ)   drawn from the AC node
```
`I` is parallel to `V`, so the draw is unity power factor by construction, and
`<v·i> = (P/|V|²)·(V_re² + V_im²) = P` exactly. Phasor convention matches `im`:
a signal `√2·(U_re·sin θ + U_im·cos θ)` has phasor `U_re + j·U_im`. UV shutdown
reuses the common test on `v2 = 2·|V|²` (squared peak), so both paths share one
threshold. The frame clock keeps advancing while shut down, so a recovered grid
does not restart from a stale angle.

**The 3-phase path is untouched** (still instantaneous, no lag, no window), so
every pre-existing circuit is bit-identical. Cost on the 1-ph side is a
one-cycle lag on the drawn-power envelope, the same accepted trade `pq`/`zip`/
`im` already make.

**Validated** (smoke_test.js): on a lateral on each of A, B, and C, AC-terminal
power equals DC-terminal power to 0.00%, power factor is 1.0000, the terminal
sits just below the source (absorbing, and bounded, which is what catches the
old instability), and the result is phase-independent.

#### Single-phase GFM inverter (July 2026 derivation)
The GFM's electrical branch (EMF-behind-RL companion) and both control laws
(droop, GFL PI) are per-phase already; only the P/Q MEASUREMENT assumed the
balanced three-phase set. On one phase the instantaneous identities
`p = Σv_p·i_p` and `q = [(v_b−v_c)i_a + ...]/√3` do not exist: single-phase
`v·i` pulsates at 2f about P with amplitude equal to P itself, and there is no
instantaneous orthogonal voltage for Q. So single-phase P and Q are MEASURED,
everything downstream is unchanged.

**Measurement: one-cycle projection onto the inverter's own reference.** Project
the terminal voltage and branch current onto `sin(θ+φ)` and `cos(θ+φ)` and
average over one cycle (integer cycles, the standing rule):
```
V_re = √2·⟨v·sin(θ+φ)⟩,  V_im = √2·⟨v·cos(θ+φ)⟩     (φ = SHIFT[global phase])
I_re, I_im likewise
P = V_re·I_re + V_im·I_im,   Q = V_im·I_re − V_re·I_im   (S = V·conj I)
```
The sign convention reproduces the 3-phase one (Q > 0 lagging/inductive), so
the droop and GFL laws that consume P/Q are byte-identical to the 3-phase path.

**Why θ and not a fixed quarter-cycle delay (the `pq` technique).** A GFM
deliberately runs OFF-NOMINAL (that is the whole point of droop). A fixed
`T/4`-sample delay is 90° only at exactly `f0`; at a 47 Hz droop operating
point it is 84.5°, and that 5.5° error injects `P·sin(5.5°) ≈ 9%` of PHANTOM
reactive power into a purely resistive load, which then feeds the Q droop and
shifts E. Projecting onto the inverter's own θ (which tracks the ACTUAL droop
frequency) cannot mistune: verified, Q into a resistive island is −0.0 var.
`im` uses the same self-referenced projection for the same reason.

**Limiter.** The `Iacmax` EMF-backoff limiter's phasor sums come free from the
same projection (`A = E²` analytically, `B = E·V_re`, `C = |V|²`), and the
one-cycle window already filters 2f, so the 5 ms LPF the 3-phase path adds is
dropped on the 1-ph path (a second lag would only slow the loop). BUT the
limiter is REFUSED on any single-phase inverter (a clear error): a bolted
fault makes the inverter slip against the grid, and one-cycle-stale P/Q drives
the angle away instead of holding it. Measured grid-tied, µ floored at MUMIN
and held 91% ABOVE Iacmax while the EMF drifted ~104° out of phase. Islanded
it happens to work (40.1 A against a 40 A limit), but "only when islanded" is
not a precondition a user can track, so it errors rather than silently fail in
the one scenario the limiter exists for.

**Everything else carries over unchanged**: the DC port (lossless AVM,
current-limited Norton injection following the measured AC power) works on a
lateral exactly as in 3-phase: validated, a battery-held 400 V bus supplies
5.054 kW to match 5.054 kW delivered AC. GFL setpoint tracking delivers its
P0/Q0 (5 kW / 1 kvar single-phase). A lateral GFM is cold-started aligned to
its own global phase via `SHIFT[phase]`, so it does not swing in from 0 (and
there is no PF init to fall back on, since `solvePowerFlow()` refuses tap circuits).

**Runs in 3 places now**: full 3-phase (unchanged), 1-ph MODE (a whole-circuit
scalar run, previously refused outright), and on a single-phase lateral inside
a 3-phase run. All three share one code path, sized from `topo.phList`.

**Validated** (smoke_test.js): a phase-A lateral reproduces the same circuit in
1-ph mode to machine epsilon while delivering its GFL setpoint; islanded droop
into R lands on the analytical f/P fixed point with ~0 phantom Q; reactive
power into an R-L island matches an independent phasor solve to ~1%; the DC
port balances; and the current limiter is refused single-phase (still allowed
3-phase).

### Passive-history initialization from the power flow (§5 item 32, July 2026 derivation)

Machines already start at the power-flow operating point (§5 item 10): the PF
back-computes each generator's internal EMF and `makeSyncGens`/`makeConverters`
start from it. Every PASSIVE element still starts at rest — `line` with
`i = v = 0`, `cap` with `v = i = 0`, `rlc` with `vC = 0`. That mismatch is the
inrush: at t = 0 the machines are already at full EMF while the network is
completely de-energized, so the first cycles are an energization transient with
the usual L/R and LC content. On a single bus it merely decays; on a multi-bus
network with long lines it is a torque impulse on machines that have no margin,
and it is what knocks `syncgen` out of step on a weak bus.

This section derives the seed. Nothing about the discretization changes; only
the initial contents of the history registers.

**Reference conventions.** Three have to agree, and they already do:

1. *Time reference.* Every AC source in the EMT solve is SINE-referenced:
   `src` injects `√2·V·sin(2πf t + φ)` and `syncgen` injects
   `√2·E·sin(θ + SHIFT[ph])`. So a per-phase RMS phasor `V̄ = |V|∠α` maps to
   the instantaneous waveform
   ```
   v_ph(t) = √2·|V|·sin(ω t + α + SHIFT[ph]),   ω = 2π f0
   ```
   with `SHIFT = [0, −2π/3, +2π/3]`.
2. *Sequence reference.* `solvePowerFlow()` is positive-sequence
   (V_b = V_a·e^{−j2π/3}, V_c = V_a·e^{+j2π/3}), which is exactly `SHIFT`.
3. *Magnitude reference.* PF's internal `V[i]` is a PER-PHASE RMS phasor in
   VOLTS (this is why `pfInit.E` feeds `E·√2·sin(...)` directly), so `vconv`
   plays no part here — the √3 was already applied at the parameter boundary.

`f0` is picked by the same rule both solvers already use: the first
`src`/`gfm`/`syncgen` block's `f`/`f0`, else 60.

**The history registers hold t = −Δt, not t = 0.** This is the part that is
easy to get wrong and silently wrong if you do. Take the series RL companion
(§2 "Series RL branch"): with `k2 = R − 2L/Δt` and `G = 1/(R + 2L/Δt)`,

```
i_n = G·(v_n + v_{n−1} − k2·i_{n−1})
```

The stored `this.v`, `this.i` are the terms subscripted **n−1**. Step `k = 0`
evaluates at `t = 0`, so its history terms are the state at `t = −Δt`. Seeding
them with the t = 0 values instead injects a one-step-ahead error into the very
first solve — small, but it rings for exactly the same reason the cold start
does, and it defeats the purpose. So every seeded quantity is evaluated at

```
t₀ = −Δt
```

**Each element derives its own current from its own admittance.** The PF
solution gives node voltages. It would be possible to take branch flows from
the PF as well, but the seed must be consistent with the DISCRETIZED element,
not with the PF's stamp of it, and the two differ wherever a block's EMT model
and its Ybus stamp are not the same object (`rlc` with `C = −1`, a saturable
transformer on its linear segment, a breaker's state). So the rule is: take the
branch-voltage phasor from the PF node voltages, and compute the branch-current
phasor from the element's OWN parameters at ω. Any residual then appears as a
small mismatch rather than as a wrong history.

For a two-terminal block with terminals on nodes t0, t1 (a grounded terminal is
the phasor 0) and transformer ratio `a` (1 for everything except `xfmr`):

```
V̄b = V̄(t0) − a·V̄(t1)        (matches the solver's own vb = v(n1) − a·v(n2))
Īb = Ȳ_branch(ω) · V̄b
```

with the per-block admittance and the registers to fill:

| block  | Ȳ_branch(ω)                    | registers ← value at t₀ |
|--------|--------------------------------|-------------------------|
| `line` | 1/(R + jωL)                    | `v`←v_b, `i`←i_b |
| `xfmr` | 1/(R + jωL)                    | `v`←v_b, `i`←i_b (primary current) |
| `cap`  | jωC                            | `v`←v_b, `i`←i_b |
| `rlc`  | 1/(R + jωL + 1/(jωC))          | `v`←v_b, `i`←i_b, `vC`←u_C |
| `rlcp` | 1/R + 1/(jωL) + jωC            | `v`←v_b, `iL`←i_L, `iC`←i_C |

where `u_C = Ī_b/(jωC)` is the series capacitor voltage (same polarity as v_b)
and `i_L = V̄b/(jωL)`, `i_C = V̄b·jωC` are the parallel branch splits. Absent
components (the `−1` sentinels, §2) drop out of both the admittance and the
register list, exactly as they drop out of the companion.

That `rlc`'s `vC` carries the SAME time index as `v` and `i` is worth showing,
since the code writes it in `update()` after `i` and the reader can reasonably
guess it is a half-step off. Trapezoidal integration of `v = R·i + L·di/dt + u`
with `u_n = u_{n−1} + (Δt/2C)(i_n + i_{n−1})`:

```
(v_n + v_{n−1})/2 = R(i_n + i_{n−1})/2 + L(i_n − i_{n−1})/Δt + (u_n + u_{n−1})/2
                  = R(i_n + i_{n−1})/2 + L(i_n − i_{n−1})/Δt + u_{n−1} + (Δt/4C)(i_n + i_{n−1})
⇒ v_n + v_{n−1} = i_n·(R + 2L/Δt + Δt/2C) + i_{n−1}·(R − 2L/Δt + Δt/2C) + 2·u_{n−1}
⇒ i_n = G·(v_n + v_{n−1} − k·i_{n−1} − 2·u_{n−1}),   k = R − 2L/Δt + Δt/2C
```

which is `rlc`'s `ihf()` term for term, with `u_{n−1}` = the stored `vC`. So all
three registers are t = −Δt quantities and none is staggered.

**The source has to be initialized too, or the seed is inconsistent.** `src` is
a Thevenin source: the EMT block drives `√2·Vrms·sin(ωt)` BEHIND `Rs`, so its
terminal is not `Vrms∠0`. The power flow, meanwhile, pins its bus AT `Vset`
(= `Vrms`), and at a non-slack bus at a solved angle that is not 0 at all.
Seeding passive histories from a PF solution the sources do not actually
reproduce would replace the old inrush with a new, smaller one. `pfResult`
already back-computes `E' = V̄ + (Ra + jωL_int)·Ī` for every block in `gens`,
and `gens` INCLUDES `src` (with `Ra = Rs`, `L_int = 0`, so `E' = V̄ + Rs·Ī` is
exactly the Thevenin EMF). So the fix is to use what is already computed: when
`b.pfInit` is present, `src` drives `√2·pfInit.E·sin(ωt + pfInit.th + SHIFT)`
instead of `√2·Vrms·sin(ωt + SHIFT)`. This is the same treatment `syncgen` has
had since §5 item 10, applied to the one source block that was left out.
Cold-start runs (no `pfInit`) are untouched and bit-identical.

**Accuracy, and what is deliberately not corrected.** The seed uses
continuous-time phasors (jω), while the running solver is trapezoidal, whose
exact response to a sinusoid is the warped `s → j(2/Δt)·tan(ωΔt/2)`. The
relative error is `(ωΔt)²/12` per reactive element — at Δt = 50 µs and 50 Hz
that is 2·10⁻⁵, four orders below the transient being removed, and it decays
with the network's own damping instead of ringing. Correcting it would require
seeding against a discrete-frequency admittance that no longer matches the PF
the node voltages came from, trading a 20 ppm error for an inconsistency. Not
worth it; documented instead.

**All-or-nothing, and not out of caution.** A PARTIALLY seeded network is much
worse than a cold one. Two series branches sharing a node, one preloaded with
its steady-state history current and the other holding zero, cannot both be
satisfied at t = 0, and the node voltage spikes to whatever reconciles them.
Measured while this was built: a coupled-line case ran at 6% first-cycle
deviation with nothing seeded and 195% with the load seeded and the line not.
So the elements carrying trapezoidal history are checked BEFORE anything is
written, and one un-seedable element among them cancels the whole pass; the run
then starts exactly as cold as it did before the feature existed. The set is
`SEED_REQUIRED` in solver.js, plus `SEED_SOURCES` for the blocks that drive the
network and so must reproduce the power flow even though they carry no history.

Shunt CURRENT-SOURCE interfaces (`pq`, `zip`, `im`, `svc`, `wt4`, `hvdc`, the
DC-side converters) are deliberately outside that set. They inject a commanded
current rather than a history current, so starting at zero understates a load
for its first cycle instead of fighting a series partner: the error is bounded
by the source impedance rather than being a spike. Pre-filling their measurement
windows is the remaining half of §5 item 32.

An element may also decline through `seedVeto(c, ph)`, for a condition only it
can test. Today only `xfmrsat` uses it: a core whose STEADY-STATE flux is
already past the knee is not seedable at all, because `buildYbus` represents the
magnetizing branch by the linear `Lm`, so the power flow's bus voltages are not
the ones a saturated core would hold (2485% vs 41% first-cycle deviation if
seeded anyway). Vetoing cancels the pass and the circuit cold-starts.

**Non-two-terminal families.** Four elements keep history that is not a plain
(v, i) pair across two terminals, and each needs its seed built through its own
internal structure rather than from the block's terminals:
- `cline`: Ī = Z⁻¹V̄b with Z = sym3(R + jωLs, Rm + jωLm). A symmetric 3x3 with
  equal diagonals A and equal off-diagonals B has just two eigenvalues,
  Z0 = A + 2B on [1,1,1] and Z1 = A − B on the orthogonal plane, so
  Z⁻¹x = (x − x̄·1)/Z1 + (x̄·1)/Z0 with x̄ = mean(x). No complex matrix code is
  needed. The PF being positive-sequence makes x̄ = 0, leaving z1 = zs − zm,
  which is what `buildYbus` stamps for this block.
- `xfmr3`: the registers are WINDING quantities, so the seed goes through the
  same incidence rows `C1`/`C2` that `update()` uses — the vector group and
  clock shift live in those rows, and reading the two terminals directly drops
  both. Internal neutral phasors are ZERO: a neutral carries the sum of its
  three winding currents, which vanishes for a positive-sequence set, so no
  Kron solve is needed for them.
- `xfmr3w`: a star (T) equivalent whose star point is not a network node. Its
  phasor is the winding-admittance-weighted mean of the referred port voltages,
  V̄s = Σ(a_w·ū_w·Ȳ_w)/ΣȲ_w, which is the phasor form of the `vs = (Sgu+SIh)/Gs`
  the time loop computes. Each winding is then an ordinary branch across
  a_w·ū_w − V̄s.
- `xfmrsat`: the flux seed λ̄ = V̄1/(jω) is EXACT despite the nonlinearity, since
  flux is the integral of voltage and integration is linear; only the current is
  nonlinear, and the exact piecewise `iOf()` map supplies it. `seg` must be set
  from the seeded flux, because seeding runs before `buildLU` and the first
  factorization has to carry the right segment.

**Measurement-window pre-fill (shunt current-source interfaces).** `pq`, `zip`,
`im`, `svc`, `wt4`, `hvdc` inject a COMMANDED current derived from a filtered
measurement of their own terminal, so unlike the branches above they carry no
`(v, i)` history at all — but the filter/window state that produces that
commanded current still starts at zero, which mis-measures for its own settling
time even when the network around it is perfectly seeded. Because each is a
current SOURCE rather than a series branch, a wrong (even zero) measurement
cannot spike a shared node the way a partially-seeded series pair can — the
error is bounded by the element's own source impedance — so these seed
independently of the all-or-nothing pass and of each other (`seedHistories`
runs them in a second, ungated loop, keyed only on the element's own `ready()`
check).

The general rule for any ring buffer of size `NW` sampled every `Δt`: slot `j`
seeds to the value the PF phasor implies at `t = −(NW−j)·Δt` — i.e. exactly
what `NW` real update() calls starting from `t = 0` would have written into it,
so the first real call reads the same thing a long-running steady state would
have left there.

`pq`/`zip` are the first of these and do not fit that simple pattern directly:
their reactive reference is a quarter-period `vbuf` ring (the rule above
applies to it as-is, `NW` = the quarter-period sample count), but their real
power reference is `v2f`, a first-order low-pass on `v²(t)` — not a ring
buffer, and not continuous-time either: it is the DISCRETE recursion
`v2f[n+1] = (1−a)·v2f[n] + a·v²(t_{n+1})`, `a = Δt/Tf`, which needs its own
closed form. At the default `Tf` = 20 ms, `a = Δt/Tf` is only ~0.25% at
`Δt` = 50 µs, small enough to look like rounding error, but seeding the
CONTINUOUS-time RC steady state instead measurably missed: ~0.14% residual at
a stiff 0.05 Ω source impedance, well over the <0.05% bar every other family
in this section clears. So this is the exact DISCRETE steady state, not the
continuous approximation. With `v(t) = √2·Vrms·sin(ωt+φ)` (the branch-voltage
phasor, as elsewhere in this section), `v²(t) = Vrms² − Vrms²·cos(Ωt+θ)`,
`Ω = 2ω`, `θ = 2φ`: a DC term (unit gain in the recursion too) plus a tone at
`Ω` sampled every `Δt`, i.e. multiplied by `z = e^{jΩΔt}` each step. Matching
the `e^{jΩt}` coefficient of `v2f(t) = Vrms² + Re{Y·e^{jΩt}}` one step apart in
the recursion gives
```
Y = a·U₁·z / (z − (1−a)),   U₁ = −Vrms²·e^{jθ}
v2f_ss(t) = Vrms² + Re{Y·e^{jΩt}}
```
verified against a long-run numerical iteration of the actual recursion to
5·10⁻¹⁰ relative error (vs. ~0.25% for the continuous formula it replaced).
`icmd` itself then seeds from `v(t₀)` and `v(t₀ − NW·Δt)` (one buffer-length
further back than `vbuf[0]`, since `icmd` mirrors what the update() call ONE
STEP BEFORE `t₀` would have produced) through the same `v2f`/UVLO expression
`update()` uses, so `inject()` at `k = 0` sees exactly what a long-running
steady state would hand it — for a PRESCRIBED `v(t)`, this reproduces a
long-run discrete simulation to 7·10⁻⁹ relative error.

That still leaves a small residual in the full closed loop (`pq` behind a
source impedance `Rs`, `icmd` depending on `v`, `v = vs − icmd·Rs`): its TRUE
periodic steady state carries harmonics beyond the PF's fundamental phasor,
which this seed does not reconstruct. Measured varying `Rs` alone at fixed
`P`/`Q`: the residual scales LINEARLY with it (0.14% at 0.05 Ω down to 0.0001%
at 5·10⁻⁵ Ω) — exactly the "bounded by source impedance" behavior the design
above claims, not a defect in the fit. Documented rather than chased further,
same call as the trapezoidal-vs-continuous mismatch earlier in this section.

**Scope and fallbacks.** The cases that cancel the pass:
- DC nodes. `solvePowerFlow()` is AC positive-sequence and does not solve them,
  so a hybrid AC/DC circuit cold-starts until the DC side is covered.
- De-energized buses (`dead`), which are at 0 anyway — cold start IS the answer.
- Single-phase laterals (`tap`), which the PF refuses outright.
- Distributed-parameter lines (`tline`, `fdline`), whose histories are travel
  buffers spanning τ, not single registers — a separate derivation.
- A saturable core seeded past its knee (`seedVeto`, above).

**Blocks entirely absent from `buildYbus` (`svc`, `wt4`, `hvdc`): seed the
measurement, never the commanded current.** `pq`/`zip` are shunt current
sources too, but `solvePowerFlow()` DOES model their injection (SPEC §2
"Reference conventions" onward), so a REQUIRED branch next to one and the
shunt source's own commanded current are both solved from the SAME
self-consistent network. `svc`/`wt4`/`hvdc` are not in that Newton solve at
all — the PF treats their bus as if they inject NOTHING, which is exactly
what the REQUIRED branches around them are seeded to assume too. Seeding
`wt4`'s commanded current to its true dispatch anyway was tried and measured:
420% first-cycle deviation on a bus wt4 alone supplies (vs 18% cold), 35% even
behind a near-ideal source (vs 2%) — because the seeded current and the
`line` next to it (assuming zero) instantly disagree, the exact
partially-seeded-series-pair spike the all-or-nothing rule exists to prevent,
just occurring between a REQUIRED branch and an un-modeled shunt source
instead of two REQUIRED ones. Restricting the seed to the WINDOW alone
(`wt4`'s `bufR`/`bufI` terminal-voltage extraction and its free-running clock
`th`, leaving `Irf`/`Iif`/`icmd`/`Pcmd` cold same as `svc`'s `Iq`) fixes this
AS LONG AS the block's own contribution is a small perturbation on its bus —
measured: 0.25% seeded vs 6.1% unseeded at 1 kW behind a 0.5 Ω source and a
10 Ω load (a realistic small-DG-on-an-established-feeder case), but STILL
worse than cold at 100 kW on the same bus (dominant generation, not a
perturbation) — the same "bounded by source impedance" shape pq's residual
has, just with the roles of source and load reversed: here the surrounding
NETWORK has to be the stiff side. `svc` and `hvdc` follow the same rule for
the same reason (both absent from `buildYbus`, both structured as a window
feeding a control loop); `hvdc`'s two-sided window seeds the same way as
wt4's single one, doubled.

**`im` is the one buildYbus-absent block that ALSO carries electromechanical
state.** Its one-cycle voltage window (`bufR`/`bufI`) seeds by the wt4 boxcar
rule above, but the rotor EMF `Ed`/`Eq` and slip `s` are governed by the
third-order ODE `makeIMs` integrates, not a filter, so they need the
induction-motor steady-state torque balance. With the transient impedance
`Zp = Rs + jX'` and the rotor-EMF branch `j·dX/(1 + j·s·ω·T0')`,
```
Ī = V̄ / (Zp + j·dX/(1 + j·s·ω·T0')),   Ē' = j·dX·Ī/(1 + j·s·ω·T0'),
Pe(s) = 3·|Ī|²·Re(j·dX/(1 + j·s·ω·T0')),
```
and the balance `Pe(s) = PL0·(1−s)^kexp` fixes the operating slip; bisect for
the small stable (motoring) root, then seed `Ed`/`Eq` from `Ē'` and `nu`/`s`
from the slip. This is the EXACT steady state of the ODE the time loop
integrates (the equivalent-circuit bisection in `smoke_test.js` solves the same
balance and agrees to <2%, but this form is self-consistent with the ODE so the
seeded `Ed`/`Eq` do not drift on the first step). `icmd` stays cold all the
same: `im` is absent from `buildYbus` and the PF load bookkeeping, so the PF
bus models no motor load and the SEED_REQUIRED line feeding it (when present)
is seeded for that same zero current — seeding `icmd` to the motor's real draw
would recreate the partially-seeded-series-pair spike exactly as it did for
`wt4`. The seeded `Ed`/`Eq` and window bring the motor to its steady-state
current in a single `update()` step; the one-step zero-to-steady ramp is a load
step bounded by the source impedance, not a series-pair spike.

**Validation** (§5 item 32): a multi-bus case that currently slips or collapses
from the inrush starts at the PF operating point and holds; bus voltages stay
within a few percent of the PF solution across the first cycle with no inrush
spike; the cold-start inrush residual is gone against the zero-history baseline.

### Hybrid AC/DC solver structure (per-node phase counts)
Every electrical node is classified AC or DC:
- Seeds: src, xfmr terminals ⇒ AC; batt, cpl terminals ⇒ DC;
  pfc terminal 0 ⇒ AC, terminal 1 ⇒ DC; gfm terminals 0/1 ⇒ AC always, term 2
  ⇒ DC only if wired (auto-grounded otherwise, §2) — pfc and gfm are the two
  AC/DC bridges.
- Passive blocks (line, load, cap, brk, fault) are network-agnostic: node type
  propagates through them to a fixpoint. A node reachable as both AC and DC
  is a user error (join the sides only through a pfc or a gfm's DC port).
  Unclassified nodes default to AC (backward compatible).
In 3-ph mode an AC node carries 3 unknowns, a DC node 1; global indexing is
NODE-MAJOR: unknown(n, p) = off[n] + min(p, cnt[n]−1), D = Σ cnt[n].
Element instances hold GLOBAL indices (elements never see phase offsets):
- AC per-phase elements are instantiated once per phase with that phase's
  indices; DC elements once. Coupled lines / gfm / pfc are single spanning
  elements holding per-phase index arrays and their own stamp() method.
Sources shifted 0, −120°, +120°. Any switch event ⇒ refactorize the full LU.
Nodes also carry a PHASE IDENTITY (`phs[n]`, §2 "Single-phase lateral tap"):
-1 = the full 3-phase set (the default, and every node predating the feature),
0/1/2 = a single-phase lateral on A/B/C alone, which then has 1 unknown and
reads as index -1 ("not connected") on the other two phases. A `tap` block is
the only legal bridge between the two.
1-ph mode: every node has 1 unknown (legacy scalar mode; coupled lines
degenerate to self R,L; gfm unsupported; pfc's AC side is abstracted; a `tap`
is a plain connector).
FAULT blocks take a phase selector (0 = all/ABC, 1 = A, 2 = B, 3 = C) on AC
nodes (ignored on DC) → SLG and other unbalanced events.
Breakers on DC buses close fine but never see a current zero — opening a DC
breaker waits forever (physical: DC breaking is genuinely hard).

### Web Worker + streaming plots (long-window runs)
`simulate(nph, Tms, onChunk)` in solver.js is the ENTIRE numeric core (topology,
element construction, LU, time loop) and is 100% DOM-free — this is what makes
it safe to run inside a Web Worker. `runEMT()` stays as a synchronous, DOM-facing
wrapper (`onChunk = null`) used by the headless test harness and as the
no-Worker fallback; its observable behavior is byte-identical to the
pre-refactor solver (verified: all smoke-test checks unchanged after the split).
Browser UI path: `runEMTLive()` (ui.js) builds a Worker from a Blob containing
blocks.js + solver.js text + a small bootstrap (`build.py` embeds this as the
`WORKER_SRC` string constant — the SAME single-file, offline, double-click-to-run
distribution model is preserved; no separate .js file is ever written to disk).
`onChunk` is called once with a plain-data `meta` descriptor (probe ids,
element {id,type,kind} — never live element objects, which hold closures
postMessage cannot structured-clone) and then every ~50 decimated samples with
incremental `{progress, t, vp, ie}` slices; ui.js appends these and redraws the
existing canvas plots each time, so long runs animate progressively instead of
appearing all at once — and the main thread never blocks, so the page stays
interactive (Stop button available) regardless of how long `Duration (ms)`
is set. Duration, Time step, and Plot step are all UI fields now (PSCAD-style
separation of solution step from plot step) — see §3.1 below; Duration
defaults to 120 ms and Time step to 50 µs, matching the old hardcoded values,
so an unmodified page behaves identically to before this change.

- **Auto-layout** (`doHierarchicalLayout`): tidy-tree positioning for circuits that
  grow beyond manual arrangement. The Layout button opens a dialog with arrow icons
  (→ left-to-right, ↓ top-to-bottom). Algorithm: (1) BFS **spanning tree** from the
  grid-forming roots (src/gfm; unreached fragments each start their own tree) —
  parent/child direction comes from traversal order, which is always correct. Do NOT
  derive direction from wire `a`/`b` order: that's just whichever terminal the user
  clicked first, and a previous version that used it produced garbage trees (real
  bug, July 2026). (2) Order each node's children: larger subtrees first (main
  feeder hugs one edge), then probe/fault taps, grounds last (`leafBias`). (3) Tidy
  placement: depth sets the main-axis coordinate; each leaf takes the next free
  cross-axis slot; each parent centers on the mean of its children — guarantees no
  overlaps and reads as a pyramid branching away from the source (a source's ground
  lands right beside it at depth 1, matching SLD convention). Blocks are centered on
  their grid point via `getDims`. **Two-terminal "through" blocks (src, line, load,
  cap, xfmr, brk, gfm, pfc, batt, cpl) get rotated 90° in top-to-bottom layout**
  (July 2026 — the layout previously left them horizontal even though the flow
  ran vertically, reading badly and forcing an L-shaped wire elbow at every
  block instead of a straight run) — `b.rot = isLR ? 0 : 90`. Their lead line
  then runs with the vertical flow, and consecutive main-chain wires land as a
  single straight vertical segment (verified: brk→line in hybrid.json renders
  as one unbroken vertical `path`). Bus keeps its horizontal-bar convention;
  gnd/probe/fault are excluded because they're single-terminal and already
  point the right way in either direction (their symbol is inherently
  vertical — a ground/probe stub or a fault's lightning bolt — so rotating them
  would only turn the GLYPH sideways for no benefit). Because rotating swaps a
  block's on-screen footprint (width↔height), `mainStep`/`crossStep` no longer
  need separate LR/TB tuning — after rotation, TB's footprints are the exact
  transpose of LR's, so one pair of constants (190, 95) covers both directions.
  (4) `fitView()` then zooms/pans the camera to the layout's bounding box
  (aspect locked, never zooms in past the default view) — without it, a
  laid-out tree mostly lands outside the default 680×340 window.
  Layout writes `b.x`/`b.y` and, for through-blocks, `b.rot` — never
  wires/params — so it can't change the electrical circuit (rotation is
  cosmetic, per above). Users fine-tune by dragging/rotating afterward.
- **Bus-aware layout** (`busAwareLayout`, taken instead of the tidy-tree when a
  circuit has 3+ buses — see DECISIONS.md 2026-07-15): buses are the backbone.
  The circuit contracts to a bus graph (nodes = buses, edges = the components
  bridging two buses), laid out in BFS-layer columns from the highest-generation
  bus with barycentric within-column ordering; local branches hang off each
  bus's taps. Four rules were added Aug 2026 after a hand-fixed IEC 60909-4
  network was diffed against the algorithm's output (DECISIONS.md 2026-08-01).
  (a) A component on 3+ buses (three-winding transformer) is drawn as a
  connector between its two BEST-CONNECTED buses; every further bus becomes a
  **satellite** parked beside the component body, outside the column grid. Its
  bus must not be dropped from the bus graph, which is what the old
  `buses.slice(0, 2)` did: BFS then never reached the tertiary, the island
  fallback put it in column 0, and its winding wire crossed the whole figure.
  (b) A connector's symbols are turned to lie ALONG the axis between the two
  taps, so a connector joining two buses in the same column (a vertical run) no
  longer lies across its own wire. (c) Parallel connectors are spread
  perpendicular to that axis by the widest body measured across the same
  perpendicular — the 50-unit tap pitch alone is narrower than a transformer
  symbol is tall. (d) Vertical position relaxes toward the mean of each bus's
  neighbours in the adjacent columns (minimum row separation re-imposed in the
  barycentric order after each sweep) instead of top-aligning every column.
  Two repair passes finish: `declutterConnectors()` slides an overlapping body
  along its own wire first and only then perpendicular (capped at 30% of the
  span, so it cannot drift out from under its own run), then
  `declutterProbes()`. `orientBlocks()` (formerly `orientTwoTerminal`) flips any
  block with 2+ terminals 180° when that shortens its wired-terminal length;
  1-terminal blocks are excluded because a flip cannot shorten a single lead.

  - **RMS and power (P, Q)** are derived signals, computed lazily by each
    signal's `.get()` (cheap: ≤~1400 decimated points). Window = one nominal
    cycle (`cycleWindow()`: `round(1000/freqHz / dtOut)`, `freqHz` read from
    the first `src`/`gfm` block's `f`/`f0`, default 60, threaded through
    `meta`/the sync return value same as `Tms`). `rmsSeries()` is a sliding
    sum-of-squares window (causal; partial-window average during the first
    cycle — a known, accepted simplification, not a bug). `activePowerSeries()`
    = `movAvg(v·i)` over one cycle — exact for any periodic waveform, no phase
    trick needed. `reactivePowerSeries()` uses the standard quarter-cycle
    quadrature method: `Q = movAvg(v(t)·i(t+T/4))` (derivable from v=Vm sin(wt),
    i=Im sin(wt−φ): this averages to (Vm·Im/2)sin(φ) = Q).
    RMS needs only ONE signal (a probe voltage or a branch current); P/Q need
    a matched v/i pair, which only a BRANCH ELEMENT has (a bare probe has no
    associated current — especially now that Bus lets many things share one
    node with no single unambiguous "current at that point"). So RMS is
    offered on both probes (`rv:`) and branch currents (`ri:`); P/Q are
    branch-element-only (`p:`, `q:`), grouped with that branch's own current
    in the picker. Branch voltage is recorded in parallel with current
    (`bv`/`vbInfo` in solver.js, mirroring `ic`/`curInfo`): generic scalar
    per-phase elements get `e._vb` stamped generically in the main step loop
    (distinct from line/cap/xfmr's own internal `.v`, their trapezoidal
    history — same value, different purpose, so both can coexist); `cline`
    already stores its branch-voltage vector as `.v`; `gfm`/`pfc` set `_vb`
    themselves since they don't flow through the generic per-phase loop.
    RMS is AC-only (skipped for `dc` signals — redundant with the raw value).
    Q is AC-only (not offered for `dc` branches). P is offered for both AC
    and DC branches (always well-defined).
    **3-phase total, not per-phase (July 2026)**: unlike RMS current (which
    stays per-phase — imbalance is genuinely useful to see there), P/Q on a
    branch with `cs.np === 3` are reported as ONE aggregate 3-phase value —
    `sumSeries()` totals the three phases' already-computed
    `activePowerSeries`/`reactivePowerSeries` results (exact, since `movAvg`
    is linear: sum-of-averages = average-of-sum for a shared window) into a
    single `p:<id>:0`/`q:<id>:0` entry with `phase: null` (no A/B/C suffix —
    `phaseLabel()` returns `''` for `phase == null`, distinct from `'DC'`).
    A branch that genuinely only exists on one phase (e.g. a phase-selective
    fault, `cs.np === 1` even in 3-ph mode) still falls through to the
    original per-phase path and keeps its real phase label — the branch is
    on `cs.np`, not on 3-ph mode itself.
    **Absorbed vs. THROUGH power (July 2026)** — separated after a user
    correctly observed that a chain of series elements plotted wildly
    different "P" values when "the power through them should be the same":
    they were reading ABSORBED power (`vb·i`, vb = voltage ACROSS the
    element), which is what the element itself consumes/generates — a closed
    breaker reads ~0 and a line only its own I²R loss, by construction
    (Tellegen: absorbed P sums to ~0 across the circuit). The power actually
    FLOWING THROUGH a branch is a different quantity: `v_node·i` at a
    terminal, against ground. Both are now offered per branch:
    `p:`/`q:` ("W"/"VAR") stay absorbed; `pin:`/`pout:`/`qin:`/`qout:`
    ("W in"/"W out"/"VAR in"/"VAR out") are through power at terminal 0 and
    terminal 1 respectively. Implementation: terminal-0 node voltage is
    recorded per branch alongside `bv` (`tv`/`tvInfo` in solver.js, `_vt`
    stashed generically in the step loop for per-phase elements and inside
    update() for cline/pline/gfm/syncgen); terminal 1 needs NO extra
    recording since `vt − vb = a·v(n2)` — the transformer's turns scaling
    falls out automatically, so xfmr's "out" is its true secondary power
    (validated: 10:1 xfmr's out = downstream load's in exactly, minus
    nothing; its own copper loss appears only in absorbed P). Identity
    `in − out = absorbed` holds to machine precision (~1e-11, verified).
    A terminal at ground potential reads 0 through power (physically
    correct — no power flows through a node at 0 V): a source's grounded
    return terminal reads "in" = 0, its delivered power is its "out".
    Not offered for `pfc`/`dcdc` (`curMeta.thru` false, `tv` null) — they're
    power converters whose two sides carry different currents, so the series
    through-power identity doesn't apply to them.
    **Sign convention** (found via Tellegen energy-balance auditing, July
    2026 — see the `energy balance` smoke-test check; UNIFIED across every
    block type, no role-based exception, July 2026): P/Q are v·i using each
    branch's own already-established terminal/current reference. **Positive
    = power ABSORBED, negative = power DELIVERED — for every single block,
    with no exceptions.** Validated: sum of P over every branch in the demo
    circuit = 0 to floating-point precision, using this exact convention.
    The only correction applied is for `src`/`gfm`, whose AC pair injects
    its Norton/EMF current at terminal 0 with the stamp physically REVERSED
    relative to every passive branch (`I[n1]+=x; I[n2]-=x`, traced directly
    from `inject()` in blocks.js — this reversal is what caused the Tellegen
    imbalance that surfaced the bug originally), so their raw v·i is negated
    — not a style choice, the one flip physics actually requires for their
    v·i to mean the same thing as everyone else's. `batt`/`pv` have the
    ordinary passive terminal wiring (`I[n1]-=icmd; I[n2]+=icmd`, same
    stamp shape as `rlc`) — despite being generator-role blocks, their raw
    v·i needs NO flip and is already consistent with the rest of the
    circuit. An **earlier version of this convention also flipped
    batt/pv** so a discharging battery or a generating PV panel read
    positive ("generators read positive," a UX nicety) — removed after a
    user flagged that role-based exception as confusing to reconcile when
    reading mixed generator/load circuits side by side. Under the current,
    unified convention a discharging battery and a generating PV panel both
    read **negative** (delivering), same as any other source; a charging
    battery reads **positive** (absorbing), same as any other load. `pfc`'s
    DC side is architecturally a single-terminal current injection to
    ground (no real terminal-0/1 pair — see `makePFCs`), so its v·i is
    already consistent with no flip needed; `dcdc` uses the identical
    `I[out]+=icmdOut` convention on its own OUT port (`_vb=vOut`), so it
    needs no flip either. This same table (`FLOW_REVERSED = {src:1, gfm:1}`,
    ui.js) is shared verbatim by the power-flow arrows below — there is
    exactly one polarity table in the whole app, not two conventions that
    happen to agree. xfmr's P/Q reflect power dissipated in its LEAKAGE
    branch only (`vb = v(n1) − a·v(n2)`, the leakage R+L's own voltage per
    SPEC §2) — not total power transferred to the secondary, which isn't a
    single per-branch v·i quantity.
- **Power-flow direction arrows (July 2026)**: animated arrows on the
  schematic itself showing which way power is flowing on each wire, built
  entirely from data the solver already produces (`live.bv`/`live.ic`) — no
  solver or companion-model changes. An AC branch carries active (P) AND
  reactive (Q) power simultaneously, and the two can flow in OPPOSITE
  directions (e.g. a capacitive branch exports Q while still importing P) —
  first shipped as P-only, then extended (still July 2026, same session)
  after this was raised as a real gap: `branchFlowValue(idx, term, reactive)`
  (ui.js) computes both, `P` via the same-timestamp product and `Q` via the
  quadrature product — two independent per-branch scalars, not one value
  with a sign variant. Each gets its own per-wire direction map (`wireFlow`
  for P, `wireFlowQ` for Q).
  **Direction basis is THROUGH power at the queried terminal (July 2026
  fix), not absorbed power**: the first cut inferred direction from absorbed
  `vb·i`, which broke visibly around a closed breaker — it absorbs ~0 W, so
  both its wires fell below the noise floor and each resolved direction from
  its opposite endpoint independently; a user saw the two arrows around one
  breaker pointing in different directions. `branchFlowValue` now computes
  cycle-averaged `v_node·i` at the specific terminal being asked about
  (terminal 0 from `live.tv`, terminal 1 as `tv − vb` — the same recorded
  data the plotted `pin:`/`pout:` signals use), normalized so positive
  always means "power flows INTO the element at this terminal"; through
  power is well above the floor everywhere along a carrying chain, so a
  series chain's arrows all agree. Q's quadrature reference DELAYS the
  voltage (`v(t−T/4)·i(t)`) instead of advancing the current: this scalar is
  evaluated over the run's LAST window, where advancing i clamps a quarter
  of the window onto one stale end-sample (found as ~17% phantom Q on a
  purely resistive load). Additionally the Q floor scales with the branch's
  own P (`max(FLOW_FLOOR_VAR, 2% · |P|)`) so the quadrature shift's
  whole-sample rounding leakage (~0.5% of P) never draws a spurious Q arrow.
  A terminal at ground potential reads 0 through power, so ground-return
  legs correctly show no arrow.
  Rendering (redesigned after user feedback on the first cut, which used two
  full markers side by side — harder to read at a glance): both ride the
  SAME wire path with no offset track, as two HALF-arrowheads — P's marker
  is only the upper half of a full arrowhead (flat edge exactly on the
  wire's own centerline, point forward: SVG polygon `-4,-3 4,0 -4,0`),
  sitting visually "above" the wire; Q's is the mirrored lower half
  (`-4,0 4,0 -4,3`), sitting "below" it — so P and Q read as one line with
  two independent halves rather than two separate marker trains. Colors:
  `--acc` blue for P (unchanged, already the app's interaction/highlight
  color), `FLOW_Q_COLOR = '#f2c94c'` (yellow) for Q — both per explicit user
  request. A `#flowtoggle` checkbox in the toolbar (default on) shows/hides
  every marker via one `render()` call — it only toggles visibility of
  already-cached `wireFlow`/`wireFlowQ`, no recomputation. A wire can show
  P only, Q only, both moving the same way, or both moving opposite ways
  (e.g. a capacitive branch exports Q while still importing P) — matching
  whatever the branch is actually doing. Q never applies to a DC branch
  (`cs.dc` gate, same as the Signals picker already does for its own Q
  trace) — `gfm`'s DC port (term 2) is excluded from Q for the same reason.
  - **Wiring polarity, not a display choice — and now the ONE convention
    for the whole app**: the arrows were built against `FLOW_REVERSED =
    {src:1, gfm:1}` (ui.js), derived straight from tracing every `inject()`
    in blocks.js — only `src` and `gfm`'s AC pair (term0/term1) use the
    reversed EMF-source stamp (`I[n1]+=x; I[n2]-=x`); everything else,
    including `batt`/`pv`, uses the ordinary passive stamp
    (`I[n1]-=x; I[n2]+=x`). At the time this was shipped, the Signals
    picker's plotted `P` used a DIFFERENT table that also flipped
    `batt`/`pv` (a "generators read positive" display nicety, unrelated to
    physical wiring) — a real inconsistency, since the same block could show
    one sign on its arrow and a DIFFERENT-feeling sign on its plot. A user
    flagged this directly ("make power in/out the same for all elements");
    the fix was to delete the extra batt/pv flip from `ingestMeta` rather
    than add anything to the arrows — `FLOW_REVERSED` was already correct,
    and is now the ONE polarity table the whole app shares (§2's Sign
    convention entry has the full before/after). Reusing an "everyone
    flipped by role" table for arrow direction would have shown battery/PV
    power flowing backwards, which is exactly why the arrows needed their
    own physically-grounded table from the start rather than borrowing the
    plot's.
  - **AC vs. DC branch — a second distinction found while implementing**:
    for an AC branch, current alternates sign every half-cycle, so only a
    cycle-averaged quantity gives a stable direction (`branchFlowValue`,
    ui.js — trailing-window through power per the note above,
    `FLOW_REVERSED` applied). For a DC branch,
    using `v·i` is actually WRONG: a DC block's "return" terminal isn't
    necessarily at 0 V (a battery's return sits well below its DC+ terminal),
    so `v = v(n1)-v(n2)` can carry either sign independent of which way
    current is really flowing — verified by testing (battery's `v·i` came
    out sign-INVERTED relative to its own `icmd`). DC branches instead
    average the exposed current directly (`curMeta[i].dc` flag), which is
    already the physically meaningful, non-oscillating n1→n2 value.
  - **Terminal fan-out — a third bug found via live browser testing**: a
    wire only gets an arrow from an endpoint's own branch current if that
    exact (block, terminal) pair is used by exactly ONE wire. The first cut
    let a wire fall back to whatever its other endpoint's element read, which
    incorrectly painted a "power flowing" arrow onto a pure measurement probe
    tap (a line's output terminal wired to both its load AND a V-probe) and
    onto every wire of a 4-way DC fan-in (PFC + battery + cap + probe sharing
    one node with no explicit Bus block) — a probe carries no current at all,
    and a shared node's per-wire split isn't something this feature attempts
    (real KCL apportionment, out of scope). `computeFlowDirs()` now counts
    wires per terminal and only trusts a terminal as a direction SOURCE when
    that count is 1; the wire itself can still get an arrow from its OTHER
    endpoint if that one is unambiguous — verified: the demo circuit's
    line→load wire still arrows correctly while its line→probe tap doesn't.
  - `gfm`'s DC port (term 2) isn't part of the AC branch's `bv`/`ic` at all
    — its current lives in the existing `AUX` table (`live.aux`, `idc`) and
    is used directly (already a slow/filtered signal, no windowing needed).
  - Rendering: SVG `<animateMotion rotate="auto">` — 2 small triangles per
    active wire, staggered `begin` times for a "marching" look, no JS
    animation loop. `rotate="auto"` keeps the triangle tangent to the
    existing Manhattan wire path through both of its bends with no manual
    angle math. Uses the existing `--acc` blue rather than a new color, so
    the category tick colors (above) keep meaning "category" and motion
    (not another hue) means "power is flowing."
  - Known scope: `dcdc`'s IN and OUT ports carry genuinely different current
    magnitudes (lossless power balance, not equal current) but only the
    OUT-side value is exposed, so both its wires move together sized off
    that one reading — correct in direction in every normal operating
    regime, not two independently-measured arrows. Arrows only appear once a
    run has produced at least one cycle window of data.
- **Block palette: one browser, categories by function (July 2026)**: the
  toolbar's 4 category buttons and their shared flyout (`#palcat`/`#palpop`,
  which replaced a flat 17-button row earlier the same month) are GONE. The
  Library drawer had made them redundant: the flyout showed one category at a
  time, at the top of the page, while the drawer shows all of them beside the
  canvas where blocks are actually dropped. `attachPalItemDrag` is now bound
  once, to `#library`. Two consequences worth stating:
  the drawer is the ONLY way to add a block, so `emt_lib` DEFAULTS TO ON (a

  no button row to keep short, the categories no longer have to be merged to
  fit. `PAL_CATS` is now 6 groups by FUNCTION, which is how a power engineer
  looks for a component, rather than by construction: Sources (src, syncgen,
  gfm, gfl, wt4, pv, batt — a wind turbine and a PV plant are generation, not

- **Blocks are drawn in their category's color (July 2026)**: this started as a
  small colored corner bracket per block, on the theory that the symbol art
  should stay monochrome. A user's verdict was that the mark was too small to
  be meaningfully useful, so the whole symbol now takes the category color:
  `blockColor(type, fallback)` feeds `blockSymbol`'s stroke argument in

  drops are the same color. Selection still overrides it with `--acc` plus the

  the existing 6 `COLORS` plot-series hues, skipping index 0 (it equals `--acc`).
  `CAT_COLORS.meas` is deliberately `null` → the default outline color: bus,

- **Toolbar run controls (July 2026)**: `dt` (the solver's internal
  trapezoidal step) and the plot decimation interval were both hardcoded
  (50 µs, auto-capped at ~1400 plotted points) until this point — now three
  separate fields, mirroring how PSCAD separates "solution time step" from
  "plot step": `#duration` (ms, unchanged), `#dtus` (µs, default 50) and
  `#plotus` (µs, blank/0 = auto). `runEMTLive()`/`runEMT()` read all three
  and pass `(nph, Tms, onChunk, dtUs, plotUs)` into `simulate()` — the worker
  bootstrap (`build.py`) forwards `d.dtUs`/`d.plotUs` the same way it already
  forwarded `d.Tms`. Inside `simulate()`, `dt = dtUs*1e-6` (falls back to 50
  if unset/≤0, so every pre-existing 3-arg `simulate()` call — the headless
  smoke-test harness included — is unaffected); the plot decimation `dec` is
  `round(plotUs/dtUs)` when `plotUs>0`, else `floor(N/50000)` (auto: keep
  every solver sample for normal runs, only decimating to cap storage at
  ~50000 points/signal on very long runs). The zoomed-out plot view is then
  decimated *at render time* by per-pixel min/max bucketing in
  `drawOnePlot` (ui.js), so a narrow spike inside a pixel column draws as a
  vertical line at its true amplitude instead of being stepped over — this
  is why record-time decimation no longer needs the old ~1400-point cap. No other code path (node classification, LU build, event
  handling) references dt directly — it was already threaded through as a
  local closure variable, so exposing it needed no architecture change,
  unlike the PI-line/PQ-load work above. Caution is on the user: an
  aggressively small `dt` at a long `Duration` produces a proportionally
  large step count (`N = T/dt`) — the Worker keeps the page responsive

  solved).

  about a wire is "which two terminals does this actually tie together?" and a
  stray click silently changed the circuit. A click now sets `selWire` (an

   **Second pass, July 2026 (2026-07-24 in DECISIONS.md):** the default solve is
   now polar-form **Newton-Raphson** (the classical method), warm-started by six
   unaccelerated Gauss-Seidel sweeps and damped to at most 0.5 rad / 0.25 pu per
   step, with Gauss-Seidel kept as the fallback. Per unit on a PER-BUS voltage
   base (each `bus` block's own `Vbase`), because Ybus is in volts and spans
   every level at once. Iteration counts drop from 1368 to 4 on IEEE 39-bus and
   from 277 to 4 on a 23-bus utility case, and series-compensated networks that
   Gauss-Seidel diverged on now solve. Voltage references are assigned per
   ELECTRICAL ISLAND (components labeled over the Ybus off-diagonals; the
   largest machine is promoted where no swing bus was declared), and a bus with
   no source anywhere in its island is held out of the iteration and reported by
   name instead of dividing by a zero diagonal. Non-convergence reports the
   worst island's power imbalance against its slack machine's rating. Result
   fields added: `method`, `unit`, `islands`, `deadBuses`, `nDead`, `note`, and
   `dead` per bus. Still future: Q-limits, passive-history initialization for a
   fully flat start, N-1 contingency screening, and a sparse TIME-DOMAIN
   solver. The power-flow path is now SPARSE (2026-07-24, third pass in
   DECISIONS.md): Ybus is CSR, the Jacobian is built once on the Ybus pattern
   and refilled per iteration, the linear solve is a column-list sparse LU with
   threshold pivoting, and the Jacobian is minimum-degree ordered so fill stays
   near nnz on imported bus numbering. This breaks the memory ceiling (no dense
   m x m; a 7917-bus case now imports and runs where the dense Ybus could not
   allocate) and makes island labeling and Gauss-Seidel O(nnz). The dense
   `buildLU`/`luSolve` for the time-domain solve remain for a later stage.
   **Fourth pass, July 2026 (2026-07-24 in DECISIONS.md): generator REACTIVE
   LIMITS.** `syncgen`/`gfm` carry `Qmax`/`Qmin` (kvar, 0/0 = no limit, so
   every earlier circuit is bit-identical), the importer carries the RAW's
   QT/QB, and both solvers enforce the band: Newton-Raphson by the classical
   PV-to-PQ outer loop (pin the bus at the limit, let its magnitude float,
   re-solve, since the bus-type set fixes the Jacobian STRUCTURE), Gauss-Seidel
   by a per-sweep clamp. Both pins latch and release on the physical condition
   (the magnitude returning through the setpoint), because an "is it over the
   limit now" test chatters once the magnitude has floated. Two things had to
   change with it: machines SHARING a bus are now aggregated rather than
   overwriting one another (the solved bus output is split back per machine for
   EMT init), and a generator bus schedules its dispatch NET of any load on that
   bus. Q-limits therefore leaves this item's "still future" list; what remains
   is N-1 contingency screening and a sparse TIME-DOMAIN solver
   (passive-history initialization for a fully flat start was the third item
   here and is now DONE — SPEC §5 item 32, July 2026).
   **Fifth pass, 2026-07-27 (DECISIONS.md): what CONVERGENCE means.** Three
   defects, all in the acceptance test rather than the iteration. (a) Newton
   accepted on a hardcoded 1e-10 pu, which is below the residual's own noise
   floor: the injection sum for a bus accumulates terms of size
   Vm_i·Vm_k·|Ypu_ik|, so its rounding error is about eps times that row's sum,
   and a closed breaker stamps a fixed 1e4 S (≈1.6e7 pu at 400 kV). One breaker
   in a three-bus case measures a floor of 1.1e-10 — the tolerance itself — so
   Newton spent its whole budget AT a solved point and reported failure. The
   default is now `max(1e-10, 10·eps·max-row-sum|Ypu|)`, which leaves any case
   without a near-short branch bit-for-bit unchanged. (b) Gauss-Seidel STOPS on
   a voltage step, which is what its iteration produces, but it also REPORTED
   on one, so `converged` meant "the last sweep did not move" rather than "the
   network balances"; it is now scored on the same power mismatch Newton uses,
   and `unit` is 'pu' for both methods. (c) The Newton-to-Gauss-Seidel fallback
   restored a bus-type snapshot taken AFTER the zero-width-band PV-to-PQ
   conversion, so generator buses came back as PQ and Gauss-Seidel (which reads
   load only at a PQ bus) dropped their machines entirely — `auto` and `gs`
   silently solved different problems on any case with a fixed-reactive
   machine. Alongside these, non-convergence now names the worst bus and
   whether it was the P or Q equation, since "mismatch 4.8 pu" is a property of
   the whole network and identifies nothing.

   **Sixth pass, 2026-07-27 (DECISIONS.md): the closed-breaker stamp is a
   RATIO, not a constant.** `buildYbus()` stamped every closed breaker (and
   `relay`) at an absolute 1e4 S. That is a sensible short at 400 V and a
   catastrophic one at 400 kV, where a corridor is ~0.04 S: the breaker node's
   self-admittance ends up 2.5e5 times its links and the Jacobian is scaled so
   badly Newton diverges on a case with a perfectly good solution. Measured on
   an 11-bus 400 kV network with 22 closed breakers: 1e4 and 1e3 S blow up to a
   6.6e5 pu residual, 1e2 S converges in 24 iterations, and splicing the
   breakers out by hand gives that same answer to four decimals — which is what
   identifies the stamp rather than the extra nodes. Below ~1e1 S the breaker
   stops being negligible (0.26% voltage error at 1e1, 2.8% at 1e0), so the
   useful window is a ratio. Each short is now stamped at
   `min(1e4, 1e3·max(nodeY_i, nodeY_j))`, where `nodeY` is the ordinary
   admittance already accumulated at its own two nodes. The measure must be
   LOCAL: a first attempt scaled by the largest admittance anywhere in the
   network and failed on the same case, because one stiff element far away (a
   source with Rs = 1 ohm) set the scale for breakers whose corridors are
   0.04 S. The `min` keeps the historical constant wherever a node is already
   that stiff, so low-voltage cases are unchanged, and a node with no ordinary
   branch (two shorts in series) falls back to it.

   **`gtrip` arming delay, 2026-07-27 (DECISIONS.md).** `tarm` (ms) blocks all
   four elements until it passes, clearing pickup latches and dwell timers
   rather than freezing them, so an excursion still in progress at the arming
   instant must re-establish itself and serve its full definite time. Real
   generator protection is blocked during energization; a PF-initialized EMT
   case needs it because `seed()` seeds measurement states but starts control
   states cold, and a case with many inverters rings 10 to 16% peak-to-peak for
   about a second before settling. Default 0 leaves every existing case armed
   from t = 0.

## 6. Division of labor (local model vs. frontier model)

Local model (qwen 27B via Claude Code): UI features, save/load, plot cosmetics,
refactors, parameter plumbing, bug fixes with clear repro, implementing blocks
whose math is already derived in §2.

Frontier model sessions (paste only the relevant function, not the app):
new companion-model derivations, numerical instability diagnosis, MNA
formulation, coupled 3-phase math, converter control design.

Rule of thumb: write the physics as a §2-style derivation BEFORE asking the
local model to implement it. Small models implement well-specified math
reliably; they fail when asked to derive it.

## 7. Known limitations (state honestly in any deliverable)

Converters: GFM inverter (3-ph AC side only; its AC current limiter is a
~10 ms EMF-backoff outer loop, so the first ~1.5 cycles of a fault pass the
unlimited transient — real inverters clamp sub-cycle in hardware — and the
limiter defaults OFF, Iacmax=0, so studies must opt in); GFM's
grid-following mode has no explicit PLL (assumes the network already sits
near f0) and no anti-windup on its P/Q trims, and its decoupled P→frequency/
Q→voltage control assumes a predominantly inductive tie (X≫R) — a
resistance-dominated interconnection (e.g. the default 1 mH filter tied
directly to a stiff source) makes Q-tracking slow or poorly damped even
though P still converges cleanly; the `gfl` transmission-grade inverter is a
generic textbook AVM only (no vendor LVRT or synthetic-inertia scheme), its
current limit is an outer ~10 ms loop (one-cycle measurement + 1 ms LPF, not
sub-cycle hardware current control, so the first cycles of a fault pass the
unlimited transient), it is 3-ph only, and its PLL locks to the BRANCH-voltage
angle (π off the bus angle under the standard term0-grounded wiring, which the
seed handles wiring-agnostically — a non-standard wiring would need a
re-checked seed); the `syncgen` block is a classical model
only — round rotor, constant-magnitude transient EMF, no subtransient
reactances (Xd''/Xq/Xq'), no saturation curve, no field/exciter dynamics
beyond its Q-droop AVR, and no anti-windup on its governor or AVR (same
accepted-limitation class as GFM's droop); it also needs 3-ph mode for the
same reason GFM does (its AVR measures 3-phase p/q); battery SOC is coulomb-counting only (no
OCV-vs-SOC curve, no efficiency loss, terminal voltage set by the PI not by
cell chemistry); PFC and GFM's DC port are the only AC/DC bridges (lossless,
unity pf, balanced draw only — no harmonics, no unbalanced rectifier
behavior; DC return is implicitly grounded; PFC's rev=1 export is the same
lossless unity-pf AVM in reverse); the dedicated `dcdc` converter shares a
single Imax across both its ports (no separate per-side rating like a real
converter's differing input/output current ratings) and has no separate
charge/discharge limit like battery's Ichg; a `dcdc` in CC mode is a bare
constant-current injection with no voltage feedback of its own, so whatever
it's tied to must be actively regulated (a PFC set to unidirectional rev=0
will go passive and let the bus ramp away unbounded once it can no longer
supply — it can't absorb) or it needs its own load/capacitor sized to
balance the injected power; the `pv` array's I-V curve is a closed-form
approximation whose analytical MPP isn't exactly at the nominal Vmpp
(checked: ~0.6 V off at defaults, well inside the P&O hunting band, not
practically significant), it has no temperature parameter and Voc/Vmpp don't
shift with irradiance (only Isc/Impp scale), `G` is a static "current
weather" knob with no time-varying irradiance/cloud-transient events, and
its fixed-step P&O has no adaptive step size (so it always shows a small
persistent hunting oscillation rather than settling to a single value — this
is correct P&O behavior, not something to fix); the PI-equivalent `line`
(shunt C) can't be combined with mutual coupling (Rm/Lm) in this pass, and
doesn't separately expose its shunt charging currents as a signal (only the
series current/voltage, same as a plain line); the `pq` load's P/Q delivery
has a genuine few-percent steady-state error from its first-order-LPF Vrms²
tracker not perfectly rejecting the inherent 2×line-frequency ripple in
v(t)² (confirmed by testing — doesn't shrink monotonically with a slower
filter, so it's not a settling-time issue to fix by waiting longer), and its
quarter-period-delay reactive-current technique is exact only for a steady
sinusoid at the configured `f` — during a fast transient or at an off-
nominal frequency it's an approximation; DC breakers never find a current zero to open;
unbalanced studies need at least one coupled line (otherwise
phases are independent and an SLG fault trivially decouples) - or a `tap`,
which produces genuine unbalance by construction; the `tap` itself supports
these blocks on its lateral: src, line (without shunt C or mutuals),
rlc/rlcp, cap, brk, fault, pq/zip, mov, a non-saturable 1-ph xfmr, and (since
July 2026) relay, vsw, and pfc, which were made lateral-aware by sizing
themselves from `topo.phList` instead of `nph`. Still refused, with a clear
error rather than silently stamping three phases of a one-phase node: tline
and fdline (deliberate, not a limitation: a traveling-wave or
frequency-dependent line models a long transmission circuit, which is not what
a distribution lateral is), pi-line, and saturable xfmr; a lateral is phase-to-neutral
only (phase-to-phase / 240 V center-tap laterals would need a per-node phase
MASK rather than a single index, a strict superset of this design); and
`solvePowerFlow()` refuses any circuit containing a tap, since a
positive-sequence power flow cannot represent an unbalanced lateral at all; transformer assumes
both windings share the ground reference (no isolated secondary); machine
states (syncgen/gfm rotor angle, EMF, filtered P/Q) can now be initialized from
a positive-sequence power-flow solve ("Init from PF", `solvePowerFlow`), which
removes the cold-start electromechanical swing, but passive-element histories
(line currents, cap voltages) and plain `src` sources still start at t=0 with
zero initial conditions, so a brief electrical inrush over the first cycles
remains even from a power-flow start; **weak-bus start envelope for `syncgen`**
(§5 item 35, measured July 2026 on a machine tied to an infinite bus through a
Thevenin reactance, SCR = 3·Vph²/(Xth·Sbase), H = 4 s, Xd' = 0.75 Ω): a COLD
start must swing from rotor angle 0 to its load angle, and at full (1.0 pu)
dispatch that swing passes pull-out and the machine slips below **SCR ≈ 1.72**
(measured cold ceiling: 1.91 pu at SCR 6, 1.38 at SCR 3, 1.09 at SCR 2, 0.91 at
SCR 1.5, 0.70 at SCR 1.0), so a cold start is only supported above that; a
POWER-FLOW start has no such envelope in the tested range, holding ≥ 1.09 pu at
every SCR down to 1.0 (3.99 pu at SCR 6, 2.81 at SCR 3, 2.02 at SCR 2), i.e.
above the machine's own rating everywhere, so it is never the binding
constraint at a realistic dispatch. Use "Init from PF" on any bus weaker than
SCR ~2 rather than tuning H or the AVR. Inertia is not the lever here (H = 2 s
moves the cold ceiling by under 5%), and line charging is not a factor (adding
2 µF of shunt C changes nothing to 2 decimal places). Guarded in smoke_test.js
from both sides; dt, duration, and plot step are all now
user-adjustable (§3) but dt
is still a single GLOBAL fixed step for the whole run — no adaptive/variable
step sizing, and an overly coarse dt on a stiff or fast-switching circuit can
show numerical ringing the default 50 µs wouldn't. Switching-event
ringing is handled by CDA (two BE half-steps after each event — see §2); no
other damping options.

Batch-2 blocks (July 2026), consolidated from their §2 derivations. A
family-wide caveat first: every QSS current-source block (im, wt4, hvdc,
svc; pq/cpl/zip by construction) injects current with no admittance stamp,
so a terminal node with NO local resistive or capacitive damping leans on
the 1 ms injection LPF to avoid exciting the trapezoidal Nyquist ringing
of adjacent RL companions; give converter buses a local load or shunt cap
when results look "fizzy". Per block: `vsw` acts only after its RMS window
first fills and its controller-driven path may RECLOSE the target breaker
(deliberate exemption from the standalone breaker's latch); `mov` is a
two-segment piecewise-linear clamp (no α exponent, no dynamic/IEEE-WG
arrester model, no energy accumulator); `tline` is balanced per-phase with
lumped R (no coupled-mode Bergeron, no frequency dependence); the syncgen
exciter/governor pair is proportional-AVR-plus-lag and turbine-lag only
(no PSS, no exciter saturation, no deadband/reheat; an integral AVR was
deliberately rejected to protect the PF flat start); `svc` supports
balanced positive sequence only (no TCR harmonics, quarter-period caveat
as pq) and is absent from solvePowerFlow(); saturable `xfmr` has a
LOSSLESS magnetizing branch, so energization flux offset (inrush) decays
only through external resistance, and its sub-ms saturation current
spikes are invisible at coarse plot steps (raise the plot rate to see
them); `xfmr3w` is primary-wye only (it IS represented in
solvePowerFlow() since July 2026, see §2);
`wt4` has no turbine/pitch/inertia dynamics (P follows wind through one
cycle) and a single gust step; `hvdc` has one lumped link state (no dc
cable model, no MMC detail, no frequency support); `fdline` is
first-order-fit JMarti (real fits use 5-15 poles; trust the fundamental
and the first wavefront, treat higher-frequency detail as qualitative)
and double-advances its propagation recursion on CDA event steps.
Power-flow coverage of the newer blocks splits by topology (July 2026
review). SHUNT-injection blocks (svc, wt4, hvdc, im) are not represented in
solvePowerFlow(): PF results on circuits containing them simply ignore
those blocks' steady-state draw. SERIES blocks with no PF model (tline,
fdline, scale, and `tap` for a different reason: an unbalanced lateral is
not representable in a positive-sequence solve at all) are different:
leaving them out would DISCONNECT the network at their location and return
a "converged" solution with dead downstream buses, so solvePowerFlow()
refuses to run on a circuit containing one, with a clear error naming the
block. `xfmr3w` was on that list until July 2026 and has since LEFT it: its
star (T) equivalent is stamped (§2), which is what PSS/E cases containing
3-winding units needed. The overcurrent relay
IS stamped (its fixed closed-breaker conductance, same as the EMT solve),
so protection circuits power-flow correctly. The PFC's AC-side draw is
likewise invisible to the PF (a rectifier-fed facility contributes no PF
load on its AC bus).

The `im` induction motor is the classical third-order model: no stator
transients (inrush MAGNITUDE is captured, the point-on-wave dc-offset
asymmetry of a real DOL start is not), single cage (understates starting
torque of deep-bar machines), no saturation, synchronous frame fixed at its
own f0 param (assumes the network stays near nominal frequency), 3-ph mode
only, and it is invisible to `solvePowerFlow()` (PF results ignore motor
draw; the motor initializes from its own s0 param instead of pfInit).

`scale` (July 2026) is deliberately NOT power-conserving at its coupling
point (that is the entire point: it represents N−1 replicas that are
never simulated), so it must never be treated as a normal branch when
reasoning about power balance across a circuit: energy "appears" at term 0
that isn't drawn from term 1 one-for-one. It assumes every replica is
IDENTICAL and UNDIVERSIFIED (same load profile, same fault response, no
staggered startup or partial-outage modeling); real fleets of N units
have some diversity that this collapses away, exactly the same
approximation PNNL/ERCOT's own current-scaling components make. It is
stamped as a same-step asymmetric admittance (solved simultaneously with
the rest of the network, no lag, no history term) after an earlier
one-step-lag Thevenin-tap design proved unconditionally unstable for large
N; the ~0.2% residual seen in validation is ordinary RMS-window
measurement noise (present in any resistive circuit measured the same way
in smoke_test.js), not a lag artifact. `Rf` is a coupling/sensing
resistance, not a real feeder impedance; it
exists to keep the reference-unit sub-circuit's local bus well-conditioned
and should be left small. 3-ph mode only (both terminals are 3-phase AC),
and as a series element with no PF model it makes `solvePowerFlow()` refuse
to run (a clear error, rather than silently severing the network at the
coupling — July 2026 review; see the PF-coverage paragraph above).
